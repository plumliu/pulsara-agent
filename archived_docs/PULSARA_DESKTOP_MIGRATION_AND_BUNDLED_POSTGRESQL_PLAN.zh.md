# Pulsara 桌面迁移与内置 PostgreSQL 实现方案

日期：2026-10-18

状态：已实施桌面硬切，完成当前 macOS 的实际应用验收。本文是有效实现合同；实际覆盖与平台限制见 [桌面验收记录](PULSARA_DESKTOP_ACCEPTANCE.zh.md)，Linux 原生桌面仍待对应环境验证。

## 1 目标与决定

将 Pulsara 的正式交互入口从外部浏览器硬切为 TypeScript 与 Electron 桌面应用，复用现有 React 工作台和 Python 内核。用户打开应用即可进入工作台，由应用管理本地依赖的启动；拖入磁盘文件时可引用原始路径。

面向 macOS 和 Linux，不做 Windows。内置 PostgreSQL 作为正式桌面交付目标：随包交付数据库与所需扩展，管理 Pulsara 专用实例，普通用户无需安装 Docker、手工启动数据库或填写 DSN。

实施采用适度验收：当前 macOS 和已有 Ubuntu 环境上的真实使用闭环优先，不建立覆盖历代操作系统和所有 Linux 发行版的测试矩阵。未验证的平台组合如实标注，不由此推断它们必然不能运行。

已经确定的方向是桌面硬切、macOS/Linux、数据库完全由 Pulsara 内置管理，以及不过度扩大兼容性测试。开发期只承诺破坏式更新：schema 或数据库版本不兼容时可以重置专用数据库，历史数据丢失是该更新合同的预期结果。本文窗口、标签和文件浏览合同均按已讨论结论实施。

## 2 首版范围

首版完成以下闭环：打开桌面应用 → 专用数据库就绪 → Python 内核就绪 → 打开或创建会话 → 引用本机文件并完成实际任务 → 查看交付物 → 退出和重新打开后历史仍在。

| 纳入首版 | 本次不做或另行决定 |
| --- | --- |
| Electron 主进程、受限 preload、复用 React 工作台、三栏布局与右侧实例标签 | 通用网络浏览器、登录状态管理、多面板停靠框架 |
| Python 与 PostgreSQL 启停、就绪及失败界面 | 跨 PostgreSQL 大版本的自动升级 |
| 原生文件和目录选择、拖入真实路径、系统打开与定位 | 云同步、远程内核、多机数据库管理 |
| 既有历史、引用、分叉、任务分组，以及文件浏览标签的跨文档导航 | Windows |
| 数据目录独立保存、开发期重置更新 | 数据迁入向导、备份恢复产品、全面系统版本测试矩阵 |

本地 HTML 链接跨文件导航与右侧标签工作区纳入本方案的交付闭环，见第 8 节，可在宿主与数据库链路完成后分阶段实现。仅完成 Electron 包装不能宣称迁移目标全部完成；通用网络浏览器仍是后续产品范围。

## 3 当前代码基础与迁移成本

| 当前代码 | 可复用内容 | 需要变化 |
| --- | --- | --- |
| `frontend/local/main.tsx`、`frontend/vite.desktop.config.ts` | 仅桌面 preload 可用的 React 入口、Vite 静态产物 | `build:desktop` 生成宿主内部使用的资源 |
| `frontend/lib/runtime-adapter.ts` | HTTP API、实时观察、历史读取 | 接入启动状态和少量原生操作，保留业务协议 |
| `src/pulsara_agent/web_app/application.py` | 启动、数据库状态、关闭顺序和执行 owner | 增加结构化宿主握手，移除正式入口自动打开外部浏览器的行为 |
| `web_app/directory_picker.py`、`web_app/native_desktop.py` | 现有功能与调用语义 | 原生 UI 操作转交 Electron，移除被替代的 Python 桌面适配路径 |
| `frontend/lib/file-drop.ts`、`workbench-file-drop.ts`、`prompt-composer.tsx` | 草稿位置、会话绑定和附件处理 | 有磁盘来源时插入原始路径引用，支持目录选择/引用 |
| `web_app/file_preview.py`、`file_preview_http.py` | 内容读取、类型识别、权限与沙箱 | 单槽改为多个独立预览实例，补齐文档导航 |
| `pyproject.toml`、`tools/hatch_build.py` | Python 包、内置技能、ripgrep 分发 | 将可运行 Python 环境及资源整合进桌面安装包 |
| `tests/linux/`、`.github/workflows/ubuntu-tests.yml` | Ubuntu 后端及安装后验证 | 增加适量桌面/私有数据库验收，保留现有有效检查 |

当前数据库基线依赖 PostgreSQL、`vector` 和 `pg_search 0.26.1`；Compose 与 Ubuntu CI 使用 `paradedb/paradedb:0.26.1-pg17`。该测试基础可用于固定依赖组合，但容器验证不等于原生随包分发已经验证。

主要成本是运行环境分发与进程生命周期。聊天、模型请求、任务调度、历史分页、引用和分叉不因桌面迁移而重新实现。

## 4 所有权与进程结构

```text
Electron 主进程
  ├─ 工作台窗口与受限 preload
  │    └─ 现有 React 工作台
  ├─ Pulsara 专用 PostgreSQL 进程
  └─ Python 应用进程
       ├─ 现有 HTTP 与实时观察接口
       └─ 现有 Kernel、调度、终端、MCP 与工具 owner
```

| 边界 | 所有者 |
| --- | --- |
| 窗口、应用单实例、原生对话框、系统打开、直接子进程生命周期 | Electron 主进程 |
| 文件选择结果与必要宿主请求 | 类型明确、能力有限的 preload 接口 |
| 会话、权限、模型上下文、工具副作用、定时任务与执行收尾 | 现有 Python 内核及其业务 owners |
| 数据锁、事务、WAL 与数据库崩溃恢复 | PostgreSQL |
| 专用实例初始化、依赖版本选择、启动失败展示 | 桌面宿主中的小型数据库适配层 |
| 历史加载区间、折叠、滚动位置、浏览页面 | 前端展示状态，不成为执行权威 |

保留已有 loopback HTTP 与实时协议作为内部通信，不将所有业务接口翻译成 Electron IPC。正式入口统一为桌面应用；用于开发和自动化测试的内部服务启动不构成另一套用户产品。

工作台可继续加载 Python 服务提供的同源页面，减少 URL、资源和 API 的迁移。实例的结构化就绪信息通过专用进程通道提供，日志不作为协议解析。接口精确字段在编码前根据现有启动 owner 确定，不新增通用消息总线。

对 preload 的调用验证来源，只向工作台暴露所需能力，不开放任意 Node.js、shell 或文件系统执行。内嵌 HTML 与外部网页不能获得工作台的宿主接口，也不能利用本地 API 访问设置和执行命令。保留现有 HTTP 来源检查，在加入浏览页面时验证该隔离边界。

## 5 启动与退出行为

### 5.1 正常启动

1. 建立应用单实例，解析现有 `require_pulsara_home()` 对应的有效 Pulsara home。再次打开同一实例时聚焦窗口，不重复启动内核和数据库。
2. 展示启动页，准备应用专用数据库。首次创建数据目录；已有目录先检查实际数据库状态和版本，禁止因初始化失败自动删库重建。
3. 通过 PostgreSQL 官方工具初始化/启动实例，验证数据库与扩展可用，然后启动 Python 应用。
4. Python 通过现有 `LocalSettingsStore` 读取模型等用户配置。宿主确定的专用实例连接信息通过唯一组合入口形成同一个有效 settings 对象，供应用、模型 runtime、内核和数据库管理操作读取；不另设可由用户编辑的 DSN 来源。复用既有管理角色和受限 runtime 角色边界，schema 与角色初始化/重置仍由现有 Python `PostgresMigrationRunner` 负责。
5. 收到结构化就绪状态后载入工作台。数据库可用和界面服务已启动是不同状态，不能仅因 HTTP 端口可访问就显示全部就绪。

启动页区分“正在启动”“需要用户处理”“启动失败”，允许查看具体错误和重试。凭据不出现在日志中，其余诊断保留有效上下文。重试不得启动第二套实例。

### 5.2 窗口关闭与真正退出

建议首版采用：关闭主窗口后应用驻留，macOS 可从 Dock/菜单返回，Linux 提供可用的托盘返回入口；若运行环境没有可用托盘/激活入口，关闭操作展示“最小化或退出”的选择，避免留下无法返回的后台应用。显式“退出 Pulsara”才执行完整停止。

托盘和关闭窗口后驻留仅属于桌面交互选择，不新增调度器、恢复机制或执行 owner。驻留期间由原有 Python 内核与定时任务服务继续工作；具体窗口交互仍可在实施前调整。

存在运行中的任务或需要后台运行的定时任务时，退出前说明影响，由用户选择继续后台运行或退出。任务状态查询使用现有 owner，不在桌面壳缓存另一套任务真相。

真正退出顺序：停止接纳新工作 → 按 Python 现有关闭路径停止并结算当前工作、回收子进程 → 确认内核结束 → 停止专用 PostgreSQL → 退出应用。沿用现有关闭取消原因和工具结算语义，不等待任务自然成功；数据库不能先于内核关闭。

关闭迟迟未完成时显示状态及诊断；任何强制结束必须是明确操作，不新增一个任意超时后自动杀进程的隐含合同。保留既有经过验证的物理操作边界。

### 5.3 异常退出

界面刷新或渲染进程重载只重连内核，不重启数据库和执行系统。内核意外退出时停止显示“运行正常”，呈现实际错误及重新启动入口，不自动重放已经执行过的工具。

宿主异常结束后，再次启动检查 PostgreSQL 自己报告的实例和数据目录状态，先确认是否仍有专用实例运行，再决定复用或启动；不只凭 PID 猜测身份，不删除锁文件强行启动。PostgreSQL 负责数据恢复，现有内核负责跨重启会话语义，不引入桌面专用执行恢复日志。

宿主专用通道断开时，Python 进入现有关闭路径；同一 home 的旧 Python 内核尚未结束时，不得拉起第二个内核，也不得停止其仍在使用的数据库。复用平台进程机制实现，不新增持久恢复协议。

### 5.4 图标启动与命令行启动

安装产物支持直接点击图标使用：macOS 从应用程序、Dock 或启动台打开；Linux 从应用菜单或已创建的桌面快捷方式打开。用户无需打开终端、手工运行数据库、激活 Python 环境或启动内核。启动进度、失败原因和日志入口在应用内可见。源码构建和自动化测试仍可使用终端，不作为普通使用的前置步骤。

`pulsara app` 改为同一个桌面应用的启动器：未运行时启动，已运行时聚焦窗口，不创建第二套内核或数据库。交付启动请求后命令返回，终端关闭不影响应用存活；命令成功仅表示启动请求已交付，实际内核就绪与失败由应用界面展示。启动器无法找到或启动应用时返回明确的非零退出状态。

删除正式命令中的 `--port`、`--no-open` 和内部静态目录覆盖等 Web 启动参数；内部服务测试通过开发入口运行，不保留旧 Web 产品回退。旧运行参数中涉及权限、工作区 MCP 信任、技能和 memory domain 的语义逐项映射到现有配置/会话 owner，不得静默忽略、扩大权限或用一次“聚焦窗口”重配正在执行的内核。映射未明确的参数应明确拒绝，不能假装已生效。

设置导航只保留通用、模型和已归档会话。“通用”中的“本地服务”卡片包含三项：PostgreSQL（简短存储用途说明、检查数据和重置数据按钮）、只读 Pulsara 家目录、命令行入口。移除独立本地服务分类和页面连接行。数据检查通过通知反馈，重置保留原有显式确认；能力目录说明链接定位到通用页的家目录并高亮。

### 5.5 CLI 保留范围与安装

CLI 保留为桌面产品的可选管理工具，不要求整体改写为 TypeScript。启动器和现有 Python 命令实现可以分层；随安装包携带的 Python 与同一个有效 Pulsara home 服务这些命令，用户无需另装 Python。管理命令不私自启动内核、调度器或另一套 PostgreSQL。

| 命令 | 硬切后的行为 |
| --- | --- |
| `pulsara app` | 启动或聚焦桌面应用，遵守第 5.4 节 |
| `pulsara skills …` | 保留技能检查、安装与管理的既有语义 |
| `pulsara plugins …` | 保留插件管理及既有信任/权限边界 |
| `pulsara mcp …` | 保留 MCP 配置管理，不因命令行写配置而重建已安装 provider 前缀 |
| `pulsara hooks …` | 保留 Hook 管理及既有信任边界 |
| `pulsara config-check` | 检查桌面版的实际配置；数据库状态来自同一专用实例，不读取旧外部 DSN |
| `pulsara db status`、`pulsara db verify` | 只诊断应用管理的数据库，沿用现有输出/失败表达；应用未运行时明确报告不可用，不自行启动实例 |
| `pulsara db migrate` | 从公开 CLI 移除，初始化与破坏式更新由应用通过既有 Python owner 执行 |
| `pulsara --version`、帮助信息 | 报告实际安装版本和当前支持的命令，不宣传已移除的 Web/外部数据库路径 |

不需要数据库的管理命令可在桌面未运行时工作。需要实际数据库连接的检查通过受限的本机宿主/内核诊断入口复用当前实例，不将管理凭据交给任意前端，也不另起维护进程竞争生命周期。文件配置修改继续由既有配置 owner 处理，运行中会话如何采纳变化遵守现有 runtime 合同。

CLI 随应用交付。macOS 与 Linux AppImage 在安装产物首次启动时自动向 `~/.local/bin/pulsara` 注册入口，后续启动维护应用自己创建的启动器以适应更新或移动；开发模式不自动注册。deb 由系统包安装/卸载脚本维护 `/usr/bin/pulsara`，应用不另建重复入口或代替包管理器修改系统路径。注册失败不阻止桌面内核启动。通用设置的“本地服务”卡片以紧凑单行提供“命令行入口”的只读状态、路径、重新检查与重置入口操作，“重新检查”使用刷新图标；同名冲突以标题右侧的红色警告按钮呈现，点击向下动画展开简短说明、冲突路径与替换影响。展开仅影响显示。命令行路径在标题和按钮下方使用与家目录一致的整行只读输入框。移除 PostgreSQL 卡片及应用菜单中的手动安装入口。

PATH 中已有旧版 `pulsara` 时保留原入口，显示具体冲突；用户明确点击“重置入口”后，只替换应用管理位置上的入口，不写穿旧符号链接或修改旧安装目录。应用仅检查自身环境的 PATH，提示缺失目录或优先命中的其他命令，并提供 `command -v pulsara` 核对说明，不执行或修改 shell 配置。两端入口均指向安装产物，不依赖源码 checkout 或开发 `.venv`；开发者可继续显式使用仓库入口。

## 6 内置 PostgreSQL

### 6.1 交付形态

随包交付固定、实际可用的 PostgreSQL 与扩展组合，首选沿用现有 PostgreSQL 17、`pg_search 0.26.1` 和经验证的 pgvector 版本。平台或扩展约束确实要求调整时，统一修改版本与相关测试，不留下旧/新版本双路径。

应用自己的二进制位于安装资源目录，数据库数据和日志位于有效 Pulsara home 下的专用子目录。数据不写入 `.app`、安装包或临时目录。普通退出、重开及卸载不主动清库；需要重置的开发期更新遵守第 6.4 节。

以当前普通用户运行，实例仅服务本机内核，优先评估私有目录中的 Unix socket；若实际集成选择 loopback TCP，则使用受保护凭据和已验证的监听范围。最终只采用一条路径，不为未发生的问题同时构建多种连接方案。

依赖直接复用官方初始化、启停和就绪检测工具。PostgreSQL 负责存储可靠性；Pulsara 只管理自己的实例，不能停止、修改或替换用户另行安装的数据库服务。

### 6.2 原生二进制与平台

首版构建目标为 macOS 15+ ARM64，以及 Ubuntu 24.04 x86_64/ARM64。不新增 Windows 或 macOS Intel 交付目标，不承诺任意 Linux 发行版都可运行。macOS 15 是本次固定资源组合的构建与安装声明；本机实跑环境和未验证平台分别记录，不推断更旧系统能否运行。

检查固定发行物的数据库大版本、CPU 架构、最低系统要求和动态库引用；优先复用可分发的现成构建。需要打包依赖时在构建阶段完成，用户机器不安装 Homebrew、编译器或 Docker 来补齐产品必需依赖。

官方包的系统名称不直接等同于最低运行版本。旧版 macOS 无需逐一实测；发布说明标明已验证环境和二进制已知要求。Linux 沿用现有测试基线，不扩展为全面发行版认证。

### 6.3 唯一数据库配置与硬切

桌面产品只使用 Pulsara 管理的内置 PostgreSQL，不允许用户自行配置数据库地址、Runtime DSN 或 Admin DSN，也不提供外部数据库模式或失败后的自动回退。内部测试可继续通过现有明确注入点使用隔离数据库，这不是用户产品配置。

硬切时移除旧设置页的 DSN 编辑、保存连接和任意外部目标管理入口，删除对应的旧配置读写路径。设置页只展示应用管理的数据库状态和必要的专用库维护操作；检查、初始化与重置必须指向第 5.1 节同一个有效配置，不能由前端提交另一套目标。用户的模型连接等无关设置保持原值。

首次桌面切换直接建立当前 clean-v0 基线，不迁入旧开发历史，也不要求先手工导出、恢复或验证旧数据。原先单独运行的数据库不由桌面应用自动接管或删除。

目前使用的外部生产库在切换完成后退出正式运行链路：桌面启动、会话、记忆、搜索、定时任务和正式 CLI 均不再依赖它。旧会话、记忆和定时任务不会自动出现在新库中或继续调度；工作目录文件、技能、插件和模型配置按各自原有存储继续保留。

切换前按既有关闭路径停止旧 Pulsara 应用，避免旧内核或调度器继续对旧库工作。新桌面不再读取旧数据库连接配置，但不会因此自动停止系统 PostgreSQL/Docker 服务或删除旧数据库、容器、数据目录。确认旧实例确为 Pulsara 专用、没有其他使用者后，可另行执行一次退役清理；清理不是桌面启动依赖，也不建设常驻兼容/迁移机制。本次文档修改不操作现有生产库，实施切换前当前应用仍照常依赖它。

### 6.4 开发期破坏式更新

Pulsara 尚未正式上线，当前只承诺破坏式更新。schema、扩展或 PostgreSQL 版本变化导致现有数据不兼容时，可以直接重置应用专用生产库并安装当前 clean-v0 基线；由此丢失会话、记忆、定时任务等数据库内容属于预期行为，不承诺升级保留数据。

复用现有数据库 reset/baseline owner。重置前按现有关闭路径停止并结算当前工作、回收子进程，验证实际目标确为该应用专用实例，再执行重置。若 PostgreSQL 大版本导致旧数据目录不能启动，则停止旧实例后重建专用数据目录，不用新版本直接打开不兼容旧目录。不得把一般连接故障、权限错误或启动失败统一当作“需要清库”。

更新说明和界面明确提示该版本会重置数据库。开发期不做数据迁入、备份恢复流程或其验收，也不引入兼容迁移、`pg_upgrade` 或回滚机制。普通同版本重启继续保留数据；重置仅作用于专用数据库，不清除工作目录文件、模型配置、技能或插件。以后正式上线如需数据保留合同，再单独定义。

本次仅修订方案，不立即执行任何数据库重置。

## 7 原生路径与文件交互

磁盘来源的拖入文件通过 Electron `webUtils.getPathForFile()` 获取路径，接入既有路径引用机制。文件夹作为目录引用，不递归上传整个目录。截图粘贴、内存文件等没有磁盘路径的内容继续走附件导入，这是不同输入类型的正常处理。

保留拖入位置、草稿会话绑定、用户编辑和发送前检查。切换会话期间的拖入不落入错误会话；一次拖入不因工作台与编辑器同时监听而添加两遍。

界面让用户能够区分“引用原文件”和“附件副本”。原文件引用发送后仍按内核现有解析、读取和权限规则执行；获得真实路径不代表获得整个目录或父目录的新权限。

复制文本统一通过主工作台的窄 IPC 接口调用 Electron 原生剪贴板，仅开放写入文本，不开放读取或向预览子帧授予剪贴板权限。

原生选择器、在文件管理器中定位和关联应用打开统一交给 Electron。业务层保留必要的路径校验，删除被替代的 AppleScript/Zenity/平台命令桥接，不维护两套原生 UI owner。

## 8 桌面布局、标签工作区与文件浏览

### 8.1 布局与视觉

采用左侧导航、中间会话、右侧标签工作区的三栏结构，保留 Pulsara 当前暖色背景、金色品牌与内容阅读风格。借鉴 Codex Desktop 的空间组织，不复制其配色，也不将所有功能改成 IDE。

- 窗口最顶端只有一行：左侧为平台窗口控件与会话侧栏开关，中间直接复用会话标题、状态、更多操作、压缩上下文和工作区开关，右侧为能力、任务、后台进程三个分类入口和展开/收起按钮。三段随各栏宽度和分割线对齐，删除另起一行的居中窗口标题与会话 header；交互控件不落入拖动区域。macOS 与 Linux 分别适配窗口装饰。
- 左侧按用户实施中确认的方向恢复原 Web 工作台的视觉结构：62px 深色图标栏、252px 暖色会话列及原 Pulsara 品牌区；保留原颜色、比例和全局入口。折叠只收起会话列，图标栏仍可用；桌面宽度下新建或选择会话不会自动收起左栏。这是布局复用，不恢复 Web 产品入口。
- 顶部左侧栏与会话栏之间使用细竖线分隔。中间让会话标题、消息区与输入框形成稳定布局。助手正文使用 15.5px、1.52 倍行高、5px 段尾间距，二级标题 19px；最后一组回复取消额外尾部外边距，消息区底部保留 30px 留白。用户消息单独使用 16px、1.7 倍行高和较宽松的气泡内边距；保留用户输入的换行与空行，空行随行高增加段落间隔。工具调用摘要使用 11.5px 标题与紧凑上下留白；右侧文档预览保留独立字号。正文保留舒适阅读宽度，表格、代码等允许按内容适当展开；继续复用历史分页、定位、引用和分叉。
- 右侧拖动调宽受实际剩余空间约束，为左侧导航及中间会话栏保留现有最小宽度，不能把文档排版推到窗口外。拖动时保持 320px 可读宽度；继续向右拖至计算宽度不超过 160px（最小宽度的一半）时自动收起，重新展开恢复本次拖动前的可用宽度，保留标签、选择及阅读位置。键盘左右方向键仅调宽。
- 两侧展开与收起使用 220ms 平滑过渡，中间会话栏同步调整；右侧拖动越过阈值也使用相同收起动画，手动调宽时直接跟手。收起仅隐藏已有视图，隐藏工作区不可聚焦，不新增执行状态；系统开启减少动态效果时直接切换。动画由 Chromium CSS transition 管理。
- 右侧可折叠、可调整宽度；能力、任务、后台进程三个带文字的分类入口和展开/收起按钮放在窗口顶栏，具体文件、任务等实例标签另排在下面一行。能力、任务、后台进程作为总览入口，按需打开相应总览或具体对象；不默认占满三个总览标签，也不随每次模型委派自动创建标签。
- 窄窗口优先通过折叠侧栏保持会话和当前内容可用，不把三栏同时压窄。统一工具栏、按钮和状态的 UI 字体、焦点与悬浮反馈；正文可以保留现有阅读字体。

标签直接使用实际标题，如“发布检查”“检查链接”“ACCESS-07.md”。用图标区分类型，完整路径、来源和类型可放在副标题或悬浮说明；不采用“类型 · 名称”格式。首版采用一条标签栏，不引入多 pane、任意停靠或浮窗系统。

### 8.2 分类入口与实例语义

共享标签栏不意味着所有标签绑定同一种对象。任务、连接、进程标签绑定明确实体；文件浏览标签绑定一次独立浏览过程，当前文件可以改变。

| 内容 | 标签对应的对象与身份 | 页内行为和首版边界 |
| --- | --- | --- |
| 会话能力总览 | 固定 `sessionId`，显示目录及继承来源 | 沿用当前 Skill/MCP 分类与来源信息；插件及 Hook 管理保留既有全局入口和表单，不附带新增会话管理页，也不混成全局统一连接状态 |
| Skill 正文 | 普通文件浏览标签中的准确 `SKILL.md` 路径 | 相对链接继续浏览 Skill 目录内文档；阅读不启用 Skill、不执行指令；来源、启用和管理保留原能力 owner |
| MCP 连接详情 | `sessionId + runtime_server_id` 对应的连接观察 | 看状态、工具和错误；编辑、认证、重连是显式操作。旧 Host 失效时不沿用旧控制引用 |
| 插件 | 首版留在能力页内详情与现有配置表单 | 遵守 user/workspace、plugin、包内组件的既有归属，不创建“插件运行容器”或通用启停语义 |
| 任务总览 | 当前会话任务集合 | 保留组与状态导航；TODO 留在所属主会话或任务内部，定时任务仍在原管理入口 |
| 任务组 | `sessionId + batch_id` | 显示组图、跨组依赖及选中任务详情；不新增整组停止语义 |
| 单个子代理任务 | `sessionId + task_id` | 用户显式打开；与组内详情复用组件和数据，查看对话、结果、依赖并沿用现有取消动作 |
| 后台进程总览与详情 | 总览绑定会话；详情绑定 `sessionId + host_session_id + process_id`，输出游标绑定原 stream | 看状态、来源和保留输出，沿用终止动作；首版不据此增加 stdin、PTY 或命令启动入口 |
| 文件浏览 | 独立前端 `tabId`，含当前位置、前进/后退历史及各页阅读位置 | Markdown、HTML、PDF、图片和源码是页面呈现方式，不分别建立 tab 框架 |
| 历史冻结可视化 | `sessionId + canonical entry ID + occurrence ordinal` | 保留发布时内容；不能按同名文件或内容 digest 合并不同发布记录 |

子代理的后续委派按现有合同创建新任务，旧任务标签仍指向原任务。主会话留在中间聊天区，不再创建一个 ROOT 代理标签。任务详情暂不增加用户直接向 worker 发言或重新运行旧任务的入口。

配置启用、当前生效、待采纳与需要批准继续分别展示，不压成一个状态灯。全局能力页、会话能力和 MCP 标签的打开、聚焦与“刷新”只刷新显示，不调用重新加载能力或 MCP 重连。现有全局“刷新能力”实际会重新加载所有 live sessions，须将其显示刷新改走只读 inspection；原重新加载能力操作单独明确命名，沿用原 owner 及作用范围，不能作为显示刷新或自动轮询的副作用。MCP“重连”单独命名和触发。

### 8.3 通用标签生命周期

同一会话内重复打开同一任务、任务组或 MCP 连接，聚焦已有标签；后台进程按完整实例身份区分，同一命令两次执行不是同一对象。文件浏览的复用按第 8.4 节处理，不永久绑定入口文件。

关闭标签只关闭视图与相应读取资源，不取消任务、终止进程、断开 MCP 或删除历史。折叠右侧区域只隐藏工作区，不等同于关闭各标签；关闭当前会话最后一个标签时自动沿用收起动画隐藏右侧工作区，其他会话已打开的标签不受影响。停止、取消、终止、重连均沿用既有显式控制入口。

切换会话时按会话保存前端标签描述、浏览历史与阅读位置，不把已打开标签悄悄改绑到新会话。释放旧连接的预览 token/frame 与订阅；返回后从当前合法连接重新读取，异步迟到结果不能落入另一个会话或已关闭标签。不为保留标签额外维持所有会话的 live connection。

标签状态首版保存在前端内存，应用重启后不承诺恢复打开布局；canonical 任务与历史仍由既有接口重新打开。后台进程只有原 Host 及保留记录仍可用时才能继续查看；原实例消失则明确显示不可用，不按同名命令重绑定。文件重新读取也不承诺恢复 HTML 的脚本内存状态。

不增加持久 tab registry、恢复 job 或任意标签总数上限。需要限制活跃物理资源时，优先复用可释放、重载的视图，并在实施中依据真实资源边界明确合同，不把资源管理变成执行恢复机制。

### 8.4 文件浏览的导航规则

一个文件浏览标签代表独立浏览过程，而非固定文件。它可以始终阅读一份文档，也可以从网站入口进入子页面、Markdown 手册及其引用。标签标题随当前页改变：HTML 优先使用页面标题，其他文件使用文件名；不再单独显示文件名和路径栏，规范化路径可在“复制路径”按钮悬停时查看并复制。文件工具栏仅保留后退、前进、刷新、源码切换、复制路径和打开所在文件夹；关闭使用标签上的关闭按钮。每个标签维护自己的前进/后退历史与各页阅读位置。

| 用户操作 | 行为 |
| --- | --- |
| 从聊天点击文件链接 | 同会话、相同有效阅读范围下，已有标签当前显示该规范化路径时聚焦并应用锚点/行号，否则新建标签；多个匹配时优先当前活动标签，其次最近使用的匹配标签 |
| 从浏览页普通点击文档链接 | 在当前标签导航，加入该标签历史，不因目标已在另一标签打开而跳走 |
| 目标只出现在某标签的过去历史中 | 不据此复用或回退该标签，按正常打开规则处理 |
| Cmd/Ctrl 点击或选择“在新标签打开” | 新建独立浏览实例，允许同一文件多开，各自保存历史和位置 |
| 点击文档内锚点 | 同页跳转，不创建标签；保留可返回的阅读位置 |
| 切换预览与源码 | 当前页的呈现切换，不新增标签或页面历史 |
| 刷新当前文件 | 重新读取当前路径，保留浏览历史；不宣称自动监听磁盘变化 |

文件资源识别使用后端规范化绝对路径与有效阅读范围，不能按 basename 去重；`tabId` 不使用读取 token、文件 digest 或当前路径。当前页变化不改变标签实例。前进/后退可以重新读取磁盘当前版本，不承诺各历史页的内容快照。

相对链接以当前文档所在目录解析，不沿用初始入口目录或终端 cwd。HTML → HTML、HTML → Markdown、Markdown → HTML 交给同一文档导航入口，再按实际类型呈现。Skill 的 `SKILL.md` → 子目录指南 → 其他文档也遵守这一规则。目录树可后续添加，首版不依赖它。

普通链接发起新导航失败时保留上一页及其位置，展示目标路径、明确错误、重试与返回能力；没有上一页时显示可操作的错误页。历史前进/后退与刷新失败按第 8.8 节保留各自的历史语义。不把裸 JSON、浏览器阻止页或空白 iframe 当成产品反馈。缺失、不支持、越界和文件变化分别沿用实际错误，不静默改读其他目标。

### 8.5 文件读取、HTML 与历史快照的边界

现有 test8 的入口是 `field_release/index.html`，通向 `learner/index.html`，再通向实际存在的 `learner/role_manuals/ACCESS-07.md`。当前 HTML 内链接直接进入静态资源路径，Markdown 因不属于资源白名单而返回 415；仅扩充资源扩展名白名单不能完成文档导航。

HTML 的文档导航与 CSS、JS、图片、fetch 等资源加载必须分流：导航经过受限宿主适配，资源加载继续使用现有资源服务器、路径检查与 CSP。适配覆盖普通链接及实际支持的文档跳转；脚本或自动跳转无法支持时明确阻止并给出反馈，不扩大为任意页面执行权限。复用平台导航机制和既有解析器，不另写通用浏览器协议栈。

从可信工作台的聊天文件链接或原生文件选择打开入口时，由后端解析入口路径，以入口文件所在目录的子树作为该次浏览范围，沿用现有 HTML 资源根的目录约定与 no-follow 文件检查。打开 `SKILL.md` 时即为其所在 Skill 目录；打开 test8 的 `field_release/index.html` 时即为 `field_release`。这不是赋予模型目录读取权限，也不允许页面访问该目录的祖先或整个磁盘。

后续页面始终继承入口范围，不按当前页或链接目标的父目录重新扩大或缩小。相对路径可以返回同一范围内的上级目录，规范化后的目标必须仍在范围内。iframe 导航请求须绑定当前 frame、标签及读取 token；不能把页面消息当成用户新授权。跨 HTML/Markdown 的导航、显式新标签、重试、前进后退及重新连接均保留原范围并重新校验，不经规范化绝对路径“洗掉”限制；重新连接由可信工作台根据保留的原入口描述恢复并校验原目录范围，不要求入口文件本身仍存在，不能以历史子页替换入口来推导范围。原目录不可用时显示实际错误，不另找目录替代。

首版越界链接明确阻止，不建设目录授权扩展框架；用户可通过聊天中的文件链接或原生文件选择另开独立浏览过程。文件页自身提出的导航和新标签请求不等同于这种可信入口操作。网络外链首版沿用明确的外部打开策略，无法安全打开时给出反馈。

历史冻结内容单独标明“发布时快照”，刷新仍读取同一 canonical occurrence，不能默默替换为磁盘当前文件。未冻结的跨文件目标显示“此快照未包含目标文档”，不从当前磁盘补齐，也不把一次可视化发布扩成整站冻结。

现有冻结元数据的 `source_filename` 只有 basename，不能据此猜目录。若可靠来源映射尚不存在，首版通过聊天里的真实文件链接打开文档包；未来提供“打开当前文件”时，须先定义可信来源关联与授权边界，并另开当前文件浏览标签，不改写原快照。

### 8.6 复用与需要硬切的前端假设

Electron 与现有沙箱负责窗口、页面承载及隔离；Python 的既有预览 owner 负责文件范围、读取资格及内容；React 工作区只负责标签、导航描述与展示。任务执行、能力采纳和控制结算继续属于现有内核。

实施前已确认的改动点：

1. `FilePreviewHost`、`FilePreviews` 当前是每连接单槽，打开或关闭一个文件会撤销整个连接的旧预览。改为连接下多个独立预览实例：单实例替换/关闭，连接断开全部释放；普通新导航成功后再替换旧页，失败保留旧页，历史跳转与刷新按第 8.8 节处理，过期请求独立释放。不能只在现有单槽上加标签外观。
2. `pulsara-app.tsx` 当前加载/关闭任务组会清空共享任务列表。改为任务组保存 membership 和视图位置，共享任务行与活动读取；单任务标签和组内详情复用 `TaskDetail`，关闭一组不能清掉其他仍打开的任务数据。共享数据继续沿用既有事件失效、水位与分页更新，不为各标签复制另一套任务状态。
3. 后台进程面板的部分 pending 控制引用与查询属于组件局部状态。将已有控制观察上提到会话/连接层，原 command/Host 引用保存在前端会话内存，不随标签关闭销毁；切出会话可以停止查询，返回后仅按原引用查询。沿用既有结果保留范围：`RESULT_UNAVAILABLE` 表示结果当前不可确认，不代表 Host 失效、操作失败或未执行；`OWNER_UNAVAILABLE` 单独显示原 owner 不可用。两者均不重新提交。内核继续按既有路径结算，不新增持久操作日志或全会话常驻轮询。

复用现有读取 API、历史分页和组件；实际缺少的导航及多预览操作只做小型适配。可参考 DSH 的统一打开入口与标签聚焦行为，不复制插件注册框架、多 pane 或持久化标签库存。

### 8.7 后续网络浏览与模型边界

更完整的网页或 localhost 项目浏览采用独立浏览实例，优先评估 Electron `WebContentsView`。导航、窗口、下载和页面隔离由宿主与平台 API 承担。地址栏、登录状态、下载与跨重启恢复等另行形成产品合同；本地文档跨页浏览不以通用网络浏览器为前置。

打开、浏览、刷新或关闭标签不自动向模型添加消息、触发模型侧文件读取或更改其 SYSTEM/tools；UI 预览仍正常读取获准的文件。不自动授权模型浏览器操作。未来若提供“引用到对话”，它必须是明确用户动作，复用既有引用与权限规则。本文不修改工具提示词，也不改变当前执行合同。

### 8.8 对象丢失、暂时不可用与恢复

对象暂时无法读取时保留标签、原目标与阅读位置，显示实际错误及重试、返回或关闭入口，不突然关闭标签或自动寻找替代对象。读取失败只改变展示可用性，不能据此把任务标为失败、进程标为停止或配置标为已删除。

| 已知情况 | 展示与处理 |
| --- | --- |
| 连接中断、请求失败或观察尚不可用 | 标明暂时无法更新；已有状态标为上次观察，停止显示实时更新，不推断对象被删除 |
| 文件返回 `FILE_NOT_FOUND` | 显示“文件已移动或不存在”及原路径；保留浏览位置，可重试，不自动搜索同名文件 |
| `FILE_UNREADABLE` 或其他读取错误 | 使用具体错误说明；该码涵盖多种 OS 错误，即使 HTTP 状态为 403 也不能断言权限已撤销 |
| owner 明确报告当前读取资格失效 | 停用该资格对应的旧 token、活动 frame 和操作入口，不通过缓存继续读取、导航或控制 |
| 新导航的候选目标越界 | 只拒绝该次导航，保留仍合法的当前页及读取资格；目标越界不代表当前页资格失效 |
| 任务或进程当前查不到 | 如实显示原记录当前不可用；只有确知原 Host 已退出或被替换，才说明原运行环境不可用，不猜测淘汰、停止或从未执行 |
| 原会话明确删除或数据库明确重置 | 沿用现有删除/清理路径，清除受影响内容缓存、浏览记录及控制引用；至多保留不可操作的失效提示，不继续浏览已删除的会话内容 |

缺失判断使用原 owner 的具体结果，不从任意 HTTP 404、不完整列表、未完成发现或连接失败推断删除。Skill 文件页不根据文件存在/缺失推断启用、生效或卸载状态；能力管理状态仍以能力 owner 为准。普通读取失败不会触发会话删除或清库后的清理行为。

已经加载的静态文字、图片或进程输出，在暂时不可读时可保留并标注“此前读取的内容，当前未能更新”。它不构成新的成功读取，不代表实时状态；输出继续保留原缺口与截断提示。已失效资格不能继续用于分页、加载资源或原生操作。HTML 无法安全保留时显示错误页，不承诺恢复脚本状态，不为保留旧画面另建截图或冻结机制。首版不新增通用权限撤销广播、文件监控或缓存权限账本。

文件导航失败的历史行为如下：

| 操作 | 失败与重试 |
| --- | --- |
| 普通链接发起新导航 | 保留当前页、历史游标和前进分支，另显示失败目标；重试成功后才追加一次历史并截断原前进分支 |
| 前进/后退到已有历史项 | 游标移到指定项，该项显示目标路径和错误；可继续前进/后退，重试成功替换该项错误，不追加历史 |
| 刷新当前页 | 保持当前历史项；可保留已显示的静态旧内容及失败提示，成功后更新该项，不追加历史 |
| 初次打开或显式新标签打开失败 | 保留该标签与目标错误页，可重试或关闭；不影响其他标签 |

重试、刷新、历史跳转与重连保持第 8.5 节的原目录范围。入口文件被删除不妨碍仍存在的子文档在原目录范围内重新读取；目录本身不可用则显示错误。用户明确选择同范围内的其他文件可在当前标签发起新导航；跨范围的可信文件选择必须另开独立浏览过程，不扩大原标签范围，也不默默替换原历史地址。

文件恢复表示重新读取该路径的当前版本，不承诺找回原内容。现有 `Preview.check()` 只比较已打开 fd 的 stat，不能识别路径经删除或原子替换后已与旧 fd 分离；实施时在实际读取/重新装载边界复用 no-follow 路径检查与 stat identity 校验。发现路径绑定改变时将旧内容视为此前读取，明确提示重新加载；新版本不得拼接旧字节或表格游标，阅读位置尽力恢复。不增加 watcher、文件 hash 或后台全盘搜索。冻结内容不可读时保留原 occurrence 身份和错误，只重试同一 canonical 内容，不用同名磁盘文件替代。

任务恢复读取仍按原 `sessionId + task_id` 获取 canonical 状态；进程必须按原 `sessionId + host_session_id + process_id` 校验。后台总览中不再出现某进程，不应直接关闭其已打开标签；该标签保留原身份和不可用提示。现有日志接口从当前连接取 Host，实施时须在读取前及异步返回后核对原 Host，不能把旧进程 ID 交给新 Host。MCP 也不能按同名或 endpoint 自动换绑不同连接。

“重试”只重新发起对应只读查询，不重放控制命令。pending 控制遵守第 8.6 节，区分 `RESULT_UNAVAILABLE` 与 `OWNER_UNAVAILABLE`；结果不可确认也不重发。重新连接 MCP、安装、启用与重新加载能力仍是分别命名的显式动作。标签不自行提交这些操作；既有内核和 MCP supervisor 自身的重试、恢复及结算策略保持不变。

以上均为前端展示和既有读取边界的适配，不新增删除墓碑、淘汰事件、持久恢复记录或全会话常驻轮询。应用重启后的布局仍遵守首版不保证恢复的约定。

## 9 硬切与不变边界

完成切换时，正式启动命令和桌面图标走同一桌面启动路径，移除自动打开外部浏览器的产品入口及已被替代的原生操作。内部 HTTP 服务、现有非 UI 工具和测试接口按各自用途保留，不为迁移任意删除无关能力。

开发阶段可以逐项完成，但交付时不出现新旧产品路径自动回退、双写或旧/新协商。更新 README、构建命令和相关测试，只描述新的正式使用方式。

必须保持：

- provider epoch 内 SYSTEM/tools 字节一致、messages 仅追加；只有现有明确边界可以重建输入根。
- 模型上下文、执行权、工具结算、停止、权限和跨重启会话语义不变。
- 历史定位、引用、分叉、任务分组与按需分页不变。
- 不增加 durable event、业务关系、job、receipt、checkpoint 或专用执行恢复协议。
- 不增加总会话、总工具调用、总轮次或任务生命周期上限。
- 配置继续走现有 home 与 settings owner。不会把凭据放进前端、子进程命令行、报告或构建产物。

普通重启遵守既有会话重启合同；开发期破坏式更新先结束旧进程，再重置数据库，不承诺恢复被清除的会话或继续旧任务。这一明确的数据清除边界不改变未重置会话的模型上下文和执行语义。

## 11 适度验收标准

用户明确要求不过度扩大实测。以当前 macOS 和已有 Ubuntu 环境为主，现有 CI 架构能力尽量复用；未能实际运行的架构不写成已验收。无需购买或准备多代 macOS 设备，无需逐一测试 Linux 发行版和各种桌面环境。

最小验收集合：

1. 从图标启动安装产物，程序资源不依赖仓库 `.venv`、源码路径或开发机 Homebrew PostgreSQL。验证 `pulsara app` 启动/聚焦同一实例、命令返回和关闭终端不影响应用；抽查一个保留的配置管理命令和内置数据库状态检查，确认旧 Web 参数及 `db migrate` 已移除。可通过独立目录与干净环境检查，不强制搭建完整空白机器实验室。
2. 新 home 能初始化数据库，两个扩展能加载；完成一次实际搜索或记忆检索链路。
3. 完成一个真实模型任务，包含文件读写和终端调用；用现有长会话数据或长历史测试样本验证分页、历史定位、引用、分叉和任务分组。测试数据通过现有测试注入点准备，不为此增加产品迁入功能，无需重新消耗整个 1M 上下文。
4. 拖入文件、目录与粘贴截图各一次，确认原始路径/附件行为正确，且不会重复加入或加入错误会话。
5. 刷新工作台不会终止任务；关闭/返回窗口与明确退出行为符合约定；退出后无继续占用该专用实例的内核。
6. 同版本普通退出重开后会话和数据存在。执行一次专用测试库的破坏式更新验证，确认旧数据按预期清除、当前基线可用，工作目录文件及无关设置未被删除。
7. 定向覆盖启动失败、重复启动和内核意外退出，失败提示可用且不删数据、不重复执行工具。
8. 检查不可信预览无法调用桌面桥或内核特权接口；这是新增宿主能力的必要边界验证，不扩展为无穷安全测试清单。
9. 用现有长会话或等价测试样本同时打开任务组与两个任务详情，验证跨组依赖、分页和定位；关闭一组不影响另一个任务页，同一任务重复打开只聚焦，同命令两次执行保持两个进程实例。打开/关闭标签不启动、取消或重跑任务，也不新增模型消息。后台进程终止进入 pending 后关闭标签或切出会话，确认原控制由内核继续结算，返回后按原引用查询；结果不可查也不重发。查询边界可用已有测试注入定向验证。
10. 验证全局能力页、会话能力与 MCP 标签打开、聚焦及刷新仅更新显示；重新加载能力与重连为单独动作。切换会话后显示与操作仍归正确对象；旧 Host 的进程或控制引用不会被新 Host 接管。
11. 实际打开 test8 文档包，完成入口 HTML → 学员入口 → Markdown 手册 → 返回/前进；再验证 `SKILL.md` 到相对路径文档。覆盖聊天重复打开、浏览内同标签导航、显式新标签、同文件不同浏览历史、源码切换及阅读位置；新开或关闭一个文件不撤销另一个文件的读取资格。
12. 验证缺失/不支持的目标有可返回的错误反馈；用同一子树内/外用例覆盖 HTML → Markdown → 后续链接、新标签、重试、前进后退及重连，确认范围不扩大，同路径不同范围不错误合并。冻结页仍显示原发布内容，未包含的文档不被当前磁盘文件冒充。切会话、关闭标签或快速导航后的迟到结果不覆盖新页面。
13. 在当前 macOS 和 Ubuntu 桌面检查标题栏拖动、窗口控件、侧栏折叠/调宽和窄窗口布局；标题采用实际名称和类型图标，不出现一排默认总览或自动弹出的任务标签。
14. 用一个本地文档包定向验证新导航、历史跳转和刷新失败后的游标/前进分支；文件删除后重试、原子替换后重新读取不拼接旧内容，入口删除但子文档存在时重连仍使用原目录范围。确认冻结内容缺失不回退到磁盘文件。可通过临时文件与既有测试注入完成，不增加监控或全平台矩阵。
15. 定向验证暂时断连、读取资格失效、明确会话删除三者显示与清理不同；任务/进程列表缺项不关闭实例标签或推断执行失败，旧 Host 不能接收标签重试，控制结果不可查不重投。Skill 文件缺失不直接改变能力状态，MCP 的只读重试不触发显式重连，也不阻断 supervisor 原有恢复。

自动测试聚焦变更 owner、关键协议边界和已出现问题；保留现有断言，不通过 skip/xfail 缩小既有正确性要求。真实页面验收替代不了内核关闭顺序与权限边界的定向测试，反之也一样。
