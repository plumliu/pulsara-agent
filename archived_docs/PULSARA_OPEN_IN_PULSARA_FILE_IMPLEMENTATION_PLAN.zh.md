# open_in_pulsara 侧栏展示实现方案

日期：2026-10-19

状态：已按用户授权实现集合参数、逐项 best effort 和文件／网页／对象混合展示；Browser tab plan review（GPT-6 Astra high）完成实施复查，修正发现的问题后未发现剩余阻断项。验证记录见第 12 节。现有 runtime 执行、结算与前缀重建边界不变。Release 工作暂后置；独立的 Release 方案保留。

## 1. 目标与范围

增加内置工具 `open_in_pulsara`，让主代理请求在当前会话的右侧标签中展示文件、HTTP(S) 网页、已有后台进程、已有 MCP 连接或三类总览。复用各对象既有视图、身份及控制 owner；模型提供对象目标，前端决定创建或复用标签，模型不操作前端 tab ID。

文件目标覆盖现有预览器支持的 Markdown、文本、图片、SVG、PDF、表格及本地 HTML，未支持的文件格式沿用当前说明页。另支持具体后台进程、具体 MCP 运行连接，以及能力、任务、后台进程三个总览。支持用真实 `task_id` 直接打开所属任务组并选中该任务，单个子代理同样属于一个任务组。不包含目录、Git review 或冻结可视化引用。

网页目标使用 `browser` 类型，复用已实施的 [网页标签实现方案](PULSARA_DESKTOP_BROWSER_TAB_IMPLEMENTATION_PLAN.zh.md) 及 WebContentsView owner。包括外部网站和任务已有的本地 HTTP(S) 服务；工具不启动服务器、不新增网页自动操作或模型读取能力。本地 HTML 文档包仍使用 `file`，不交给网页 owner。

首版不提供跨会话、标签 ID、指定阅读根目录、新窗口、底部面板、行号定位或强制新标签参数。网页包通过一个本地 HTML 入口打开，后续相对链接继续使用现有文件浏览行为。

产品收益是减少交付后的手动点击。工具只请求展示；文件读取给模型、视觉检查、内容发布和任务执行仍由既有工具负责。网页一旦被前端打开，会正常联网并执行页面脚本，不能将展示解释为“不会发生网络请求或网站侧效果”。

## 3. 工具输入与结果

输入包含非空的 `targets` 数组，单文件也使用一项数组，不保留单数 `target` 参数。结构为：

```json
{
  "targets": [
    {"type": "file", "path": "/absolute/path/说明.md"},
    {"type": "terminal", "process_id": "实际进程 ID"},
    {"type": "mcp", "runtime_server_id": "实际运行连接 ID"},
    {"type": "panel", "name": "tasks"},
    {"type": "browser", "url": "http://localhost:3000/report"}
  ]
}
```

每项按以下联合类型严格校验，类型以外的额外字段也拒绝该项；单项不合格不拒绝其他项：

| 类型 | 输入字段 | 目标身份来源 |
| --- | --- | --- |
| `file` | `path` | 交付文件路径 |
| `browser` | `url` | 已知的完整 HTTP(S) 地址，例如回复中的来源网址或终端报告的服务地址；不能用页面标题或猜测端口代替 |
| `terminal` | `process_id` | `terminal` 返回值或 `terminal_process` 的 list 结果 |
| `mcp` | `runtime_server_id` | 能力查询的运行时目标，不能用配置声明 ID 代替 |
| `task` | `task_id` | `spawn_agent`、`spawn_agent_group` 或 `list_agent_tasks` 返回的真实任务 ID；在调用会话内读取其 canonical 任务行，定位所属任务组并选中该节点 |
| `panel` | `name`：`capabilities`、`tasks`、`background`、`browser` | 前三项是固定总览；`browser` 新建空白网页，无须先查对象或提供 URL |

文件的 `path` 为非空本地路径。相对路径相对于调用会话的工作目录，不相对于终端当前目录、右侧当前页面或用户正在查看的其他会话。沿用已有读路径的 `~`、`${PULSARA_HOME}` 展开语义；不接受 URL 或 `image:` 引用。最终输出绝对路径，展示阶段仍需通过文件预览器的验证。

网页的 `url` 必须是非空、带 `http://` 或 `https://` 的完整地址，不接受用户名/密码、磁盘路径、`file:`、`javascript:`、`data:`、`image:` 或搜索词；拒绝非法 URL。仅用户地址栏支持省略协议，工具参数不猜协议、不做 HTTPS 失败降级。工具对 URL 只做纯参数校验并去掉首尾空白，结果保留该请求地址；完整 href 的 WHATWG 规范化、去重及控制端口阻断继续由网页 owner 执行。工具不探测地址、不读取页面，不在内核复制 Chromium 导航或 URL 解析器。

工具规范化目标，并从可信执行上下文为进程和 MCP 补齐原 Host 身份，不由模型填写 host/session/tab ID。不预先给文件发读取 token，不把文件内容读入模型上下文，不调用系统默认应用或外部浏览器。路径规范化保留预览所需的词法路径，不先解引用符号链接来绕过现有 no-follow 检查。

正常结果使用既有 `ToolExecutionResult`，正文的 `targets` 只包含通过逐项检查并规范化的目标，保持其输入相对顺序及重复项；有被拒绝的项时附加 `errors`，没有则省略。文件返回绝对路径，网页返回上述请求 URL（不返回最终重定向地址或页面标题）；进程/MCP 附带其原 Host 身份，以便历史手动打开也不会误绑新实例。例如：

```json
{
  "targets": [
    {"type": "file", "path": "/absolute/path/说明.md"},
    {"type": "terminal", "process_id": "实际进程 ID", "host_session_id": "调用所属 Host"},
    {"type": "mcp", "runtime_server_id": "实际运行连接 ID", "host_session_id": "调用所属 Host"},
    {"type": "panel", "name": "tasks"},
    {"type": "browser", "url": "http://localhost:3000/report"}
  ]
}
```

部分目标被拒绝时，例如输入第 2 项使用了不支持的网页协议，返回：

```json
{
  "targets": [
    {"type": "file", "path": "/absolute/path/说明.md"}
  ],
  "errors": [
    {"index": 1, "message": "网页地址只支持 HTTP(S)"}
  ]
}
```

`errors` 按原始输入顺序排列，每个被拒绝的项只给出一个简短、可操作的原因；`index` 从 0 开始，指向原始输入 `targets`，不是过滤后的结果数组。不回显整项参数、堆栈或包含凭据的 URL。模型可修正后只重试失败项，不要求重复整批。`targets` 与 `errors` 共同覆盖所有输入项，保留重复项的各自处理结果。

工具名、调用身份和执行成功状态使用现有工具记录，不在结果正文重复返回 `status`、会话 ID、标签 ID 或解释性文案。`type` 用于区分目标，`host_session_id` 是原对象身份的一部分；`errors` 仅报告工具执行时已知的逐项拒绝原因，不是界面回执。正常结算表示工具已完成逐项处理，不表示所有目标通过或已打开；即使全部目标被拒绝，也正常返回空 `targets` 和逐项 `errors`，不将其变成整次工具错误。原先仅含 `paths` 的草案被这个统一结果替代，不实现两套结果格式。

失败边界分为三层：

- **调用级 gate：整批拒绝。** 工具不可用、无调用权限、非 ROOT scope，以及外层参数非法（无法解析、缺失 `targets`、不是数组、空数组或外层额外字段）继续使用现有工具错误机制，不产生展示请求。不绕过已安装工具 surface 或调用授权。
- **目标级检查：逐项 best effort。** 非法项结构、未知类型、缺失或额外字段、空路径、非法网页地址等仅拒绝该项；继续检查其他项，并将通过项放入 `targets`、拒绝项放入 `errors`。不得用笼统异常捕获把取消、执行故障或提交失败伪装成目标拒绝；这些仍沿用现有 runtime 结算路径。
- **展示级检查：由现有 owner 处理。** 文件类型、存在性、读取资格、对象可用性、网页网络隔离与加载结果仍在展示阶段判断，不为填充 `errors` 提前读取文件、探测网站或复制 owner 的权限规则。目录在展示入口拒绝；文件丢失、不支持、网页受阻等沿用对应错误/说明页，单项失败不影响其他项。界面断开或稍后加载失败不追改已提交的工具结果，不等待前端回执，不重试模型回合。

现有 `tool_runtime.py` 会在执行前按 descriptor schema 校验整个调用，因此本工具的外层 schema 只约束参数对象、唯一字段 `targets`、数组类型与非空要求，`items` 使用空 schema；上述联合类型及字段要求写在工具参数说明中，并在本工具执行体内逐项严格校验。否则把严格联合类型直接放进 `items` 会在通用 gate 提前造成整批拒绝。不得因此修改通用 gate、放宽其他工具校验、增加第二套 provider schema 或跳过权限检查。实施验证须通过真实工具入口覆盖非法单项，不能只测直接调用执行函数。

通过检查不保证文件存在、网页可达、已成功渲染、用户已看到或内容已验证；这些边界写在工具描述中，不逐次占用模型上下文。全部被拒绝的结果没有展示目标：前端照常消费记录，但不创建标签、不展开侧栏、不改变焦点，也不把该空批次视为新的展示意图去取消先前有效请求。

建议工具描述：

> Show files, HTTP(S) webpages, existing background processes, MCP connections, or overview panels in this conversation’s right-side tabs when the user asks to open them or active presentation helps the current task. Use ordinary reply links for sources and optional reading; do not open every cited page or repeat a URL solely because you opened it. Group related targets in one call; the last accepted target is selected. Invalid targets are skipped and reported in errors with zero-based input indices; correct and retry only those targets. Use complete HTTP(S) URLs, process IDs from terminal results/listings, and MCP runtime IDs from capability inspection. File paths are relative to this conversation’s workspace. Accepted targets are display requests, not confirmation of opening. Display is best-effort and starts after the tool result, without waiting for your final answer; later display failures are not returned to you. Opening webpages loads them normally; it does not give you their contents or verify rendering. It does not start servers, run terminal commands, or reconnect MCP. Only the root assistant may call this tool.

## 4. Runtime 边界与主代理归属

### 4.1 走普通工具调用，不增加界面回执协议

工具由现有 kernel tool port 绑定，正常执行和提交工具结果。展示失败不阻止后续模型调用、任务完成或会话保存。内核不等待 renderer，不增加超时重试、UI receipt、投递确认或恢复 job。

不新增 durable event、live event kind、数据库表、subject、append guard 或发布队列。利用现有工具请求/结果记录和已有 `observe.committed` 流，界面的展示状态保持可丢弃。

前端不扫描模型自由文本、任意工具输出或可视化围栏来触发该操作。只有对应真实 `open_in_pulsara` 调用、正常结算且 `targets` 非空的工具结果才有资格成为自动展示请求；带 `errors` 的部分接受结果仍符合此条件。具体匹配见第 5 节。

### 4.2 只允许 ROOT scope

调用所属会话、scope 和工具调用身份从已安装的执行上下文获得，不接受模型传入会话 ID。首版只由主代理展示；子代理返回文件路径供主代理汇总，不能直接争抢侧栏。

在构建新工具 surface 时依据现有 scope 信息限定主代理可见性；执行边界仍校验实际 scope，不只依赖提示词或前端过滤。复用现有工具绑定、权限和恢复配置，不为此建立一套 scope 注册系统。工具不新增文件写入、终端执行或网页操作权限；复用现有工具调用授权，网页显示还受既有原生 owner 的权限/网络规则约束。不得因为工具被称为“展示”就授权点击、提交表单、登录、重连或绕过控制服务隔离。

在现有 `_recovery_contract()` 中明确归入 `read_only`，避免落入默认 `unknown_effect` 而改变执行异常分类。此分类描述内核里的请求规范化与结果结算，不承诺页面加载没有网络副作用。网页加载发生在成功结果提交后的独立前端效果中，不让工具执行直接联网，不为展示失败重新执行工具。界面展示仍是可丢弃效果，不新增自动恢复或重放路径；不修改其他工具的恢复合同。

新增描述和提示词仅在已批准的 provider 输入重建边界生效：新的 cold epoch 或显式采纳的 compaction successor。既有 epoch 的 SYSTEM 和 tools 字节保持不变，messages 仍按后缀追加。不因前端上线、重连、刷新能力或恢复会话而偷偷加入工具或重写前缀。

## 5. 新请求与历史回放严格分开

### 5.1 自动展示的唯一来源

自动展示只从当前 `LocalRuntimeConnection.observeNext` 接收的新提交记录产生。不得在 React 渲染、`project()`、通用 `mergeEntries()`、历史正文补全或工具气泡挂载时执行打开操作。

候选必须同时满足：

- 来源为该连接 `observe.committed` 中的 `IMMUTABLE_ENTRY`，记录为 `TOOL_RESULT`，scope 为 ROOT，结果成功，且非 `IMPORTED_HISTORY`。
- 通过既有 `assistant_entry_id + tool_call_id` 关联到同会话、同 scope 的真实工具调用，工具名称为 `open_in_pulsara`。不能仅凭结果 JSON 的字段认定来源。
- 精确结果正文可读取，结构符合第 3 节，且 `targets` 非空；只展示 `targets`，不从 `errors` 或原始被拒绝参数构造目标。通过既有 `source_coverage/display_kind` 确认原始结果完整；精确读到 canonical 内容不代表原始输出未截断，不能从截断预览或自由文本猜测路径。
- 记录的 event sequence 高于该连接已消费的展示水位；当前会话可见、连接仍有效且角色为 controller。

关联调用未在当前历史窗口中时，直接复用既有 `historyPost('window', {anchor_entry_id, maximum_entries: 1, ...})` 获取精确锚点，核对会话、ROOT scope、`tool_call_id` 及对应 `TOOL_CALL.tool_name`。查询只取值，不安装历史页面，不改变分页或显示投影；不能调用会执行这些操作的 `locateEntry()`。完整结果正文复用既有 content 读取，无需新增后端接口、权威字段或 live 缓冲补证。读取失败或内容不完整时放弃自动展示，保留历史及已有手动入口。

### 5.2 水位与消费时机

初次连接用 canonical snapshot 的 `event_sequence_cut` 建立展示水位，snapshot 本身不产生打开操作。该水位是前端 process-local 的一次性效果去重状态，不替换或改变协议的 `eventSequenceCursor`。

对每批 observe，先按序识别水位之后的候选并推进消费水位，再做异步正文读取和文件打开。重复返回同一记录、React 重渲染、重复订阅都不重复消费。异步失败也不把消费水位倒退；明确的新工具调用或用户点击才可再次尝试。

关联查询、正文读取和文件预览异步执行，不在 `observationOwner` 串行链内等待，慢读取不能阻塞后续 observe 或工具结算。候选消费与请求发起保持记录顺序，使用可取消的本地操作承接；不同批次的异步完成不承诺严格有序，但旧批次迟到不能夺走新批次的焦点；复用来源事件序列和可取消操作对象比较展示意图，不建设等待队列或持久化任务队列。

只有实际接受的 canonical snapshot 刷新/重新定基线，才提升展示水位到相应 cut，并取消此前尚未完成的展示动作；不从快照恢复展示操作。普通历史 window/context 查询不是重新定基线，被现有逻辑拒绝的旧 snapshot 也不改变展示状态。所有序列比较复用现有无精度损失的十进制序列处理。

只推进展示水位不能取消或跳过协议观察，也不能干扰历史分页、工具结算或任务列表更新。历史数据仍按原路径完整可读。

### 5.3 不自动重放的入口

| 场景 | 行为 |
| --- | --- |
| 首次进入旧会话、重启桌面、页面重载 | 恢复历史，旧调用不自动打开任何目标 |
| 向上分页、历史定位、搜索跳转、正文补全 | 只呈现记录，不产生展示操作 |
| 断线后重新连接或 canonical rebaseline | 从新基线消费未来记录，不补开断线期间已进入基线的目标 |
| 只有 live snapshot / `TOOL_RESULT_END` | 不触发；等待正常 committed 记录，避免未提交结果生效 |
| 会话分叉、导入历史、旧回合恢复读取 | 继承的旧调用不触发；新分支的新调用按自身会话处理 |
| 用户关闭标签后再次渲染旧记录 | 保持关闭 |
| 用户主动点击旧记录里的目标入口 | 作为新的用户操作；文件读当前内容；网页沿用打开与去重规则，命中已有标签时聚焦、未命中才加载原请求 URL；进程/MCP 保留原 Host 身份 |

不提供跨重启补投、历史补开或“至少一次展示”承诺。不为防止 advisory 展示丢失而建设持久化队列；历史工具摘要中的目标入口始终可供用户手动重试；普通回复中的链接也保持原有点击行为。

## 6. 当前会话与异步竞态

展示请求携带来源连接对象及其已有 sessionId、connection generation，不使用响应到达时的全局 activeSessionId 重新归属。开始消费和发布前的每个异步返回后，均核对来源仍对应当前 controller 连接、当前可见工作台及同一会话。

主界面为本次可见状态保留可取消的本地操作对象；切换会话、离开工作台、断开/替换连接、删除会话或组件卸载时使其失效。A → B → A 不能仅因 sessionId 再次相等而接受旧 A 的迟到响应。

上述取消约束覆盖尚未发布的展示意图。标签被 workspace 正式采用后，其异步加载归现有文件/网页 owner 管理，不再因来源批次失效删除正常标签；尤其网页在切换会话、进入设置或收起后继续保活，迟到状态不得切换会话或抢焦点。会话删除、宿主重载/退出等资源终止行为仍按既有 owner 处理。第 5 节取消尚未完成动作同样不撤销已采用的标签。

| 场景 | 决策 |
| --- | --- |
| 当前会话的新请求含通过项，侧栏收起 | 打开/聚焦目标并展开侧栏，沿用该会话已保存宽度 |
| 用户正在另一个会话或设置页 | 丢弃自动展示，不切会话、不修改其他会话侧栏状态 |
| 请求准备途中、发布前切到其他会话 | 取消展示；迟到的 preview token 由原 owner 关闭，网页不创建或导航 |
| 切回来源会话 | 不补开被丢弃的请求；用户可点击链接 |
| 当前连接只是 observer | 不自动打开；保留已有只读记录与手动操作规则 |
| 同一真实调用重复观察 | 只消费一次 |
| 不同的新调用再次请求同一目标 | 按目标去重规则复用或新建并聚焦；这是新的展示意图 |

首版不实现参考工具中的隐藏会话 queued 行为，也不新增后台请求积压。默认新会话侧栏关闭的偏好保持不变；只有有效的新展示请求或用户动作才展开。

## 7. 目标标签、批量展示与读取资格

程序化打开复用 `FilePreviewProvider` 的顶层文件入口，提取不依赖 `HTMLElement` 的小型接口；鼠标链接打开和工具展示调用同一入口，不伪造点击元素，也不复制路径解析及读取 token 管理。

工具结果中 `file` 目标的 `path` 是原始绝对文件路径；进入预览 API 前，使用现有 `fileUrl/pageAddress` 逐段编码为 file URL，不能直接把原始路径当 URL 解析，避免 `#`、`?`、`%` 被误当片段、查询或转义。结果正文和用户看到的路径仍保留原始值。

### 7.1 批量展示与焦点

一次调用中通过目标级检查的 `targets` 对应一批展示请求；被拒绝的项不占标签位置、不产生错误标签。`targets` 为空时不发起展示；非空时工具结果提交后即可处理，不等 final answer，也不将多次调用积攒到回合结束。提示词建议交付文件准备好后集中调用；中间成果需要展示时仍可调用。

由文件浏览 owner 准备文件预览元数据或错误状态，网页 owner 准备 URL 及可复用目标描述，进程/MCP/总览通过既有 inspector owner 生成对象视图描述。通过项的准备各自完成为可展示内容或错误状态，并再次确认归属后，统一发布标签与选中状态；不能因一项准备失败撤销其他项。这是一次界面状态发布，不是整批成功或回滚的事务。无需等待网页、HTML 资源或图片渲染；一个网站加载缓慢不能阻塞本批其他标签出现。

准备阶段不创建或导航原生网页，不调用当前会逐项 insert/activate 的 `BrowserTabs.open()`。复用现有 owner，增加最小的准备/统一采用入口：发布时复查网页去重及归属，在同一前端操作中采用新记录、确定顺序和最终选中项，再异步创建/加载各新网页；其余网页始终隐藏保活。文件准备也不先激活临时标签。发布前切会话等取消时释放未采用 token，网页不得发起请求。发布后网页已经是该会话的普通标签，切换会话或收起只隐藏保活；关闭/删除按既有 owner 释放，迟到创建结果不会复活标签。

- 新标签按参数顺序追加；已有标签保持位置、历史及既有视图状态，仅复用。文件按第 7.2 节、网页按第 7.5 节、对象按第 7.4 节去重；重复项指向同一实例，`targets` 结果仍保留通过项的输入相对顺序。
- 只切换一次焦点，选中结果 `targets` 最后一项对应的标签，不逐项调用会激活标签的 `workspace.open()`。在现有 workspace owner 内提供最小的批量发布入口，不另建标签管理器。
- 通过目标级检查后，单项预览失败使用错误页，不阻止其他项；结果 `targets` 最后一项展示失败时仍选中其错误页。原始输入的末项若在工具执行时已被拒绝，则选中前一个通过项。目录拒绝同样是该项的展示结果，释放其临时读取资格。
- 加载完成顺序不决定排列或焦点。旧批次晚于新批次完成时可补入仍有效的标签，但不抢占新批次焦点；用户在等待期间主动选择或关闭标签、收起侧栏时，旧请求也不重新激活或展开。使用本地操作有效性标记处理，不新增持久化状态。
- 不设任意目标数量上限；沿用已有工具参数与预览读取的资源边界，不新增无界并发读取路径。

### 7.2 文件去重规则

- 使用同一会话、预览器确认后的路径、相同 `reading_root` 判断可复用标签；不得只按文件名去重，也不跨会话或跨读取范围合并。
- 只复用当前正展示目标文件的标签。若用户已从 A 导航到 B，即使 A 还在该标签的历史中，也不把该标签强行退回 A；打开 A 使用新的浏览实例。
- 命中现有标签时聚焦并保留既有导航历史、滚动记录及源码/预览模式，不主动 refresh 或替换存活标签的 token。命中当前活动 HTML 时，不先激活临时标签，以免导致不必要的 iframe 卸载。切换到后台标签保持现有挂载行为，不承诺页面保活；不为此增加 keep-alive。模型刚修改文件时可提示用户用现有刷新按钮查看，首版不增加隐式刷新语义。
- 先取得临时预览，检查取消状态并根据实际响应去重，再按批量规则决定发布新标签或选中已有标签。不要照搬当前 `create()` 先激活可见临时标签、响应后再去重的顺序。未命中时才加入标签集合并展示；失败时仅在操作仍有效时显示现有错误页。
- 并发结果返回后，在发布前重新检查当前标签集合和导航状态；已开始导航到其他文件的标签不能只凭尚未替换的旧 `file.path` 被命中。保留用户显式创建的多个实例，只选择一个有效匹配，不批量合并。未采用的临时 token 由原 owner 释放，存活标签继续使用自己的 token。
- 工具只发顶层打开请求，不传 `basePreview` 或任意 `reading_root`；HTML/Markdown 内的后续导航继续沿用当前标签的读取范围。

### 7.3 关闭与迟到响应

消费标记先于打开，不因用户关闭标签而删除。自动请求确认展示前不进入可恢复的标签集合，取消后不留下加载标签，避免切回会话时被现有标签恢复逻辑重新读取。已存在的正常标签不因另一个请求取消而删除。加载中的标签被关闭后，迟到结果不得创建或激活标签，返回的 token 由原 owner 释放。

新增的程序化打开路径须检查本次可见状态操作对象和 `FilePreviewProvider` 已有的 ownerKey、sessionId；涉及已有标签时也检查其 tab request。成功、失败及去重命中后准备 activate 前都要重新检查；不能只在网络读取前检查一次。目录被拒绝时也释放已领取的临时 token。

模型路径不授权扩大文档导航范围，文件符号链接、目录、外链、资源加载及 CSP 继续使用现有规则。不存在或失去访问资格的文件沿用现有错误页；不搜同名文件替换、不自动重建文件、不自动拉起其他应用。

### 7.4 任务、后台进程、MCP 与总览入口

任务使用 `{ "type": "task", "task_id": "task:..." }`，模型不填写 batch、Host、session 或前端 tab ID。工具仅校验目标形状和任务 ID 格式，不启动、重试、等待或取消任务。前端复用当前会话的任务读取 owner 和 canonical `batch_id`，复用既有 group 标签身份并选中目标节点；主对话的紧凑任务气泡也使用同一展示入口。一个任务读取失败仅产生该项的错误页，不阻止其他目标展示。取消、会话切换及 A → B → A 的归属检查与其他异步展示一致。

主对话的任务组只保留组进度与紧凑节点，不再展开目标、指导、思考、工具或最终回复；完整任务对话只由侧栏承载。

模型不需要列出前端标签，也不依据标签标题或数组下标定位对象。三类入口直接使用固定 `panel.name`；重复打开复用当前会话既有总览。总览读取当前会话的现状，打开不触发能力重新载入、MCP 重连或进程控制。

第四个入口 `{"type":"panel","name":"browser"}` 对应顶部“新建网页”。它创建空白网页标签并聚焦地址栏，不接受 URL 或额外字段；需要具体网页时仍使用 `browser.url`。同批重复项共享一个新空白标签，后续调用另建空白标签，不复用或清空已存在网页。仍由既有 BrowserTabs 在整批发布后创建原生实例，不发起网页导航；发布前取消不创建实例。历史摘要显示“新建网页”，用户点击后才新建，历史读取不自动执行。

进程详情直接展示命令、状态、来源、目录和输出，不复用列表展开按钮。列表点击通过与 MCP 详情相同的 View Transition 机制移动所选卡片并淡出其他行；工具直接打开不制造来源卡片动画。命令悬停仅显示完整命令；列表打开按钮不压缩，窄侧栏显示图标。工具结果采用独立目标行和拒绝原因区域，不显示重复的完成底栏。

**后台进程。** 使用真实 `process_id`，不知道 ID 时先调用 `terminal_process`，参数为 `{"action":"list","include_running":true,"include_finished":false}`。已结束但记录仍可读的进程也可展示。工具运行上下文补齐原 `host_session_id`；前端用 `sessionId + host_session_id + process_id` 复用现有 `process` 标签。没有对应记录时显示不可用，不根据命令内容寻找替代进程。不启动 shell、不执行命令、不写 stdin、不终止进程；关闭标签仍只关闭视图。

**MCP。** 使用 `list_capabilities` / `inspect_capability` 的准确运行时目标。若列表返回配置声明，先 inspect 该 target，再从 `runtime_target.runtime_server_id` 取运行实例；没有 runtime_target 时不能将声明 `server_id`、工具名、显示名称或 endpoint 当运行 ID。此时模型可打开能力总览。前端以 `sessionId + host_session_id + runtime_server_id` 复用现有 `mcp` 标签，直接呈现单连接详情；不重新渲染技能/MCP 分类栏、导入入口和继承能力折叠层。编辑、启用、认证、重连、移除继续由用户显式操作，打开与刷新显示不能附带调用它们。

进程和 MCP 的 Host 身份在工具执行时从可信上下文取得，经既有工具结果保存；不能在前端接收时拿“当前 Host”覆盖。投递时还要核对来源连接仍属于该 Host。旧记录的手动入口也沿用保存的完整身份，原 Host 已失效时展示不可用，不能自动改绑同名新实例。只是暂时读取失败时保留原目标并允许只读重试，不把失败当作删除。

工具直接打开没有来源卡片，不模拟列表点击或播放从另一张卡片飞入的动画。用户手动点击 MCP 列表仍走实际来源卡片的过渡；工具批量展示只为最终选中项安排入场，不逐项播放、抢焦点。动画不参与对象身份或执行结算。

### 7.5 网页目标、重复打开与权限

网页标签归属于真实调用的会话；URL 不是跨会话身份。同会话多个网页复用已有临时浏览分区，会话之间继续隔离。复用 `BrowserTabs`、原生 owner 和显示槽位，保留导航、重定向、历史、缩放、输入焦点、遮挡及标签保活规则；不新增第二套浏览管理器、标签持久化或浏览记录。

- 使用网页 owner 的 WHATWG 完整 href 比较，保留路径大小写、query 和 fragment，HTTP/HTTPS 不合并。仅复用同会话中当前已提交到目标 URL、未加载/未待导航且未崩溃的可复用实例；优先当前活动匹配，否则按现有标签顺序选一个。保留原生历史、滚动、表单、cookies 与现有错误/状态，不自动 reload。页面已从 A 导航到 B 时，请求 A 不倒退 B，也不按历史 URL、标题或“最初打开地址”命中。
- 批内相同规范化 URL 只准备/采用一个目标实例，所有重复项指向它，仍按结果 `targets` 最后一项决定选中项；结果数组保留通过项的输入相对顺序。发布前重新检查现有导航状态。不同调用遇到仍在导航的旧实例时沿用现有不命中规则，不能依赖过时 URL 误复用；不为去重创建跨批等待队列。
- 用户已有多个相同 URL 实例不合并或关闭。工具不接受 tab ID、强制新实例或导航现有标签参数；普通链接与工具共用目标打开规则，用户仍可使用既有显式新标签操作。
- 只在前端接受本批展示后才创建/导航网页。新标签加载失败或被控制端口规则拒绝时，保留该目标的错误视图；结果 `targets` 末项展示失败仍选中其错误视图。加载/重定向后的实际 URL 由原生状态驱动，不追改工具结果中的原请求 URL。
- 保留 HTTP(S) 和页面资源策略、禁止控制服务端口、权限默认拒绝、下载与特权协议限制。工具不能扩大读取权限、传入预览 token 或借 `browser` 打开磁盘文件。页面可正常联网和执行脚本，但模型不会得到网页正文、截图、Cookie 或操作句柄。
- 工具主动展示不伪造文件 iframe 的点击或 user activation，不经过不可信 HTML 消息桥。文件 HTML 内的外链仍按现有可信外壳激活校验及“打开网页”确认入口处理，不能借工具扩展放宽该路径。
- 发布前取消不分配原生资源；发布后关闭加载中的标签，迟到原生实例由 `BrowserTabs` 原 owner 关闭。会话删除、宿主重载/退出仍沿用分区退役流程，不给工具加补投、复活或跨重启恢复。

## 8. 历史显示与提示词

摘要只为结果 `targets` 提供手动打开入口；`errors` 按原始项序号呈现简短原因，不为拒绝项创建可绕过检查的打开入口。全部被拒绝时只显示原因，不显示“已请求展示”或任何打开成功文案。原始结果仍保留，正常历史读取不触发展示或自动重试。

工具记录提供简短的“请求展示”摘要；文件提供可点击路径，网页提供原请求 URL，进程/MCP/总览提供对应的手动打开入口，避免显示未经确认的“已打开”或“已验证”。历史记录的链接使用当时保存的绝对目标，不按当前工作目录重新解释；点击仍读取当前磁盘内容，不冒充历史文件快照。这些入口在原始工具输出默认隐藏时也应可访问，复用现有工具结果摘要呈现。历史网页入口由用户主动点击才执行打开：沿用现有去重规则，命中已有标签时直接聚焦并保留状态，未命中才加载原请求 URL。它不是原发布快照，也不承诺旧 localhost 服务仍在运行。

### 8.1 普通链接与主动展示

普通回复中的链接用于来源、引用、可选阅读和按需再次打开，由用户点击才展示。当前会话的 HTTP(S) 点击已由前端路由到右侧网页标签；这是 UI 行为，不需要另写进 system prompt，也不能因模型输出一个 URL 就自动展开侧栏或导航。

`open_in_pulsara` 用于用户明确要求打开对象，或主动展示当前成果有助于完成任务的时候。判据是“是否需要现在主动展示”，不是“是否出现了网址”。例如：回答里列几个参考网页只给链接；用户说“打开刚启动的演示页面”时，使用 `browser` 目标。一次调用可以混合文件、网页和其他支持的目标，最后一个通过项选中。

工具调用后不强制在最终回复重复同一个网址。最终回复仍应保留独立有用的来源引用、交付物位置或操作说明；不能用“已经打开”替代本来需要给出的证据。手动重试由工具摘要目标入口保证，不以每次回复必须再贴同一链接作为可靠性补偿。

`pulsara-visualization` 围栏继续负责聊天内的冻结展示，`view_image` 负责模型视觉检查，网页工具只展示当前网站。一次展示调用不同时执行冻结发布、页面读取或图片检查。

### 8.2 模型可见说明的最小修订

上述选择规则放在工具描述里即可，不新增一段介绍网页点击路由的系统提示词，也不为每种对象重复解释。实施时只删改现有提示词/Skill 中与新工具确实矛盾的句子，例如若有“所有交付物都必须重复贴链接”的绝对要求，改为按交付/引用需要提供。相关目标建议集中调用、最后一个通过项选中；拒绝项依据 `errors` 修正后单独重试；不要求每次写文件、每个中间产物、每条引用都打开。

提示词、工具描述与运行时可用性在同一合法前缀重建边界一起生效。旧 epoch 没有该工具时继续使用文件链接，不注入替代别名或修改旧 tools 数组。

## 11. 交叉检查结论

GPT-6 Astra high 子代理对照生产代码完成只读审查。现有工具请求/结果、history window、content 读取及预览 API 足以支持方案，无需新增后端查询、durable/live 类型、界面回执、恢复队列或 provider 前缀重建边界。

审查发现并已纳入方案的实施约束：原始文件路径必须编码；预览去重先于可见标签发布；取消不能留下可被恢复的临时标签；精确关联不能调用改变历史布局的定位方法；异步读取不能阻塞 observe；工具须显式归入 read_only。后台 HTML 标签沿用既有挂载行为，不扩大为页面保活项目。

基础审查后，用户确认集合参数、后台进程、MCP、三个总览入口及网页目标。本轮将这些合同统一为 targets，并补充链接由用户点击、工具主动展示的分工、网页批量发布边界及当前网页 owner 的复用方式；新增部分已由同一 GPT-6 Astra high 子代理对照生产代码完成复核，未发现剩余阻断项。具体任务/任务组仍未纳入。

本轮复核确认：发布前取消与发布后正常保活的边界一致；文件并发去重、网页批内去重和跨调用加载中不命中的规则没有互相覆盖；原 Host 身份、会话分区、批量焦点与 runtime 结算保持既有归属。按复核建议进一步明确，历史网页手动入口先按现有规则去重，命中不刷新；历史验收检查的是不因旧记录新增创建/导航，不要求已采用的网页停止正常联网。未因此增加新队列、回执或持久化机制。

后续按用户确认改为逐项 best effort：调用级 gate 仍整批拒绝，目标级拒绝返回 `errors`，展示级失败由原 owner 呈现；空结果不产生展示意图。只在该工具执行体内做目标级严格校验，通用 runtime gate 不变；焦点、历史入口与验收要求保持一致。该合同及其实现已纳入本次子代理复查。

实施复查修正了循环导入、异常 URL 丢弃整批、目录预览 token 未释放、文件锚点丢失，以及迟到文件请求覆盖用户选择的问题。实际收起侧栏会更新已有交互版本：工具准备取消，普通文件迟到只允许后台加入，不重新展开。没有增加 durable/live 类型、回执、任务或恢复机制。
