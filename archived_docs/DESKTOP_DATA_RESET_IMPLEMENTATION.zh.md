# 桌面数据重置与显式卸载

本合同规定当前桌面数据重置边界；不实现旧数据迁移或旧版本执行兼容。

- 启动时由 schema owner 的基线不兼容、目录结构漂移、可读但不满足当前结构的本地配置、有效 PostgreSQL 大版本不匹配产生明确的 resetRequired。网络、权限、扩展缺失、占用、未知失败不产生此结果。错误通过私有启动协议传递，不匹配错误文字，不添加内部版本标记。
- 启动页展示不兼容说明和实际 home；按钮上一行的复选框确认永久删除。未选中仍可点击按钮，但只显示工作台共用 ToastStack 提醒。宿主同时验证布尔确认与当前重置资格，不弹模态确认框。
- 重置只作用于经 resolver 冻结的当前 home。清除数据库、设置/密钥/OAuth、本地能力、附件、快速开始文件和 UI 偏好；home 外的项目、已安装运行资源及 WSL 目标保留。Electron 用自身 Session API 清除活跃浏览存储与缓存；清理器保留其活跃目录和原有锁 inode，防止绕过独占与运行时写回。剩余结构不承载用户数据。
- Python 文件系统维护入口不读取 LocalSettingsStore，不连接旧 schema。先取得内核独占，停止已验证的专用 PostgreSQL，再取得 PostgreSQL 生命周期独占，最后清理。任一步失败不宣称成功，不因未知进程状态删除目录。重置期间持有锁，不删除并重建锁 inode；彻底卸载在移除所有已验证的运行资源后删除剩余 home。
- Python 标准库负责目录与锁，psutil 负责同用户进程身份/存活和终止，pg_ctl 负责 PostgreSQL 停止。Pulsara 只定义目标归属、停止顺序和清理范围。
- Windows 显式卸载主动请求当前应用退出，正常停止已验证的 WSL 内核和专用数据库；不响应时允许强制终止该应用的进程。此操作允许中断未完成工作，不保证远端副作用取消。不得终止发行版或按进程名终止无关实例。升级安装保留原有被占用时拒绝覆盖的行为。
- 显式维护每阶段给正常停止 30 秒，强制结束后再等待 30 秒确认退出；pg_ctl 外层允许额外 5 秒用于命令退出和输出回收，超过此边界不视为已停止；这是用户请求卸载的物理停止操作边界，不限制任务或应用寿命。PostgreSQL 使用 pg_ctl fast，失败后 immediate，并重新检查 stopped 状态。仍不能确认退出时停止清理。
- 无新增 durable event、subject、guard、关系或 job。仅临时 UI 状态与现有 OS 锁。验证采用临时 home，覆盖确认/取消、错误分类、停止失败、凭据清除、目录边界及外部文件保留；真实用户 home 不作为测试目标。
