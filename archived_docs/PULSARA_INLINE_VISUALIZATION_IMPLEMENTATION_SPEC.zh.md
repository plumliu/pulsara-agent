### 模型指引分工

SYSTEM 提供 Markdown、公式、静态 SVG/Mermaid 与交互 HTML 的选择规则，以及 HTML 发布、路径基准、资源内联、冻结、紧凑布局和环境 API 的必要契约。普通 HTML 代码块展示源码，交互页面通过本地文件及正文路径标记发布。`view_image` 描述只负责支持的输入、截图环境、引用与审阅范围；字段说明负责路径和图片引用参数。

数据分析技能首页和多视图分析参考按需指向 `references/visualization-render.md`，由该参考集中提供发布示例、图集分组、根容器、主题和动画环境示例。宿主按钮尺寸、驻留数量及裁切内部状态由实现规格记录。模型可见指导只描述当前能力与使用规则，不叙述设计历史；已有 epoch 的 SYSTEM/tools 保持原样，新文本仅在允许的前缀安装边界使用。

## 1. 目标与范围

本次只做五件事：

1. 模型在回复正文中通过 `pulsara-visualization` 围栏代码块引用本地 HTML 路径，决定展示位置。
2. 助手消息发布时读取并冻结 HTML，历史回看使用保存内容。
3. `view_image` 支持本地 HTML，由 runtime 隔离渲染并向模型返回截图。
4. 向可视化传递宿主主题、可见状态和减少动态效果偏好。
5. 小图表根据主体尺寸自适应高度；整页和放大模式继续使用视口展示。

不做交互参数持久化、画布操作转追问、画布调用工具、结构化视觉诊断、自动修复循环、新的 JSON 组件语言、外部资源代理、文件自动监听或可视化版本管理产品。现有截图审阅保留，不增加独立审计历史。

## 2. 产品流程

```text
使用现有文件工具写好完整 HTML
  → 可选：view_image(path=HTML) 查看截图
  → 按需要修改并再次截图
  → 助手正文在合适位置写 HTML 路径标记
  → 消息提交前读取该路径，冻结内容
  → 消息、HTML blob、展示位置绑定一起提交
  → 前端在正文标记处加载保存的 HTML
```

模型不再先订阅展示，不需要生成或复制展示 ID，不需要预先取得内容摘要。路径是创作来源，消息保存的是本次展示版本。

例如，第一次发布 `chart.html` 时内容是 A；修改该文件为 B 后再次发布，第二条回复展示 B，第一条回复仍展示 A。历史 HTML 中的滑块、筛选和动画仍可交互；“冻结”指保存的 HTML、脚本和内嵌数据，不指画面或 JavaScript 运行状态不变。

## 3. 正文路径标记

### 3.1 语法与模型指引

````markdown
方案的成本变化如下：

```pulsara-visualization
.pulsara/visualizations/comparison.html
.pulsara/visualizations/cost-breakdown.html
```

超过交叉点后，方案 B 的成本更低。
````

围栏 info string 去除首尾 ASCII 空格与 Tab 后必须恰为 `pulsara-visualization`，不接受附加参数。仅显式闭合的围栏生效，闭合判定遵循 Markdown 解析器的围栏规则并核对源码位置；CommonMark 将 EOF 未闭合围栏解析为 code 节点不等于可视化指令成立。未闭合围栏保持普通代码展示，不读取文件也不占展示序号。每个围栏是一个独立图集，每行一个本地 HTML 路径，按行顺序展示。每行仅去除首尾 ASCII 空格与 Tab，忽略由这些字符构成的空行；全空围栏仍产生一个 FAILED 条目，防止后续序号错位。允许文件名含空格，不做 shell 展开或命令执行；不需要 JSON、引号、HTML 源码、模型自造 ID 或 URL。

相对路径锚定该次发布使用的会话 workspace root，不随 terminal 当前目录变化。绝对路径、`~` 和 `..` 沿用现有文件读取的路径解析及权限语义；标记本身不授予读取权限。推荐创作目录仍为 `.pulsara/visualizations/`，不是额外的授权边界。

首版按 `.html` / `.htm` 后缀识别 HTML 来源（大小写不敏感），同时验证实际字节是非空 UTF-8。远程 URL、目录和单行内的无效路径不作为 HTML 展示来源；一条失败不影响同图集其他条目。

### 3.2 识别范围与示例转义

标记由 Markdown 语法解析识别，不用正则扫描整段文本，不扫描渲染后的 DOM。

首版只把助手消息公开正文中的顶层专用围栏视作展示指令。用户输入、工具结果、思考内容、引用批注中的历史文本不触发读取；块引用、列表内嵌代码及更外层代码围栏中的示例保持普通文本。需要展示标记语法时，像本节一样使用更外层围栏。

沿用现有发布范围：在已完成且无工具调用的助手消息上物化展示；不等待整个 turn 结束。带工具调用的中间消息不登记隐式订阅，也不把标记排队到后续消息。解析输入统一采用现有批注正文投影：按 block_ordinal 取得 TEXT 块、过滤空字符串，以两个换行连接。沿用 `annotations.py` 的语义并抽取复用，前端任务视图等 fallback 也对齐空块规则。跨块围栏按照这份实际展示正文的 Markdown 语义处理，不额外建立块级解析/定位协议。DATA、工具参数和 provider replay 不混入该正文。

后端和前端应使用现有 Markdown 解析依赖或适合的维护中依赖，各自解析结果通过共享语法样例验证一致；不要手写一套 Markdown 状态机。

### 3.3 展示位置与重复引用

对该展示正文中的显式闭合、顶层 `pulsara-visualization` 围栏按出现顺序解析图集，再将每个图集的路径按行顺序展平，直接复用消息内 visualization ordinal。内容合法且读取成功产生 READY，路径或读取失败产生 FAILED；失败条目和全空围栏占据序号，不能使后面的图错位。前端从同一正文推导每组的起始 ordinal 和条目数，不新增 group ID、位置绑定表或正文指纹。展示绑定只属于该消息，不是可跨会话使用的授权令牌。

每个围栏在原位置显示一个独立图集，互不影响所选页面。单图直接展示，不显示缩略图条；多图通过缩略图选择切换，保留键盘方向键/Home/End 和放大交互。不显示左右切换按钮或计数。失败条目也可被选择，使用独立的浅底色、细边框紧凑错误卡：左侧图标，右侧“可视化无法显示”标题及简短原因；文件不存在显示“未找到 HTML 文件”，原始错误保留在 title 中。只有读取失败可重试时显示重试按钮。错误卡按内容高度展示，不使用 HTML 参考视口撑高；正常 HTML 保持无框。相邻围栏仍是两个图集，不自动合并；没有标记就没有末尾图集。

正文图集不使用统一外框、底色或顶部文件名栏，正图靠正文左侧展示，保留 HTML 自身样式。文件名通过控件 title 提示提供；放大按钮统一放在占满正文宽度的图面右上角，采用半透明底色，鼠标悬停图页或键盘聚焦图页时显示；无悬停能力或粗指针设备保留淡显入口，放大状态下退出按钮始终可见。多图在会话滚动区域至少 890px 宽时，将 72px 缩略图侧栏放在版心右侧，间隔 12px；这个断点来自最大 690px 版心及两侧容纳侧栏的空间，不依赖整个浏览器窗口宽度。侧栏只包含竖向缩略图，不与正图共用底框，也不压缩正图宽度。侧栏参与布局高度，避免小图下方的正文被侧栏覆盖。

空间不足时缩略图改为图下方的轻量横排，无统一底框；放大模式也使用下方横排。缩略图只显示图片，选中项细边提示，文件名悬停显示。长缩略图列表仅限制可见滚动区域，不限制图数；保留延迟读取与驻留逻辑，支持上下及左右方向键、Home/End，切换或布局变化后仅滚动缩略图区域使选中项可见，不带动正文或 iframe。

同一消息中，同一规范化来源路径在发布准备的局部缓存中只读取、冻结一次，各位置共享相同保存内容，但有各自的 ordinal 和临时交互状态。该缓存随本次准备释放，不成为全局注册表。跨消息重新引用同一路径会重新读取。

恢复并复用原有缩略图读取链路：从消息拥有的冻结 HTML 生成一次性 PNG，沿用所有权、摘要与大小验证、浏览器隔离和串行执行槽。缩略图是可丢弃的展示数据，不是新持久资产，也不重新读取来源路径。仅为进入缩略图条可见范围的项目请求图片，切出/卸载时取消前端请求和待执行工作；沿用原 HTTP 取消机制，已启动的后台截图浏览器可能继续至现有 30 秒超时，不承诺因前端取消立即终止。生成失败显示占位图标，不阻碍正文交互。

每处图集复用最多三个最近访问页面的 iframe 驻留策略，这是浏览器物理资源缓存，不是图集条目上限。未选中的驻留页不可聚焦、不可见，向其环境传递 `visible=false`；再次切回驻留页不重建 iframe，超出缓存后重开会恢复 HTML 初始状态。各图集独立维护缓存，不把三页限制用于正文图集总数。

## 4. 发布时冻结与历史一致性

### 4.1 所有者

| 事项 | 所有者 |
| --- | --- |
| HTML 创作、修改、删除 | 现有文件与执行工具及其权限、Hook |
| 路径解析及读取资格 | 现有 workspace / filesystem 权限所有者，使用当前运行冻结的范围和权限 |
| 标记解析、位置绑定、读取结果准备 | 助手消息发布准备路径 |
| HTML 保存及展示结果提交 | 现有 assistant settlement 与 PostgreSQL blob / visualization 所有者 |
| 展示 | Markdown 渲染器与现有隔离 iframe |
| 截图审阅 | `view_image` 调度现有一次性截图所有者与工具图片链路 |

### 4.2 读取与提交

发布前读取文件，一次读取所得字节就是本次冻结版本。文件后续保存不改变这一版本。多文件展示不承诺跨文件原子快照；每个文件独立读取。保持现有单文件资源预算、非普通文件拒绝、UTF-8 校验、超时和取消管理，不增加任意历史总量上限。

**沿用真实存在的读取边界，不新造批准流程。** 当前 permission presets 的本地读取范围是 `host_local`，READ_ONLY 模式也允许普通只读文件工具；并不存在所有 HTML 都需要额外获取的文件读取 permit。发布准备复用 `WorkspaceTool._resolve_read_path` 对应的冻结 workspace、用户 home 与 Pulsara home 解析及普通文件/OS 访问限制，不误改成 workspace-only，不伪造工具调用、Tool Hook 或确认请求。若读取失败则在标记处展示失败。前端始终只读消息拥有的快照，不另开路径读取接口。

消息、READY/FAILED 展示记录、位置绑定和所需 blob 按现有 settlement 事务一起提交。重复 settlement 不重复产生展示；提交失败或取消不能留下已对用户可见但没有消息所有者的展示。不为准备阶段增加持久任务、恢复队列或临时引用注册表。

### 4.3 失败与历史读取

正文明确引用的文件不存在、被删除、不可读、非 HTML 来源、内容无效或超过现有资源边界时，在对应位置显示简洁错误；不静默删除标记或整张图，也不阻止其余正文和成功图表发布。

历史回看只读取消息拥有的保存内容，并沿用 session/workspace 校验、摘要与大小完整性校验。修改或删除原文件后，旧消息仍可正常展示。历史读取失败时允许重试读取该快照，不能退回原路径读取最新版。

HTML 内的运行错误不倒写已提交的 canonical 状态；本轮不新增运行诊断系统。

### 4.4 Schema 硬切

当前 `assistant_visualizations` 的实时记录要求关联 `source_result_entry_id`（TOOL_RESULT）。新产品中展示来自助手正文，必须删除这一旧要求及相关工具结果外键/字段消费路径，不伪造工具调用满足约束。

复用现有消息所属展示关系与 blob，以及既有 ordinal 作为正文各图集中逐项展平后的序号，不新增位置字段或绑定表。保存最小的来源显示名称，供标题及错误说明使用，替代从旧工具参数反查名称；不需要为历史回看保存可重读的绝对路径，更不新增文档实体或事件流。消息拥有内容，ordinal 只负责正文定位。

同步修改 clean-v0 baseline、DTO、reader、fork/import、展示投影与测试。Fork 后仍展示原快照，不重新读取父会话文件；复制时保留正文与相应 ordinal、快照及失败结果，不留下父消息所有权。开发库按 AGENTS.md 和具体实施授权验证目标后处理，不建旧订阅与新标记双读迁移链。

## 5. `view_image` 支持 HTML 截图

### 5.1 工具形状

继续使用现有来源二选一：

```json
{"path":".pulsara/visualizations/comparison.html"}
```

或已有截图的精确引用：

```json
{"image_ref":"sha256:实际已返回的图片引用"}
```

`path` 增加 `.html` / `.htm` 分支；原 PNG/JPEG/静态 WebP 行为不变，不放宽图片校验。`image_ref` 仍然只引用图片，HTML 内容摘要不能冒充图片引用。不增加 `visualization_ref` 参数，不把任意文本文件自动当成 HTML。

### 5.2 渲染和结果

调用时读取当前 HTML，复用 `VisualizationScreenshotOwner` 的一次性、可终止浏览器进程，得到 PNG 后走现有图片验证、图片预算和模型输入链路。不得把 HTML 源码作为图片结果，也不另建常驻浏览器服务。

源 HTML 使用既有 `MAXIMUM_BLOB_BYTES` 单文件边界；产出的 PNG 使用当前 view_image allowance 的 canonical/logical/wire/token 图片预算，不能把原图片读取的 `maximum_bytes` 直接拿来限制 HTML 源。HTML 读取交给现有 KernelSessionIO / physical IO 所有者，不复制旧 review 分支里裸 `asyncio.to_thread` 的临时读取。截图经 `freeze_local_image` 后以原始 `ViewImageSource(PATH, requested_path)` 参与既有 quote，保留当前工具调用、executor、source 与预算的对应关系。

复用当前截图视口（1200×800）、网络阻断和主体标记裁切规则；没有合法唯一主体时截取页面视口。返回的文字交代这是 HTML 当前版本截图及所用视口/环境，图片照常提供 `image_ref`。沿用当前渲染等待策略，不承诺任意异步脚本或动画已经稳定。

截图不发布可视化、不登记订阅、不锁定以后回复的文件内容。修改后需要重新调用才能审阅新版本；发布仍以消息提交前实际读取的文件为准。截图审阅与发布冻结之间存在这个明确时间差，不宣称截图证明最终版本已验证。

模型无图片能力、文件读取失败、浏览器不可用、渲染超时或图片预算不足时，返回明确的工具结果并保留现有取消/清理语义；不伪造截图成功。取消/超时由截图所有者终止并等待浏览器进程组清理，随后沿 view_image 的物理完成/错误结果路径收尾，不保留“截图失败但订阅成功”的旧语义。失败不禁止模型继续编辑，也不预先取消未来正文标记。

截图只检查一个时刻的画面，不能代替交互测试。

## 6. 宿主环境传递

### 6.1 最小合同

增加一个可选、只读的环境接口。建议名称为 `window.PulsaraVisualization`，提供当前环境快照和订阅/取消订阅方法；字段限于：

- 当前浅色/深色主题及少量语义颜色：背景、正文、次要文字、强调色、边框、柔和背景。
- `visible`：当前画布是否处于可见展示状态。
- `reducedMotion`：静态截图采样请求。2026-10-22 用户变更后，交互展示固定为 `false`，不读取系统动态效果偏好；独立静态截图 worker 为 `true`，用于稳定画面，不是产品设置。

在画布内映射对应 CSS 变量，便于普通 HTML/CSS 使用。接口不包含会话正文、凭据、文件路径读取能力、工具调用能力或任意宿主对象。主题变量应来自现有设计 token，不另建不一致的配色系统。

模型可按环境订阅自行配合停止/恢复动画。首版不复制 dsh 的动画调度器，也不拦截或改写第三方 `requestAnimationFrame`；现成浏览器 API 足以承担作者侧动画。本能力不保证暂停任意脚本，不是 CPU/内存硬隔离。

内嵌图的创作指导默认让 html、body 和最外层布局容器透明，以融入正文；不要求卡片、绘图区或完整页面设计一律透明。主题背景色用于需要独立底色的局部表面，前景、边框等仍使用宿主语义颜色并提供普通浏览器回退，确保深浅主题可读。仅修改后续创作指导，不强制覆盖作者 CSS 或既有冻结 HTML，不重写已安装的 provider 输入前缀。

### 6.2 传递路径与生命周期

复用现有双层隔离 iframe：宿主 → 可信外壳 → 内层 HTML。各层校验发送窗口、消息种类和字段类型，只转发白名单环境数据。保留现有禁止网络和宿主导航的边界；不得通过添加 `allow-same-origin` 来实现环境访问。

环境启动代码应在作者脚本执行前建立，使初次读取有明确值。挂载时安全序列化并冻结初始环境，初始化 API 和 CSS 变量，再运行作者代码；不能把不受转义的 JSON 插入 script。主题、系统动态偏好、页面可见性及画布展示状态变化后只通过消息更新环境，不改变 srcDoc、React key 或重新挂载 iframe。可信外壳保留最新环境，在内层 ready 后重送，避免启动阶段消息丢失；无需 generation、回执账本或全局注册表。`visible` 综合当前视图激活、展开状态、视口可见性与页面前后台状态；卸载时清理观察器和订阅。

HTML 应能在普通浏览器中独立打开：示例与指导中为缺少宿主接口的情况提供普通 CSS/浏览器偏好默认值。不要把导出文件绑定到必须存在的宿主运行时。

### 6.3 截图环境

截图进程也提供同一接口与变量合同，避免使用环境接口的 HTML 在审阅时直接报错。首版使用明确、可复现的默认环境：浅色、可见、减少动态效果；截图结果注明该环境，不冒充用户当前浏览器状态。Playwright context 同时配置 `color_scheme="light"`、`reduced_motion="reduce"`，使 matchMedia、CSS 和接口值一致。前端与截图进程复用同一小型环境 bootstrap/字段合同和默认 token 来源，不分别维护两套实现。

截图只用于审阅初始静态画面，不能证明动画过程正确。已有历史 HTML 的保存字节不因注入环境接口而重写；环境是展示运行条件，不是新的内容版本或持久状态。

## 7. 自适应高度与正文布局

主体识别是一项改善常见图表观感的布局启发式，不保证任意 HTML 的全部绘制像素完整。允许少量阴影、轮廓、祖先边框或 SVG 描边被裁；不建立 paint-bounds 引擎、不继续扩充装饰 CSS 黑名单。明显的正文溢出和交互内容消失仍需处理。

正文展示与 HTML 截图共用一个 DOM 主体选择函数，不修改冻结的 HTML：

1. 有 `data-pulsara-visualization-root` 时以显式标记为准；多个或隐藏标记不尝试自动选择。作者承担显式裁切范围的选择。
2. 无标记时，唯一可见的标准 `<main>` 可自动成为主体。检查正文的布局矩形、外部可见文字和元素；明显溢出或多个可见 main 使用整页。隐藏的其他 main 不计数，允许不承载其他可见内容的祖先容器与 display:contents 容器。
3. 有文字的伪元素（包括 html 上的伪元素）、Shadow DOM、自定义元素等仍保守使用整页；这不是像素完整保证。空文字伪元素、阴影、描边、外置列表符号等装饰绘制不做额外边界推导。

不猜测 body、最大元素或任意单子元素，不新增作者高度参数。不通过 body.scrollHeight 收缩参考视口。

### 7.1 正文限高和高主体

按用户后续要求，正文展示上限提高到 `min(120dvh, 1200px)`，允许长图超过一屏、随正文滚动查看；小主体仍按测量高度收紧。侧栏或下方控件按第 3.3 节布局，额外空间不计入 HTML 参考高度；这是视口展示资源边界，不是内容长度上限。

- 正文中已测量且可裁切的主体低于 46px 时，隐藏放大入口并取消舞台最小高度，按实际主体高度显示。46px 来自顶部 8px＋按钮 30px＋底部 8px 的控件布局空间，不是内容限制。46px 及以上、整页及长页保持现有放大入口；主体动态变化或切换图页后按当前测量重新判断。放大模式始终保留退出按钮，即使切换到矮图。HTML 裁切窗口与参考 iframe 不为控件拉伸。
- 小主体完全位于参考视口内：仅按主体 y/height 裁掉上下留白，外层实际占用对应高度。HTML 展示宽度始终填满正文版心，不按主体 x/width 缩窄，也不横向 translate、缩放或改写作者 CSS；保留 HTML 原有内部边距，正常图与错误卡共享一致的外宽。截图工具的主体截图仍按其独立截图合同处理。
- 主体过高或纵向超出参考视口：主体仍是合法候选，但以固定参考 iframe 的完整原坐标页面展示，由 iframe 原生滚动查看；不再 translate 裁切，也不把 iframe 拉长到主体全文高度。这种情况下可能保留主体上方原有留白。
- 无明确主体、非法尺寸、横向超出参考视口：整页展示。
- 放大模式使用放大视口；返回正文时重新按正文宽度测量。
- 布局消息携带真实 viewport width/height，只接受与当前参考视口相同的测量，不用旧坐标裁切新布局。

**避免反馈环：** iframe 的参考高度不由测得的主体高度反向驱动。只调整外层展示窗口；宽度、视口或放大模式变化时再测量。外层图集不创建滚动容器；图页、舞台和裁切窗口使用 overflow:clip，隐藏的参考尺寸探针不能扩大正文滚动范围（包括失败状态和小图）；不创建能被焦点或 scrollIntoView 滚动的隐藏滚动容器；长页的滚动只发生在 iframe 内的原始文档。三维变换等任意绘制行为仍不做完整性承诺。

### 7.2 常见交互与动画

继续复用 ResizeObserver、MutationObserver 与同一 RAF 合并测量；补充 pointerover/out/down/up、focusin/out、input/change/toggle、scroll，以及 CSS animation/transition 启停/取消事件。初次及每次测量通过浏览器 `document.getAnimations()` 检查 running/pending 动画，不逐帧轮询。

仅对自动识别路径：检测到运行/待启动动画，或交互重测发现原先能完整裁切的小主体已经不再满足裁切条件（包括主体失效、负坐标、横向或纵向越界）时，本次 iframe 挂载锁定为整页模式，不再自动收缩，防止 hover 位置变化导致来回振荡。正常交互且仍合法的小主体继续裁切；显式标记不增加这一锁定。锁定是可丢弃的进程内展示状态，重新挂载会重建判断，切图保留的 iframe 则保留状态。

退回整页可能让内容位置一次性变化；不主动滚动宿主会话、不添加鼠标锚定协议。任意 JS/WAAPI 若在后台改变绘制位置却不触发这些观察或事件，仍可能迟至下一次测量才被发现；不能宣称覆盖所有脚本动画。截图按默认浅色、减少动态效果环境审阅当前静态状态，与交互中的浏览器展示不保证同一时刻。

折叠、离屏、历史长消息中的 iframe 可以延迟挂载/按需卸载；不要把现有图集“驻留三个页面”的缓存策略误用为最多只能有三个正文图表。无总图表上限，也不承诺任意脚本状态跨卸载保留。

## 8. 流式展示和正文能力

生成中的不完整围栏保持普通生成态；完整标记可显示轻量占位，但前端不能据此提前读取工作文件或执行 HTML。只有收到已经提交、绑定到该消息的展示记录，才加载快照。

Markdown 渲染器直接把已识别、已绑定的标记渲染成组件，包括 FAILED 绑定的错误展示，不做 DOM 扫描、隐藏代码块再插入 Portal。没有对应 canonical 绑定时不能临时按路径加载。等待态仅用于仍在生成或尚未完成提交投影的消息；已完成且展示投影完整的消息缺少绑定时，保留普通代码或显示明确不可展示状态，不能永久等待。带工具调用的消息仍按 §3.2 不登记、不排队。

保持正文其余部分的 Markdown、复制、选区和批注源映射。复制回复应能保留原始路径标记；画布内部交互不被当作助手正文选区。实现必须验证多个文本块、相邻标记、同路径重复和示例代码的映射。

正文与行内 Markdown 使用 `remark-cjk-friendly/parseOnly` 和 `remark-cjk-friendly-gfm-strikethrough/parseOnly` 识别 CJK 标点附近的强调、加粗及删除线。批注源映射使用对应的 micromark 扩展，保持同一套解析规则。依赖负责语法识别，Pulsara 负责展示和规范原文位置映射；不改写保存的正文，不插入空格，不新增模型提示词约束。代码、公式、显式转义和可视化围栏仍按各自语法处理。

正文路径标记原样保留在 canonical 助手正文、provider 重放和原始复制中，前端仅替换其视觉呈现。解析不能删改正文或改变原生 provider replay。展示位置、主题与环境变化不得改写已经安装的 provider SYSTEM/tools 或重写历史 messages。工具目录、说明及下节 provider 可视化 metadata 注入的移除，通过正常 cold epoch 的新输入构建生效；不重编译、删改或修补已经安装的前缀，不保留旧协议兼容支路，不用可视化改造引入新的 epoch 重建例外。

## 10. 实施顺序与验收

### 10.1 实施顺序

1. 定义标记语法及共享样例，复用既有展示正文投影、文件读取边界和 ordinal，完成发布快照与来源 schema 硬切。
2. 接入 Markdown 内嵌展示，复用隔离和放大组件，完成历史、fork、失败态及流式占位。
3. 将 HTML 截图接入 `view_image`，删除旧订阅工具及其专用支路。
4. 实现环境传递、自适应高度，并同步截图环境。
5. 更新指引和测试，完成真实 provider 与浏览器验证，检查无旧兼容路径残留。

### 10.2 必须验证的行为

- 同一标记多路径、多个独立标记、单图隐藏导航、多图缩略图/键盘切换、驻留页状态与可见性、全空组和组内失败、中文/空格路径、合法绝对/相对路径；无权限路径、URL、目录、错误后缀和无效 UTF-8。
- 用户消息、引用、示例围栏、未闭合围栏和附加 info string 不触发读取；闭合但路径无效的标记保留 FAILED ordinal；前后端解析相同正文得到一致标记位置。
- 共享语法样例覆盖 LF/CRLF、info string 大小写、围栏缩进（含三空格）、反引号与波浪线围栏及闭合规则；数学块、HTML 块内部的伪标记按实际 Markdown 展示语义处理，不能额外计数。后端解析需与前端现有 Markdown 扩展一致。
- 修改文件后再次发布得到新版，原消息及其 fork 仍展示旧版；删除原文件不破坏旧展示。
- 发布前删除文件显示对应失败；单图失败不影响其他图；重试 settlement 不重复，取消不留下孤立可见展示。
- 多标记、多文本块（含空块和跨块围栏）、重复路径、正文复制与批注选区映射正确；不把失败标记后面的图错绑到前面。
- 流式阶段不读文件、不执行 HTML；已发布后在准确正文位置显示，不在末尾重复追加。
- FAILED 绑定在原位置显示失败；已完成且投影完整但缺少绑定的标记不永久等待；带工具调用的中间消息不产生延后展示请求。
- `view_image` 的原图片与 image_ref 流程不回归；HTML 截图图片可再次用 image_ref 查看；审阅之后编辑不会伪装成已验证最终版本。
- 截图无模型图片能力、浏览器缺失、超时、取消和预算失败可解释且进程正常收尾。
- 主题切换、浅/深色、窄屏、离屏/收起/后台可见性、减少动态效果；初始作者脚本能读到环境，后续环境更新不重载 iframe、不重置已有控件；普通浏览器独立打开有合理默认显示。
- 小主体减少外层留白；整页、过大/多个/隐藏主体和放大保持可读；viewport 高度依赖不产生反复缩放或无限测量；排队中的旧视口测量不能误作用于新视口。
- 双层 iframe 隔离、网络阻断、宿主导航阻断和消息来源校验不回归。
- 不增加订阅兼容入口、持久任务、事件、通用状态注册表或任意历史总量上限。

真实 dogfood 使用保存配置并只读加载凭据：通过新会话让模型创作至少一个交互图和一个完整页面，实际调用 HTML 截图工具，在一条回复的不同段落嵌入多图；修改其中一份后再次发布，浏览器核对旧/新消息、主题、窄屏与高度。捕获实际工具输入、输出及必要 provider 输入作为证据，仅去除真实密钥。报告功能验证和未覆盖边界，不用截图替代交互测试。
