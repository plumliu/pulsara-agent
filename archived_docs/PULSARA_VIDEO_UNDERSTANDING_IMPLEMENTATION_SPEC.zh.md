# Pulsara 视频理解与音频转写实现规格

当前合同（2026-11-05）：六参数画面读取保留；detail 显式指定不超过两秒的 from/to，在有效视频交集内取首、中、尾三个目标，同源帧合并，页内精确图片共享，选择策略为 `frames-v3`。按问题选择 overview/detail/motion 的规则见[修订规范](PULSARA_VIDEO_DETAIL_AND_REVIEW_STRATEGY_REVISION_SPEC.zh.md)。

会话历史不按累计条目数或图片编码累计字节触发压缩；canonical、编译工作集、epoch 及回放/副本的固定历史字节配额已取消。单消息/媒体 worker、实际请求传输、token仍各由原 owner 控制，见[历史累计字节与条目数合同](PULSARA_TOOL_OUTPUT_AND_PAGINATION_REFACTOR_PLAN.zh.md#222-历史累计字节与条目数)。

文字读取采用[工具输出与分页合同](PULSARA_TOOL_OUTPUT_AND_PAGINATION_REFACTOR_PLAN.zh.md)。每次新增识别的有效范围累计最多 180 秒；已有原文按完整输出预算分页。

## 1. 目标与范围

让支持图片输入的模型，以较少的参数和可回查的证据理解本地视频：先看概览，再按问题读取清晰画面、连续动作或文字；纯音频共用文字读取、播放器和时间段批注。模型负责判断还需要什么证据；媒体工具负责解码、采样、排布和识别，不在内部另起一个推理代理。Pulsara 不将原始音视频文件作为多模态输入直接转发给 LLM provider；模型收到采样图片、时间索引和字幕／语音转写文字，云端 ASR 仅接收所需音频。

视频理解阶段新增且只新增三个模型工具：

| 工具 | 顶层参数数 | 必填参数 | 产物 |
| --- | ---: | --- | --- |
| `read_video_frames` | 6 | `target` | 视频取样画面、时间索引，不表示完整观看区间内每一帧 |
| `read_transcript` | 4 | `target` | 按时间读取视频或纯音频中的已有文字字幕或云端语音转写；完整 next 续读 |
| `annotate_media` | 4 | 全部 | 对原视频或纯音频的时间段追加一条批注 |

三个工具仅供 ROOT 直接调用，SUBAGENT 与 Code Mode 均不可见、不可调用，包括 ROOT 发起的 Code Mode。画面、原文与批注结果直接进入当前会话的工具交付路径；媒体处理及 ASR 的内部并行由 runtime 负责。

两个读取工具通常只需填写 target 与本次所需范围；批注明确提供媒体、范围和正文。元数据探测是工具内部步骤，不增加独立查询工具、查询 action 或元数据 mode。视频只传 target 即使用默认 overview，取得全片稀疏画面，无需填写其他参数。纯音频直接调用 read_transcript，不要求先调用取画面工具。`overview` 使用页内保持真实时间顺序的可变格子 DP 拼图；跨页沿覆盖优先计划续读；`detail`、`motion` 使用各自的取证策略。

观察流程借鉴剪辑师审看素材：浏览概览 → 定位候选片段 → 圈定范围回看 → 放大或前后对照 → 依据证据回答或追加时间段批注。模型可以从任一步开始，按任务选择需要的证据。三个工具的顶层参数分别为 6/4/4 个，不增加回看、比较、剪辑或批注 CRUD 工具。

首版输入为现有 `PATH` Target 指向的本地视频或纯音频；read_video_frames 只接受有可用视频画面的文件，另外两个工具共用于音视频。网页解析、登录和媒体下载继续由已有文件、浏览器或终端能力处理；媒体工具不接受 URL、Cookie、任意请求头或下载脚本。用户附件与下载产物沿用既有本地文件引用。会话页侧边栏内置共用播放器：原生 video/audio 元素负责解码播放，Pulsara 自定义时间轴展示可拖动预览位置、模型实际读取范围和时间段批注。预览与模型阅读独立，改变模型阅读位置使用既有 steer。首版不增加音视频上传消息类型、原生音视频 provider 入参或跨媒体语义索引，也不承诺与用户同步播放、陪伴发言或定时配音。

普通预览与模型分析共用同一媒体标签页；没有相应数据时隐藏模型范围、批注轨道与列表。同一规范媒体路径与文件修改时间只展示 0–1 个当前工作的模型阅读范围：实际读取开始时覆盖，工具返回后保留，与 TODO 一起在 ROOT 工作回到 idle 或关闭时清空。该状态可丢弃且不持久化，不表示工具仍在执行或模型理解进度。批注按规范路径与文件修改时间归属，从已有会话工具记录按需重建，不新增媒体/批注数据库对象或跨重启恢复任务，见第 11 节。

`pulsara-viz` 渲染端支持本地音视频路径，以原生控件播放，“扩大”通往同一侧栏标签。音视频仅保存路径引用，视频封面按需取帧，音频使用静态图标与文件名；不向系统提示词或 bundled Skill 增加专门的音频发布教学。发布、播放与扩大均不触发模型读取或 ASR，也不将原始音视频送入 LLM，见第 11.6 节。

macOS、Ubuntu、WSL2 的画面处理在本地完成。`read_transcript` 优先读取可用的内嵌文字字幕；没有可用字幕或字幕解码失败时，才进入转写兜底路径。ASR 统一走用户配置的云端服务，只由该工具按需同步触发：先复用跨段转写缓存，再内部并行处理请求范围内的未识别音频，不自动预取下一段或转写全片。字幕条目之间的空白不触发 ASR。画面中的硬字幕、UI 和幻灯片文字由主模型通过清晰帧或 detail/crop 阅读，不提供独立 OCR 或屏幕文字索引。不提供本地 ASR 引擎、权重下载、设备选择或离线 ASR 回退；原有文字字幕、画面和已完成缓存的读取不依赖云端连接。

首版不做纯音乐理解、乐器/风格识别、音乐描述或扒谱，不增加相关模型、服务或工具。音频播放不等于模型听到音频；语音转写不证明模型理解音乐、音效或语气。只在本次实际提取音频时附带轻量静音检测，区分近乎静音与存在声音但未获转写文字，不把声音分类为音乐或噪声，见第 7.3 节。

## 2. 生产入口与归属

- `capability/builtin_catalog.py` 提供工具定义和角色筛选。直接工具面、物理绑定和执行准入共同约束调用入口。
- 工作区读权限核对后，`media/source.py` 绑定文件描述符和版本，PyAV 负责容器、codec、seek 与展示时间。视频取样由 `media/frames.py` 组织，Pillow 合成画面。图片进入既有校验、资源 quote、canonical 图片和 provider lowering 路径。
- `media/transcript.py` 选择字幕或识别缓存、计算缺口并组织完整源页。`media/asr.py` 使用 OpenAI SDK、凭据绑定 HTTP 客户端和受限 multipart 请求。用户通过独立 ASR 设置配置一个完整 endpoint、模型 ID 和 API key。
- Core 管理 PostgreSQL 中唯一的 `asr_cache` 成功块表。缓存记录服务来源和真实范围。工具正文与图片、批注的冻结参数和成功结果分别由既有会话记录保存。
- `current_work_runtime.py` 承载当前 ROOT 工作的 TODO 和媒体范围。Host 的 live-control 快照及其失效通知通往 renderer。工作回到 idle 或关闭时清理范围。
- `desktop_app/file_preview.py` 与 `file_preview_http.py` 负责描述符绑定、版本校验及 Range。文件浏览、普通链接、工具展示与围栏扩大共用预览标签。音频和视频共用播放器与时间轴。历史批注从可访问域内的 canonical 结果和同次调用参数按需读取。
- HTML 保存布局与代码快照，本地媒体经受限目录引用读取。独立音视频发布项只保存规范路径引用。浏览器负责播放与解码，预览生命周期负责暂停、清源和撤销引用。

## 3. 统一输入规则

`target` 只接受 `{"kind":"PATH","path":"…"}`，字段关闭，沿用文件读取的展开、解析和访问权限规则。文件句柄与源文件事实在操作开始时捕获，缓存命中仍必须重新经过读取入口。

时间均为从原媒体展示起点开始的秒数，使用半开区间 `[from,to)`，不使用帧号代替时间：

- 两个读取工具的 `from` 默认 `0`，`to` 默认已知媒体结尾；annotate_media 的两端均必填。均须为有限数字，拒绝 NaN、Infinity、负数、布尔值及数字字符串。
- 有效区间满足 `0 <= from < to`，已知时长时还须 `to <= duration`；显式越界报 `INVALID_RANGE`，不悄悄改成另一段。各工具内部复用元数据探测来解析默认范围，不要求模型先查询。未知时长时读取须给有限 `to` 并如实返回覆盖；批注无法确认上界时返回 `MEDIA_DURATION_UNKNOWN`，不为添加批注扫描全片。
- 读取省略 to 而无法确定结尾时，返回明确范围错误、时长未知及需要填写 to 的说明，不附整份探测报告，不新增预检 action，也不先扫描全片来猜结尾。
- 以实际 PTS/time_base 对齐视频、音频、字幕，处理非零 stream start、VFR、旋转及像素宽高比；不能用 `frame_index / nominal_fps` 推算所有时刻。
- 三个工具的时间均使用同一个原媒体时间轴；局部读取、裁剪、拼图、字幕定位或转写分块不会将时间重新从零计起。纯音频以其实际音频时间映射建立同一 from/to 语义，不虚构视频轨或帧。视频 seek 可以解码更早的关键帧，但只交付展示区间与请求范围相交的画面；边界位于一帧展示期间时，保留该帧真实时刻，并标明展示区间与请求范围的交集，不将 PTS 改写为请求起点。
- 多视频轨优先默认的非封面视频轨，再选第一条可解码视频轨；实际选择保留在内部源事实，影响结果解释时才附必要选择说明，不常规输出轨道编号或列表。首版不增加模型选轨参数。
- 多音轨选择源文件标记的默认音轨，否则选择第一条可解码音轨；有音频但无法解码时报告解码错误，不伪装成没有音轨。音轨选择由媒体源决定，不因 ASR provider、模型或识别参数变化而改变；不增加模型选轨参数。封面图片不使纯音频变成可供 read_video_frames 阅读的视频。
- 操作中若源文件被替换或修改，返回 `MEDIA_SOURCE_CHANGED`，不得把不同文件版本的帧或文字拼成一个成功结果。此检查保障同次读取和缓存正确性；批注归属只比较规范路径与文件修改时间，不增加 inode、设备号或内容哈希。

所有工具拒绝未知参数，不增加 `video_id`、私有 cell handle 或兼容 DSH 参数的别名。

## 4. 三个工具的接口

本节固定模型参数与产品语义；结果预算、源续读和已保存正文回读遵循统一输出契约。工具面只在已批准的 cold epoch 或明确采用的 compaction successor 安装；不能改写既有 epoch 的 SYSTEM、tools 或已接受页面。

### 4.1 `read_video_frames`

| 参数 | 类型 | 默认/要求 |
| --- | --- | --- |
| `target` | PATH Target | 必填 |
| `from` | number | overview/motion 默认 `0`；detail 必须显式提供 |
| `to` | number | overview/motion 默认视频结尾、未知时长必填；detail 必须显式提供，且 `0 < to-from <= 2` 秒 |
| `mode` | `overview` / `detail` / `motion` | `overview` |
| `crop` | 四项 number 数组 | 省略为完整画面 |
| `continuation` | object | 首次省略；续读直接复制 runtime 返回的完整 next |

只接受上述六个顶层字段。continuation 是 runtime 生成并验证的非空位置对象，不接受 null、空对象、图片页码或手算位置。它绑定规范目标、原 from/to/mode/crop、当前唯一选择策略、源版本与下一遍历位置；字段按位置类型关闭。源版本复用 MediaSource 的 dev/ino/size/mtime/ctime 比较事实，仅用于续读检查，不改变批注身份或 ASR 缓存键，不增加 hash、HMAC、分页实体 ID、注册表或持久计划。

`crop=[left,top,right,bottom]` 相对于旋转和像素宽高比校正后的完整展示画面，满足 `0 <= left < right <= 1`、`0 <= top < bottom <= 1`。先应用展示变换，再裁剪；同一矩形用于本次所有帧，不承诺自动跟踪物体。时间不因裁剪改变。

| mode | 产品语义 | 默认交付 |
| --- | --- | --- |
| `overview` | 判断场景、结构与大致变化 | 覆盖请求范围的稀疏分镜，按第 6 节 DP 拼图 |
| `detail` | 看清文字、人物、物体或局部状态 | 不超过两秒范围的首、中、尾清晰原帧；同源帧只交付一次 |
| `motion` | 回看短片段，判断顺序、状态变化与重复动作 | 覆盖实际处理区间的密集有序采样帧，优先时间密度；遵循第 5.2 节回看规则 |

三个 mode 使用相同的 from/to，区别是图片预算的取舍：overview 优先代表性与范围覆盖，detail 优先空间清晰度，motion 优先时间密度与过程。片段较短不自动切换 mode；很短且静止的片段可以返回相同源帧，不为区分模式复制图片或强行制造差异，也不要求模型对每段调用三遍。

例如五秒录屏中的菜单打开后关闭：overview 用于定位菜单所在片段，motion 用于检查打开、停留和关闭的过程；读取菜单文字时，在已定位的打开时刻附近选择不超过两秒的 detail/crop。

对快剪、持续运动或局部频繁变化，三种 mode 按各自质量策略与物理准入分别处理；detail 不复用变化分析来增加交付：

- overview 按第 6.2 节建立覆盖全范围的固定稀疏计划，相邻观测组只表达已采画面的相似关系；页内统一档位进入 DP，不从稀疏观测推断切点密度或章节。减少冗余不能变成“已看完全部动作”。
- detail 按第 6.2.4 节解析首、中、尾真实源帧，保持同一 crop 与清晰图片目标。选择不使用变化检测或邻时刻择锐。
- motion 在固定物理分析配置决定的有界窗口内建立稳定有序观察序列，保留骨架、已观察快速变化与短暂往返；页预算只切分该序列。先交付完当前窗口，再沿精确下一源 PTS 进入后续窗口，不静默退成 overview。只标记连续扫描中实际观察的切点。

detail 超过两秒或缺少显式 from/to 时，返回 INVALID_RANGE 与局部读取/模式选择提醒，不探测或解码、不自动截断或拆段。长范围 motion 继续沿原窗口和 next 交付。两秒约束仅用于 detail 单次局部核对，不限制视频时长、其他 mode 或总调用数。

纯音频不使用 overview，read_video_frames 对无可用视频画面的源返回 NO_VIDEO_TRACK，不输出伪造封面帧或元数据专用成功。

overview/detail/motion 均不附全片基础元信息块，只返回采样画面、源事实、本次范围、实际采样时间、必要画面尺寸/crop、完成情况、续读和影响解释的限制。元信息查询可通过终端使用 FFmpeg/ffprobe。容器属性、编码器、完整轨道列表、原始帧率、常规 VFR 字段与 ASR 配置均留内部，不默认给模型；若某事实确实影响本次观察，只附具体限制，不展开整份探测报告。内部探测不为元信息解码全片或访问云服务，帧时间仍按真实 PTS 处理。

规则：

- 未给时间范围的 overview 是全片的稀疏概览，不静默改成只看前几分钟；也不声称看过每个镜头。
- 完整 next 使用同一工具，保留原 target/from/to/mode/crop。overview 重建固定代表计划；detail 重建同一个短范围的有限首中尾计划，以 next_observation 续交；motion 先续交窗口剩余观察，再进入后续窗口。页预算只改变交付前缀。源、权限、策略或位置失效明确失败。
- detail 的一次完整计划最多三个不同源观察，预算足够时一次交付；不足时按原图文预算分页，next 始终留在同一个短范围。
- 每张实际图片有第 5.1 节定义的紧凑时间索引。图片内烧可读编号，精确时间和采样间隔放在旁边的文字索引中；代表区间不是已完整观察的区间。
- 若已有选中字幕/转写缓存，可附与已交付画面对应的少量原文。所有 mode 均不启动 ASR 或文字预取；overview 也不预热一小段语音。不增加文字起点参数或首次准备 action，不生成未经核对的机器摘要。
- read_video_frames 的成功结果直接包含 `LLMImagePart`；模型不必再调用 `view_image` 才能看到本次画面。没有图片输入能力时，在解码前返回 `MODEL_IMAGE_INPUT_UNSUPPORTED`。
- 不把音频响度、切点密度或单帧状态当成音乐理解、精确动作计数或整段事件的证明。
- 模型通过同一工具调整 `from/to` 回看、缩小范围提高时间密度，或通过 `crop` 放大空间细节。工具不自动扩张显式范围，不改写原视频，也不自动生成片段含义、人物身份或事件结论。
- 三种 mode 共用第 6 节的“固定质量策略与物理准备配置 → 稳定观察序列 → 原片 render → 联合装页”路径。detail 不做变化检测或邻时刻择锐；overview 的像素分组与 motion 的连续观察不调用 LLM 或隐式启动 ASR，内部策略不增加模型参数。

### 4.2 `read_transcript`

| 参数 | 类型 | 默认/要求 |
| --- | --- | --- |
| `target` | PATH Target | 必填 |
| `from` | number | overview/motion 默认 `0`；detail 必须显式提供 |
| `to` | number | 希望读取的音视频媒体终点，默认媒体结尾；未知时长时必填 |
| `continuation` | object | 首次省略；续读直接复制 runtime 返回的完整 next，不手算位置 |

四个顶层字段之外均拒绝；不接受 query、offset、source、模型、块长或并发参数，不保留旧参数别名。首版不提供原文关键词搜索或隐式全片转写搜索。需要检索已取得的文字时，可先用 write_file(source=SESSION_ENTRY) 保存已有结果，再使用现有文件搜索；保存只涉及该次结果，不能据此宣称搜索了尚未取得的全片文字。

本工具接受本地视频和纯音频，自行探测所需音轨、字幕、时长与源事实；模型结果只给本次范围、文字来源、实际完成情况和必要错误/续读。无文字时可附已有的音轨或静音检测事实，但不附全片基础元信息块。不要求先 read_video_frames，也不因模型不支持图片而不可用。

来源由工具自动选择，固定优先读取可解码的内嵌文字字幕。字幕先遵循已有用户语言偏好（可取得时），否则按默认轨标记、第一条可解码轨选取；本次选择回传，不为本功能新增语言配置。只有没有可用文字字幕或字幕解码失败时，才进入转写兜底：先读同媒体版本与访问域的已完成转写缓存，再由云端 ASR 补齐请求范围内尚未成功识别的音频。位图字幕不属于可读文字字幕，不能冒充字幕原文；格式或解码问题保留必要说明。

纯音频沿用同一来源选择与时间范围规则，不要求有画面或先调用 overview；通常直接复用语音转写缓存或对缺口执行 ASR。元数据标签中的标题、歌词字符串和封面不冒充带时间码字幕，首版不增加外部歌词/字幕查找。文件没有音轨但有可用文字字幕时仍正常读取字幕；没有音轨且没有可用文字字幕时，返回 NO_AUDIO_TRACK，并简短说明“此媒体没有音轨，也没有可用文字字幕；无需再次调用本工具”。该情况不发 ASR、不要求配置服务，不提供反复重试的 next。字幕解码失败的实际诊断仍保留。

字幕轨可用时按原文读取；条目间空白或请求范围没有字幕条目均不触发 ASR，也不补入转写缓存中的台词。成功读完范围字幕但无条目是正常空结果，不证明实际没有讲话。ASR 缺口只指转写兜底路径中尚未成功处理的音频，不指字幕条目未覆盖的时间。返回项的 source 标明 subtitle 或 asr；字幕不保证与实际讲话一致，读取字幕不能表述为已核对原声，不将不同来源静默拼成无来源的“真实台词”。

一次调用同步完成本次可交付窗口，不返回要求轮询的任务 ID。首次和续读使用同一执行路径；云服务若采用异步协议，由薄适配器在同一次工具生命周期内等待并遵循取消/处理期限。服务未配置、认证失败或识别失败分别报告，不以空原文冒充完成；字幕或完整缓存命中不依赖服务配置且不联网。

**新增识别与文字交付使用两种边界：**

- 每次 read_transcript 调用最多新增 **180 秒有效音频范围** 的 ASR，按请求范围内实际缺口的时长累计，不含已完成缓存。180 秒用于约束单次等待和收费工作量，是本次新增处理上限，不是固定块长、返回文字的时间跨度或媒体总长度上限；不向模型增加参数。
- 已有字幕与已完成缓存没有 180 秒读取限制。按照本调用输出 allowance、真实正文和完整 next 装页；一页可跨越远长于 180 秒的源时间。仍遵守现有解码、内存、取消和 watchdog 边界，不为凑完整页整体载入全片。
- 先交付当前位置已有的文字。已有文字足以形成一页时直接返回，不额外发 ASR；尚未交付完当前已处理窗口时先续交剩余原文，不跳过去启动下一批识别。读到缺口且本页仍可接纳内容时，才按剩余新增额度计划本次识别。
- 多个缺口按时间推进、累计不超过 180 秒；内部块可按已验证服务限制并行，不能给每块、每 worker 或同次调用的循环分别重置 180 秒。成功空块同样占用本次处理量并计入已完成覆盖，不能因没有文字而不断识别后续音频。
- 180 秒上限可以因输出、服务或物理边界提前停止；不是必须用满的额度。必要边界上下文不增加有效覆盖，仍按实际上传量/时长计费，并受服务协议与第 7.2 节限制；不把上下文当免费或另一个有效识别额度。

输出与续读语义：

- 每条保留原文、绝对时间及实际来源；文字时间可用于同一媒体的播放器和 annotate_media，视频还可用 read_video_frames 定位。命中文字不能证明相应画面事件发生，服务置信度不等于答案正确率。
- 原文按时间、稳定来源位置输出。continuation 定位下一条原文或条目内部的未交付字符，并保留必要的处理进度和源校验事实；不能只靠一个浮点秒数跳过同时间条目、跨界句或超长 segment。
- continuation 是 runtime 生成并验证的非空位置对象，携带必要媒体版本与选定文字来源，字段按位置类型关闭；模型直接复制完整 next。完整 next 保留规范 target、原请求 from/to 和续读位置，省略 to 的首调用在已知时长后将实际终点写入 next，避免续读改变目标范围。它不授予读取权限、不创建新 ID、游标实体或持久分页会话。
- 每次续读重新校验文件、权限与位置。源版本变化按 MEDIA_SOURCE_CHANGED 处理；文字来源变化或所需定位数据被清理时明确续读失效，不悄悄切轨、从头重放或重识别已交付文字。用户可重新指定 from/to 开始一次当前源读取。ASR 模型/配置变化不使已有块失效，也不单独使 continuation 失效。
- 超长条目按现有文本 packer 的行/行内字符能力分片，保留该条目的真实时间和分片位置；不按字符比例伪造更细时间，不跳过剩余原文。分句或排版改变不能重排已交付前缀。
- 正常源页完整交付，仅保存本页原结果；继续源数据使用 next，回读已保存正文使用 read_file(SESSION_ENTRY)，保存原字节使用 write_file(source=SESSION_ENTRY)。不再套一层正文省略，也不要求模型用 read_file 获取下一段字幕，详见第 5 节。
- 无识别能力、识别失败、没有音轨、范围近乎静音和检测到声音但未获转写文字分别报告。声音事实遵循第 7.3 节；空文字不证明静音、没有讲话或全片没有文字。

### 4.3 `annotate_media`

| 参数 | 类型 | 默认/要求 |
| --- | --- | --- |
| `target` | PATH Target | 必填，明确批注所属视频或纯音频 |
| `from` | number | 必填，原媒体开始秒数 |
| `to` | number | 必填，原媒体结束秒数 |
| `text` | string | 必填，非空白的纯文本正文 |

模型在审看视频或音频期间，通过本工具把自己对相关片段的观察和解读写成给用户看的话。一次调用追加一条 `[from,to)` 时间段批注；成功提交后用户即可在媒体时间线上阅读、点击回看片段，模型可以继续审看。范围可跨多次读取或整个章节，不必与某个 ASR 块或最近一次工具范围一致。视频和纯音频使用同一工具、参数及提交路径，不要求有视频轨。工具自行验证媒体读取权限、规范路径、源事实和时间边界，不依赖活动播放器，也不要求先调用读取工具；校验不证明批注结论正确或范围已完整观察。

工具不生成洞察，不移动播放器或模型阅读位置，不发起 ASR、抽帧、导出或源媒体写入。正文由模型明确提供；不要求标题、颜色、标签、action、批注 ID 或修改/删除参数。不在工具内部另调模型，不根据最近一次调用猜媒体或时间范围。

成功结果的模型可见正文只确认添加状态，不重复正文、时间范围或全片元信息。实际解析的规范路径与文件修改时间随同一 canonical 结果保存，正文和范围复用同次冻结参数；侧栏据此重建批注。修改时间沿用文件的 st_mtime_ns，以十进制字符串传递以避免 JavaScript 精度丢失，不使用批注创建时间。会话只保留为来源与访问边界，不参与媒体身份；不保存 inode、设备号或内容哈希。仅生成参数、执行失败或结果未提交均不显示为已提交批注。不另建可编辑批注正文、独立批注 ID、提交事件或确认凭证；侧栏复用来源结果的既有身份定位。

首版已提交批注只追加；更正通过后续批注或会话补充表达，不回写旧记录、不自动维护替代链。用户尚未发送的草稿可改删，发送给模型仍走既有输入/steer，不直接改动已提交批注。查看、定位和分页属于侧栏对既有记录的读取，不新增模型查询工具。正文受现有内容准入约束，不新设批注总数或任务寿命上限。

## 5. 返回、覆盖情况与续读

模型可见的读取结果只包含紧凑证据，批注结果只确认添加状态；读取结果的源事实与批注结果的规范路径与文件修改时间按各自 owner 保留。不默认附带调参手册、各策略价格比较或内部诊断日志。

两个读取工具的共同内容为原 target、请求范围、本次实际处理范围、证据覆盖方式及必要限制，不设每次都附完整元数据的公共块。缓存是否命中放内部诊断。各调用的元信息输出遵循下表；annotate_media 不产生 processed_range、采样覆盖或 next，也不把批注范围标成已读。

| 调用 | 模型可见的元信息 |
| --- | --- |
| read_video_frames / overview | 一行时长、展示尺寸、有无音轨/文字字幕；附图片与时间索引 |
| read_video_frames / detail、motion | 本次范围、采样时间、必要尺寸/crop 和观察限制 |
| read_transcript | 本次范围、文字来源、已处理与已交付位置、完成情况及必要错误/续读；附原文，无文字时可附已知音轨/范围声音事实 |
| annotate_media | 添加状态 |

基础元信息不增加输入参数、查询 action 或新 mode；重复 overview 的一行输出可接受，不建设首次展示标记、跨轮“已见”记录或去重回执。完整流/编码/帧率报告和客户端配置不进入默认模型结果，真实采样时间、来源与覆盖限制仍必须保留。

覆盖必须分开说明：

| 内容 | 表达方式 |
| --- | --- |
| overview 采样跨越整个请求范围 | sampling 为 sparse，给出实际采样时刻；不写“每个镜头均已观察” |
| 图文计划只交付一部分 | 分开说明已分析范围、实际交付样本和计划完成情况；完整 next 定位未交付观察，不能用样本时间包络冒充连续已看范围 |
| motion 仅完成当前分析窗口 | 保留窗口内尚未交付位置；交付完后才沿精确下一源 PTS 推进 |
| ASR 完成块非连续或部分失败 | 交付已完成的连续前缀，列明剩余缺口与错误；后部成功块可缓存，不跨缺口宣称完整 |
| 已处理音频的文字尚未交付完 | 保留已处理范围和当前原文位置；next 先交付该窗口剩余文字，不重复 ASR |
| 新增 ASR 已达到本次 180 秒额度 | 明确实际已处理范围；未处理部分通过 next 继续，不冒充请求范围已全部处理 |

两个读取工具只返回一个 next，为 null 或具有 tool/arguments 两个字段的完整调用对象；tool 为原工具名，arguments 为下一次完整参数。read_video_frames 用第 4.1 节的 continuation 定位稳定图文计划；read_transcript 用第 4.2 节的 continuation 同时承载文字位置和必要处理进度。模型只复制 next，不另算页码或位置。next 为 null 且正常完成时才表示本次源计划已处理并交付完；overview 的完成只指有限稀疏地图，detail 的完成只指有效范围内全部选定采样目标已交付，不表示全部镜头、动作或文字均已观察。错误或资源边界不能仅凭 null 被解读为完成。

**完整源页沿统一输出合同交付。** 使用现有 ToolResultPageBudget.fits，对正文、控制事实、真实 call ID、完整 next、外层转义及 provider allowance 联合装页；复用文本 packer，不另造按字符数猜 token 的分页器。普通字幕/转写页设置 page_complete=True，本页正文完整进入 native 交付，不被公共展示层再次截成头尾或裸 read 引用。最小带位置的文本分片与控制事实仍放不下时，返回既有 typed resource boundary，不跳项或返回原地 next；可确定无法交付最小页面时不先发起收费 ASR。

| 要做的事 | 使用路径 | 读取范围 |
| --- | --- | --- |
| 继续字幕/转写源数据 | 复制 read_transcript 的 next | 尚未交付文字，必要时按本次 180 秒额度识别新缺口 |
| 回读某次已保存的结果 | read_file，target 为原 SESSION_ENTRY | 仅该次已接受的页面正文，不触发 ASR 或获取下一段源文字 |
| 保存某次已产生的结果 | write_file(source=原 SESSION_ENTRY) | 复制该页原正文；不会导出尚未产生的全片转写 |

原结果保存到现有 canonical 正文 owner；ASR 缓存仍保存实际成功块，范围可大于本页交付文字。两者职责独立，本页完整不表示整个请求或整部媒体完整，不以 read_file 替代正常源 next。

文字的 processed_range 表示已成功处理音频/读取字幕的范围，不用首末句跨度代替。已交付位置可停在其中一个条目/字符，不能因已识别到 180 秒就把未交付文字标成模型已读，也不因条目整体时间跨度而声称分片有更细时间。成功处理而无原文时仍能沿真实处理时间前进；失败、未运行和取消不计入完成。仅后部成功而起点失败时报告失败/缺口，不以无进展 next 掩盖错误。

例如模型只传一小时媒体的 target：无字幕且无缓存时，本次最多处理 [0,180)；文字一页放不下则 next 先继续该窗口原文，未交付完前不识别下一批；该窗口交付完后再推进。已有完整一小时字幕或缓存时，直接按输出预算分页，不额外切成固定三分钟页面。用户停止复制 next 后不遗留全片识别任务。

跨调用的读取是对当前源的观察，不建立持久分页会话；重复 next 不消费游标，不承诺源或有效预算变化后的精确旧页重放。顺序使用各页实际返回的新 next 时，静态源和可用定位数据下不得漏字、重复交付或原地循环；没有任何可交付文字或真实处理进展时返回明确边界/错误，不伪造推进。不设置总页数、总调用数或媒体寿命上限。

### 5.1 时间索引与画面位置

索引在当前页内按原视频真实时间排序，并明确指向本页实际交付的图片位置。detail 的多个观察可映射同一张精确相同的图片，不能要求观察数等于图片数。overview 的跨页遍历为覆盖优先，不承诺跨页时间递增。模型可见的最小内容如下；共同值只在结果级输出一次，不逐格重复源路径、crop 或采样说明。

| 内容 | 契约 |
| --- | --- |
| 请求与分析范围 | `requested_range` 保留原解析请求，`processed_range` 表达本次实际准备范围；detail 的准备批不是连续扫描区间，不能以其包络表示全部图片已交付或逐帧覆盖 |
| 计划交付位置 | 三种 mode 均使用 plan_delivery 的 position/next_position/observations/window_complete；detail 的 observations 为去重后的一至三个源观察，window_complete 表示本次有限计划交付完。observation_position 为计划内源观察序号；这些位置不是对象 ID |
| 帧序号和图片位置 | 每帧有本页结果内递增的 `n`、所属 `image` 序号，均从 1 开始；拼图另有 `cell_rect=[left,top,right,bottom]`，相对最终输出图片归一化，包含最终裁边/留白后的实际位置 |
| 实际时刻 | `t` 为该帧映射到原视频时间轴的真实展示起点秒数；人类时间码仅作其显示格式，不用四舍五入后的字符串作为 seek 输入 |
| 时间差 | 除首帧外提供秒数 `dt`，等于与前一帧的实际时间差；跨图片、跨行仍按这个顺序计算 |
| 代表区间 | overview 可另给 `representative_range`，按整个固定计划的真实时间邻居计算或省略，不能按当前页邻居重划；仅说明采样分区，不将未取样画面标成已观察 |
| 坐标与边界 | 结果级给出原画面展示尺寸及实际 crop；格子到原画面的映射沿用同一几何。边界帧按需给出与请求范围相交的 `visible_range` |

detail 的 `n` 逐观察递增，`image` 指向唯一图片；不同观察可拥有相同 `image` 与 `cell_rect`。图片内烧号用唯一 `image` 序号，不用观察 `n`。`n`、`image` 是当前页结果的序号，不是跨调用身份、全局时间次序、私有 cell handle 或源文件帧号。跨调用定位使用原 target 和实际秒数；历史图片重读使用已有 IMAGE_REF。裁剪、缩放、留白或 DP 重排不能改变时间或原画面坐标解释。

每次结果明确区分 sparse 概览与 ordered 片段采样。ordered 只保证时间顺序，只有实际交付了全部相邻源帧才可声明逐帧覆盖。稀疏跳采、未处理范围、已观察到的切点及非均匀采样均如实标注；未扫描的间隔不能报告为“没有切点”。不以格子面积、图片相邻位置或重复帧数量表达时长，不把不相邻的时刻伪装成连续动作。

### 5.2 短片段回看与时间细节

`read_video_frames(mode="motion", from=..., to=...)` 承载圈定片段后的回看。模型既可直接指定范围，也可从 overview 或文字时间位置跳转；无需先安装标记、选片对象或播放会话。

- 在本次实际处理范围内，以展示时间和固定物理分析配置建立密集采样，保留开始、过程与结束的可见状态；本页 provider 额度不改变已定采样密度。不能只取某个最清晰时刻，也不能将候选帧按锐度或画面相似性重新排序。
- 已观测到短暂 A→B→A 时，按第 6.2.6 节保留往返前、中、后的实际帧与真实时刻；只保留相同的首尾或单个变化峰不足以交付该过程。未采到 B 时不推断它存在或不存在。
- 使用等尺寸、同一 crop 的有序格子或清晰分图，使帧间状态容易比较；overview 的可变格子 DP 不直接用于 motion 的连续帧排布。若为保留已观察到的快速变化而加入非均匀采样，索引必须体现实际 dt。
- 有切点时在相邻帧间标记已观察到的切点，不将跨镜头位置变化当成同一物体连续运动。没有切点也不意味着没有事件：录屏里的菜单打开、提示变化或物体状态变化同样需要过程帧。
- 分析窗口由固定物理分析配置决定，独立本页 provider 额度。当前窗口的稳定观察可跨页，完整 next 先交付剩余观察，再进入后续窗口；不得因显示预算重新选择过程、删掉已选中间状态，或只交付开头却把结尾标成“结束状态”。缩小 from/to 后可提高同一资源下的时间分辨率，不引入视频总时长上限或模型 FPS 参数。
- 回看不插值、不补帧、不修改播放时间来制造动作证据。快速闪现、精确动作次数或连续性无法由当前采样确认时，结果保留采样限制，供模型进一步缩小范围观察。

### 5.3 清晰帧与前后对照

`read_video_frames(mode="detail", from=..., to=..., crop=...)` 用于局部高清核对，显式范围满足 `0 < to-from <= 2` 秒。按原请求检查两秒边界，再求有效视频交集 [a,b)，取 a、(a+b)/2、before(b)。时间支持小数秒，strict-before 使用真实展示区间解析；同源帧满足多个目标时只形成一次观察。

每个目标直接解析其展示区间内的源帧。保持同一尺寸/crop 与原有长边至多 1280 的空间清晰目标；小字使用 crop，短暂状态缩小时间范围，过程问题使用 motion。已有画面足以回答时停止。

相同真实源帧的已验证展示区间可精确跳过其覆盖的后续目标；不同源位置即使画面相同，也保留独立实际时间索引。仅当前候选页中，展示变换/crop/目标缩放后的未烧号 RGB 尺寸与全部像素完全一致时，多个观察可共享一张图片。图片烧唯一 image 序号，索引分别保留 n、实际 t、visible_range 和图片位置；不按低清相似门删除细小数字或状态变化。

页面只交付有限计划的连续前缀；next_observation 指向下一未交付源观察。最小清晰图片及索引仍不适配时返回资源边界。结果以 sparse 表示首中尾采样，scanned_ranges 与 observed_cut_times 为空。

相隔较远的两个位置可通过两次 detail 读取对照，沿用历史图片和时间索引；不为一次比较扫描或密集解码中间全段，不增加 `compare_video`、`timestamps`、多范围参数或第四种 mode。比较不同调用时核对实际 crop、展示方向、源文件事实及时间，源已变化时不能声称是同一版本的前后证据。

### 5.4 同步来源与按需审看

画面、已有文字字幕和 ASR 使用相同时间轴，各自保留来源。时间重叠只表示同时出现，不自动建立“这句话描述了这个动作”的语义关系；字幕可能与讲话不同，旁白也可能早于或晚于画面操作。原视频已合成的内容不能被声称恢复成独立可编辑轨道。

文字只按任务需要读取。清晰帧上的硬字幕、错误提示、路径或幻灯片文字由模型直接读，必要时用 detail/crop；完整讲话总结、按时间读取字幕/转写或遗漏疑虑再使用 read_transcript。ASR 不能代替未被说出的画面文字，概览也不能保证看清每个字。波形、音量与 VAD 可辅助选取时间位置，但不能替代音乐、音效或情绪理解；首版不向只接收图片/文字的模型声称已交付原音频。

例如，对一个假设的“教程是否演示保存成功”问题：overview 找到操作片段；必要时按候选范围读取讲话原文，或使用现有搜索工具定位已保存原文中的“保存”；motion 回看附近的点击与弹窗；detail 放大提示并比较两端状态。每步由已有证据决定是否需要，最终结论引用实际时间和画面/文字来源。模型可在对话中保留候选时间段清单，不新增持久标记、选片表或剪辑导出流程。

媒体中的字幕、转写、画面文字与文件元数据均作为外部数据，不提升为系统指令。工具不执行其中的命令，也不调用 LLM 改写原文。

### 5.5 分段阅读、章节与用户交互

根据问题选择入口：全片总结或位置未知时用全片 overview 建立地图，再以相关片段的 overview 定位；具体内容辨认用不超过两秒的 detail/crop，动作与先后关系用 motion。用户给出时间点时直接处理当地问题，不强制全片概览或 motion+detail 组合。纯视觉问题独立使用画面工具；需要讲话时沿既有 read_transcript 合同读取。

章节、模型阅读窗口、ASR 分块是三个单位：章节是模型根据内容形成的可修正认识；阅读窗口是一次工具的 from/to；ASR 分块只是 runtime 的执行单元。模型可从 overview 形成章节草案，标题看不清时用 detail 核对，随后根据讲话与画面修正；不先精确划完全片，也不新建持久章节对象。一个章节可跨多轮，一轮也可跨章节。

不固定“一分钟一轮”。模型根据文字量、画面变化、疑点和任务选择窗口：普通连续内容可以扩大范围摊薄网络、首字和推理往返开销，密集操作或疑点缩短范围；overview 的采样密度、motion 回看与 detail 放大各司其职。扩大范围不证明未采样内容已被看过，缩小范围也不等于逐帧覆盖。内部 ASR 分块和并发不决定模型必须按相同长度阅读。

侧栏的模型范围来自当前 ROOT 工作实际开始的最近一次读取，工具返回后继续保留，下一次读取覆盖；工作回到 idle 时与 TODO 一起清空。历史处理范围与已交付画面保留在工具证据中，不从历史恢复当前范围。主模型按内容成熟程度用 annotate_media 追加带范围的洞察；也可用普通 assistant 消息回应用户，不必把同一正文再重复输出。章节尚未结束时可以继续读取而不发言或添加批注。不要求每轮总结、固定频率回应、跟随用户播放速度或另起后台 LLM。

长视频批注是与用户共同审看的入口：模型按需组合 overview 定位、detail 辨认与 motion 检查过程，边推进边标记有用发现，用户可点击批注定位、提问或调整关注点。批注范围跟随发现本身，可跨多次读取；局部问题处理后继续主任务。Skill 明确直接从 `read_video_frames` 开始，首次实际读取自动在侧栏打开视频，已满足该视频的展示需求，无需在审看前或结束时重复调用 `open_in_pulsara`；另行生成需要展示的新产物仍按通用展示指引处理。

bundled Skill `pulsara-video-review` 按全片总结、定点核对和讲话理解选择入口，也支持纯音频的讲话理解。每窗先核对来源、实际范围和未解问题，再选择复制完整 next、另开 from/to 窗口、局部回看或作答。next 为空时结合 complete、实际范围及错误判断覆盖。讲话论点与解释用文字取证，图表、演示和界面结果按对应时间核对画面；读完字幕不等于看完画面，纯视觉问题不必转写，也不要求每窗调用全部工具。正文用保存动作区分意图与结果，随包的 `references/worked-examples.md` 以长视频说明跨窗推进、保留未解问题、修正认识及局部回看后回到主阅读位置；另用同一短录屏演示全片总结与定点核对，再用讲座说明何时续页、换窗或结束。并行、缓存合并、缺口补齐和取消由 runtime 实现，不能靠提示词要求模型手工管理。播放器预览与 steer 的具体规则见第 11 节。

### 5.6 上下文额度与压缩

preaccept 恢复仅准备已闭合前缀的摘要和 dry quote，不提前 adopt。ROOT 队列据真实 dry successor 发放 fresh 份额；实际工具 batch 仍在原 epoch 结算，完成后重新核对实际 suffix，才 adopt/install 后继前缀。当前页是否已消费从已接受业务 assistant 的真实 input cut 推导，不新增读回执。导入的已结算历史不当作刚返回页面；独立 late observation 保留自身图文 carrier，不恢复旧 request。沿既有 owner 完成，不增加 durable job、ACK、实体 ID 或恢复图。

当前图文页和续读必须通过以下四项合同，不能由已有安全切点保护推定已经满足：

1. **当前页完整保留。** 已返回但尚待业务模型处理的图文页作为完整组保留，工具文字结果与对应图片附件 user 消息之间不能切分，不能只用摘要替代该页原图和索引；下一次正常模型请求必须取得图片、帧编号、时刻及真实调用归属。
2. **压缩后重新计算额度。** 旧历史占用使最小页无法交付时，在合法安全点采用既有 compaction successor 释放旧历史，再按压缩后的完整请求重算可交付额度。不能以压缩前剩余预算提前判定永久无法交付，也不能在已安装 epoch 重写前缀。
3. **仍不足时缩页续读。** 压缩后拟交付页仍过大，只从稳定观察序列减少当前页末尾观察并保留完整 next，不重新选帧或跳证据；已接受页不回写缩小。最小可辨帧、索引和控制信息仍不适配才返回 typed resource boundary，不返回空成功页或原地 next。
4. **生产链路实际理解与续读。** 生产 Host 中强制工具返回后压缩，检查后继真实请求的原图、帧编号、时间索引及调用对应，并让真实视觉模型完成定位/对照且复制 next 续读。覆盖压缩后整页可交付、须缩页、最小页仍不可交付三分支；核对无遗漏、重复、工具重执行。单元切点或摘要提到图片不替代此验收。

## 6. read_video_frames：候选选帧与排版算法

### 6.1 借鉴来源与实现边界

借鉴 `dsh-video-storyboard` 的“档位序列 → 行候选 → DP 分行分页 → 几何回溯”，参考仓库提交 `b644b99a0a3b8eb69e4d6ce7e8c01af06523949e` 的 `src/storyboard/pack.js`、`tiers.js`。不运行 DSH 插件宿主，也不搬入其设置服务、Cookie、兼容别名、私有缓存框架或启动脚本。

实现采用 Python，与媒体处理及现有 Pillow 同一栈。移植构成衍生代码时保留 Apache-2.0 头、NOTICE/署名，纳入现有第三方许可交付；Git 记录源码身份，不另存逐文件 SHA。

变化筛帧的设计参考 `dsh-see-now` 提交 `af33bbc750e267267a9cb2c35640c81f8ca1f2be` 的 `cuts.js`、`pipeline.js`。该仓库主体为 PolyForm Noncommercial，不能沿用 storyboard 的 Apache-2.0 授权假设。这里记录算法设计，Pulsara 使用已选媒体/图像依赖的算子实现，不复制其受限源码，也不引入其实时采集、后台唤醒、丢旧图队列或悬浮语音系统。

短暂往返的证据保留参考 [Aiming-cookie 的数值降采样](https://github.com/Clickist/Aiming-cookie/blob/67b686b6f034624287696c67e526302bc30663af/webapp/coach-runtime/src/evidence-native.ts#L370)：仅借鉴保留首尾与极值、避免短暂变化在压缩时消失的原则。视频候选仍使用本文的实际帧、变化特征和图片交付路径；数值极值保留不等于视频状态识别或对未采样时刻的恢复。

### 6.2 稳定计划与模式分工

#### 6.2.1 计划与页面分开

固定质量策略先决定真实观察及遍历顺序；provider allowance 只决定本页交付。detail 一次准备完整的首中尾有限计划，缩页复用本次候选，next 按最后交付观察推进。overview/motion 保留原计划/窗口续读。每次续读校验源、权限与策略，不建立持久分页状态。

detail 渲染在首次新增唯一图超出图片/像素物理准入时，直接交还已接纳的非空观察前缀；第一张清晰图仍不适配才返回资源边界。编码字节超出时，截在首个未准入唯一图的首次观察之前。后续 provider/正文缩页仅在本次调用内投影该已准入、尚未绑定的编码页前缀：保留已有图片字节与烧号，按剩余最后观察重新绑定 next、plan_delivery 和 complete，不重复解码或重选源观察。该临时值不跨调用、不成为权威缓存，已接受页不可修改。

若 worker 的内存或结果序列化边界使渲染来不及交还前缀，不能仅凭通用 RESOURCE_BOUNDARY 判定最小页也失败。直接验证一次首观察的清晰原子页；适配则交付该前缀并保留 next，仍不适配才报告边界。不逐个减少观察数重复启动解码，也不依赖错误消息文字猜测失败原因。

本次页面的 canonical/logical/wire/token 必须共同适配。依次减少本页遍历序列末尾的观察并重排，使用真实图片、完整索引和完整 next quote；JPEG/DP 的字节数不保证单调，不使用未经证明的二分搜索。正常非空页必须推进，最小一帧及其索引、控制事实仍放不下时返回 typed resource boundary，不返回空成功页或原地 next。已经接受的页不可回写缩小。

#### 6.2.2 全局与局部变化特征

先应用展示旋转、像素宽高比校正和本次 crop，保留坐标映射，再生成低清分析视图。分析视图只用于选时刻；最终图片回原片按所需清晰度生成，不能放大分析图或 overview 缩略图冒充清晰回看。

全局变化使用 HSV 距离。以 64×36 网格作为横屏分析起始配置；每格聚合少量像素，HSV 通道归一到 0～255。设 P 为有效网格数，h 为两帧色相的环形距离、w 为两帧较小饱和度除以 255，则：

`G_i = Σ_p (w_p × h_p + |ΔS_p| + |ΔV_p|) / (3P)`。

局部变化使用稍高分辨率的亮度代理图。横屏起始配置为 256×144、划为 16×9 块；在每块内计算亮度差超过噪声门槛的像素比例 `p_ij`，得到 `L_i = max_j p_ij`，保留命中块的范围与强度。它补充全局均值可能淹没的小按钮、状态文字或弹窗变化；只检测像素变化，不识别文字内容或将变化命名为业务事件。

其他画面比例保持几何比例；必要留白不参与评分。网格、块尺寸和噪声/局部门槛是为低成本检测设定的内部初始配置，须经第 14 节基准校准，不能作为输入视频尺寸限制。低清或未采样时刻仍可能漏检，局部检测不能撤销基础覆盖或 motion 时序骨架。

#### 6.2.3 Overview 的确定性选择

1. 按 crop 后比例建立默认方向感画布，长边至多 1280、面积至多 1280×720。代表画面目标为横向至少 320×180、竖向至少 180×320；对原尺寸使用 `scale=max(required_width/source_width,required_height/source_height)` 的单一比例并安全取整，同时满足两轴下限，不能拉伸或让极端宽高比的短边塌缩。
2. 令目标矩形为 `(w_target,h_target)`、默认画布为 `(W,H)`，`K=max(2,floor(W/w_target)×floor(H/h_target))`。至少两个名额用于不同的真实端点；首尾命中同一源帧时只交付一次。16:9 的默认 K 为 16。这是一次方向感概览的质量配置，不是 provider 最大值或媒体长度、总调用数、任务寿命上限。
3. 在解析后的有效视频轨道区间内，令时长为 D 秒，建立 `Q=min(2K−1,max(3,ceil(D)+1))` 个均匀目标，包含实际可见首尾。末目标严格位于半开终点之前；不在视频轨已结束的纯音频尾部安排探针，原请求未被视频覆盖的事实仍返回。短片约每秒一个候选，极短片保留首中尾，长片按质量预算稀疏取样；这些不是固定整数秒采样。依真实展示区间解析实际帧并去重，不能把 Q 当作实际依赖解码帧数。
4. 按时间建立相邻观测组：每个候选只与当前组固定第一张画面比较，`G≤3 且 L≤0.15` 时入组，否则新开组。固定基准避免缓慢漂移被逐邻帧相似性一路合并。组只是相邻已采画面，不是连续静止区间、镜头或语义章节；不同时间出现的 A/B/A 不做全局去重。
5. 每组可选代表取低清锐度最高者，平局取靠近该组已观测时间中点者，再取较早真实 PTS。保留不同真实首尾，端点所在组已算有代表。其余代表按以下降序键选择：包含未选组代表的最大已选时间间隙、距该间隙两端最近距离、邻组局部新颖度、较早 PTS。局部新颖度取与相邻组第一张画面比较的 `max(G/10,L/0.2)` 的最大值。不含未选组代表的间隙跳过；所有组已代表或达到 K 即停止，不填重复画面。该策略优先方向感，不承诺全局最优时间覆盖、语义召回或未采到的短暂事件。
6. 固定遍历顺序为实际首、实际尾、随后逐次选出的代表；每一页只取该顺序的连续片段，页内按真实 PTS 排序后排版。跨页不承诺时间递增，编号、图片与矩形均为当前页局部位置。若保留 representative_range，只能按整个固定计划的时间邻居计算或省略。

overview 不做默认连续开头扫描或全片逐帧扫描，`scanned_ranges=[]`；稀疏探针不产生连续扫描区间、真实切点、精确切点数或未采到的 ABA。分开报告全局分析范围、实际交付样本及地图完成状态；仅能交付一帧的首批明确是未完成概览。320 目标也不保证小字可读，准确文字通过 detail/crop 核对。

#### 6.2.4 Detail 与 motion 的稳定证据

detail 的局部范围与三个目标按第 5.3 节生成，完整计划最多三个不同源观察。显式范围与两秒边界在探测和解码前校验；直接准备入口同样校验。有效 [a,b) 由源与请求求交，保留原 requested_range 及前后无视频事实。

detail 使用精确有理数首、中、尾目标和原源展示区间。不同目标落在同一源帧时合并观察，不同源位置的相同图片保留各自时间。最小分析准入不足时明确报错，不减少选定目标。

detail continuation 只含下一未交付源观察 next_observation，复用有限计划位置；不设时间窗口游标或持久计划。next 根据实际交付位置推进。有效计划全部交付后 next=null；请求前后缺少视频时 complete=false 并说明缺口。取消、最小页失败或未接受页面不消费位置。

detail 不运行变化候选、切点/ABA 检测或邻域择锐，`scanned_ranges=[]`、已观察切点为空；解码依赖或已准备时间包络不能冒充连续观看。最终图片从原片按固定空间目标生成。页内精确共享仅改变图片表示，保留每个独立源观察及时间索引；低清相似不能证明同文字或同状态。

motion 按固定 256 个实际源观察的物理分析槽决定窗口，连续扫描并完整保留窗口内真实有序观察序列；该配置不因本页 provider 额度变化。先交付完窗口内剩余观察，再沿精确下一源 PTS 进入后续窗口，不预先建立整小时密集计划。所有已选过程观察可跨页，不能为适配页面抹掉中间 B、独立返回 A′或真实端点。不插值、不补帧。

只有实际连续扫描可计算相邻变化、累计、切点与往返，遇缺口必须重置。局部变化不要求同时通过全局阈值。未采到、源未记录或特征无法分辨 B 时，不能由 A/A 推断期间没有变化。

#### 6.2.5 质量档位与页面排版

只对当前页已固定证据排版。overview 页内统一档位为 `clamp(ceil(sqrt(n_page)),1,8)`；稀疏观测不能提供真实切点密度，不按切点密度分配档位。档位保持第 6.3 节尺寸比例区间，DP 不增加候选填洞、不决定证据重要性。detail 使用清晰大图与页内精确共享，motion 使用同尺寸、同一 crop 的有序格子或分图。

预算不足先减少本页帧数、增加正常源页；不能为避免分页压缩全部证据。只有 overview 在单个目标尺寸原子帧连同索引和完整 next 仍不适配时，才一次降至横向至少 160×90 / 竖向至少 90×160 的两轴场景下限，同样用单一比例满足两轴。只有目标与下限两档，不逐像素重试；降档明确披露场景可辨限制，不保证文字可读。motion 保持目标尺寸的过程图，detail 保持长边 1280 的清晰目标，两者只缩页，不使用 overview 场景下限。各自最小原子页仍不适配时返回 typed resource boundary。

奇异宽高比需要的原子画布可在实际物理 quote 允许时超出默认画布；否则报告明确边界并建议 crop，不增加宽高比禁用名单或媒体总时长上限。最终画面从原帧生成，不能放大分析缩略图冒充清晰证据。原源分辨率本身不足时如实披露。

这些默认数值是明确实施目标，须经第 14 节素材和行为验收；不是已证明最优参数，不暴露 strategy、tierMap、fps、maxFrames、maxSheets 或像素预算等模型参数。

#### 6.2.6 短暂 A→B→A 的保留

本节是 motion 连续过程的保真要求，不作为 detail 的变化补帧规则。motion 保留连续扫描的实际有序观察，包括真实 A、中间 B、返回 A′及精确时刻。相邻等高变化峰不能代替中间状态；不能要求往返同时满足切点尖峰、累计门槛或去抖间隔。B 较模糊仍保留实际图，A 与 A′即使像素相同也保留独立时间索引，可复用图片字节。

已选过程必须通过后续页面完整交付；当前页尚未交付完时明确 incomplete 和 next，不把局部页面称为完整往返。overview 的相邻稀疏组与 detail 的首中尾采样均不等同连续往返检测。detail 已采中的不同源观察不得因相同像素删除，但采样点之间的 B 仍可未采到；不承诺任意短 ABA 均可识别。

### 6.3 行候选与约束

所有帧保持原时间顺序；只允许连续帧组成一行。尺寸比例的允许区间沿用原方案：1 档为 `[1/2,1]`，2 档为 `[1/3,1/2]`，其余 k 档为 `[1/(k+1),1/(k-1)]`；再与最小可读尺寸取交集。区间为空时提高该帧名义尺寸或减少当前页帧数，未交付观察留在 next；不能改变稳定计划或突破可读性下限。

每个行候选携带连续帧数、每格几何、行高和实际图像面积。生成名义尺寸候选，以及通过有界二分调整尺寸的满行候选。枚举到最小允许宽度之和超出画布后即可停止，行长由当前可读尺寸约束自然决定，不新增全片帧数上限。

首版不采用非等比拉伸候选。按比例缩放、必要时留白；不通过变形或裁掉原画面来填缝，也不为了填满版面额外抽取无关帧。最终裁去的是画布外侧空白，不是帧内容。

### 6.4 DP 状态与目标

采用整数像素几何，行高向上取整后进入状态，避免归一化浮点误差导致实际多开一页：

`DP[i,h] = 排完前 i 帧、当前页已使用 h 像素高度时的最高得分。`

奖励为每格实际画面面积除以单页画布面积；关闭一页扣一次开页代价。overview 默认 `mu=1`、`lambda=1.5`：

`score = mu × 总归一化画面面积 − lambda × 页数。`

该 lambda 是偏向紧凑概览的内部产品策略，不是 DeepSeek 或其他 provider 的 token 单价。不能据此宣称跨模型计费最优。实现验收对比 1.02、1.5、2.5，若需调整默认值，在本文和基准中同步记录，不新增模型旋钮。

转移包括：当前页接一行、主动关闭当前页、放不下时换页接行。每个状态只保留最高得分及前驱。结束时计入末页代价，回溯恢复行、页和格子。最高分只针对当前候选行和离散像素状态，不宣称任意二维布局全局最优。

回溯后必须按最终几何重算页数、面积、边界与重叠；不能用另一个启发式偷偷修改布局后继续使用原 DP 得分。若几何不可实现，丢弃该候选并显式失败或重新求解，不做数据修补掩盖错误。

### 6.5 编号、时间与实际成本

每张拼图标注其实际采样时刻的跨度，overview/motion 的格子在页内按时间编号；overview 跨页遍历沿稳定覆盖优先位置，不将页内编号当全局时间序号。detail 观察按时间索引，精确共享图片烧唯一 image 序号，多个 n 可映射同一 image/rect。采用第 5.1 节的同一索引，区别实际取帧时刻与代表区间；格子面积只表示排版分配，不表示镜头持续时间。索引作为紧凑文字交付，不额外生成一张占用上下文的时间线截图。

整图编码后，按当前模型的实际图片预处理与资源 quote 验证。图片越少不等于费用必然越低；不复制 DSH 的“每张固定 384/233 token”口径。预算不足时在提交结果前减少当前页帧数并重排、续读，不能重新选择稳定计划，不把图片作为 Base64 文本或不可见文件路径交给模型。

页面只接受本页真实图片、相应完整索引、必要控制事实和完整 next；复用 ToolResultPageBudget 的完整外层文字检查与图片 owner 已有的联合 provider 请求 quote，同时通过 canonical/logical/wire/token，不重复计算文字。C/P 只含本次接受页，不能存在隐藏未交付图文后缀。read_file(SESSION_ENTRY) 只回读已有 UTF-8 正文，不充当多模态源分页器；历史图片仍走已有 IMAGE_REF。

### 6.6 解码、重试与内存边界

PyAV/FFmpeg 拥有 demux、seek、依赖解码和 flush；MediaSource/MediaWorker 保持文件权限、已授权描述符、物理内存、取消、deadline、kill/reap。Pulsara 只适配展示区间、真实观察与产品分页，不新增进程池、持久 worker 或 GOP 索引框架。

内部使用 `pts×time_base` 和原点的有理数坐标；对外浮点秒数用于显示，选中帧与续读边界不能由四舍五入的 t 重建。相同 PTS 的连续解码帧归一化为该时间最后一帧，前面的零展示时长帧不作为独立观察。缺少 PTS/time_base 或展示 PTS 倒退时返回 typed 结果，不发明 FPS 时间线或静默修补。

真实展示区间为 `[PTS,下一不同 PTS)`；终帧优先真实 duration，其次已知轨道端点，未知时不能虚构保持区间。范围尾部严格求 `before(end)`。seek 后必须证明目标的前驱展示区间；目标早于真实首帧时按延迟轨道与请求交集处理，不能交付请求之外的晚到帧。

正常每个 decode pass 使用一个活跃容器，有序目标共享 predecessor/lookahead，只有需要的实际观察转换 RGB。密集窗口连续解码，远距离稀疏目标 seek；不能盲目顺序解码到全片结尾。疏密切换复用上次成功 seek 的实际帧工作量 S（包含定位中失败 seek 和回退解码）及 preroll 时间 D：已被展示区间覆盖则复用，近于 `max(D,最近正时间间隔)` 先前向解码，远距 seek。一次前向尝试消耗 S 帧仍未夹住目标则转 seek。这是每段调度，不新增总解码帧数、重试数或媒体寿命上限。

open-GOP 等情况使 seek 首次输出晚于目标时，按观测超前量向更早时间扩大回退；达到真实起点仍无法证明时重新打开已授权源，从自然开始解码。晚到帧不能冒充目标帧，最差依赖工作仍受现有 deadline 与取消约束。

一次逻辑调用先完成一次低清 prepare_plan，再执行 render 尝试，沿现有一次性子进程生命周期分开两个操作。parent 只保留有界低清分析所得的元数据计划，不持有低清或原分辨率栅格，渲染可重新解码本页所需原帧，不承诺跨进程或跨页零重解码。预算重试不得重复分析或更改稳定代表帧。

内存核算包含 parent 元数据计划及其序列化副本、child 低清分析视图与原生参考帧、lookahead、单张变换 raster、画布和编码结果；低清槽数不授权保存同数量原分辨率图片。结束、失败、取消均丢弃计划，源检查贯穿 prepare、render 和最终接受；物理工作停止后才能释放原 owner。

## 7. 文字处理与质量约束

字幕保留原文，利用成熟字幕解码 API 去除格式控制，不将 ASS 样式代码当台词。避免把同一句跨多个分镜的台词全文重复打印，但不能为去重消除不同时间真的重复发生的发言。

### 7.1 云端 ASR 的同步与内部并行

只有按第 4.2 节进入转写兜底路径后，才从视频或纯音频抽取实际缺失范围所需音频，做选定服务要求的声道、采样率和编码转换，不上传视频画面或无关范围，不先重编码视频。可用字幕的条目空白或请求范围没有字幕条目均不启动转写。ASR 转写而非翻译；由配置服务自动识别原音频语言，不新增语言设置或模型工具参数。服务返回的句子/词时间映射回原媒体 PTS 时间轴；不能用字数均摊、图片时刻或另一个 LLM 猜时间码。

执行顺序为：冻结源事实和本次识别设置 → 校验 continuation 并先装当前位置可用原文 → 必要时按媒体版本与访问域求完成并集和缺口 → 按时间计划本次累计最多 180 秒有效缺口 → 提取音频并附带静音检测 → 按 admission 切分/并发 → 校验每块响应与源事实 → 缓存成功范围、原文及已有声音观察 → 按时间装页并交付完整 next。识别设置只用于本次新增缺口，不参与已有缓存命中；仅提交本次范围内的缺口及必要边界上下文，不按播放器位置、章节猜测或下一轮阅读计划扩展转写。

例如请求 `[180,360)` 且无缓存，可以内部并行处理 `[180,240)`、`[240,300)`、`[300,360)`，合计正好 180 秒；60 秒仅为示例，不是固定块长或模型阅读节拍。实际块长取决于服务的音频时长/字节限制、切句质量、调用开销、计费粒度及本次处理边界；优先在附近停顿处切分，使用成熟媒体/VAD 能力，不自造语音识别器。实现基准后冻结首个适配器的内部默认，不向模型暴露块长。单块/并发配置不能扩大每次调用累计 180 秒的产品边界；失败或空文字不能通过重置额度继续扫描全片，既有重试仍如实记录实际上传与费用，不声称 180 秒等于费用或端到端等待的绝对上限。

并发数受同一服务/账号经核实的并发与速率配额、现有网络/内存/物理执行 admission 共同约束；所有相关调用共用该物理额度，不各自启动一组无约束请求。配额未知时单请求执行，其他逻辑块排队；这是未知协议额度下的物理准入，不是拒绝长视频或额外任务的总上限。每块独立完成、归位与结算，不按完成先后排列台词；不保证增加并发就线性加速。

调用在现有 watchdog 内同步交付；不向模型暴露云端任务 ID，也不在结束后另起识别、轮询或后台唤醒。部分失败按第 5 节交付连续成功前缀并报告缺口；成功的后部块可缓存，不能用整段首尾包围范围掩盖中间失败。

### 7.2 跨块拼接与边界

合并对象是带绝对时间与来源的句子/词列表，不是无时间的字符串或新生成摘要。每块保留实际请求音频范围、负责的有效范围和服务原始时间事实；边界上下文可重叠，重叠不重复计作新的有效覆盖。边界上下文的额外音频仅用于保证切句质量，须受源范围、实际服务限制和第 10 节的数据发送约定约束；不能借“上下文”转写远处内容。

收到响应后按 OpenAI 转写协议的实际字段与时间事实确定性识别，不依赖模型名、供应商目录、配置页测试记录或另一个 LLM。每次响应独立校验顶层 text、词/段条目的文字字段、有限且非布尔的秒数时间、起止关系、顺序和相对实际请求音频的范围；未知包装或单位不靠猜测转换。服务可返回额外字段，保留必要来源，不递归寻找任意 text 来冒充标准响应。

| 实际响应 | 使用方式 |
| --- | --- |
| 有合法且非空 words | 优先使用词级时间；按句末标点、至少 0.5 秒的词间停顿及说话人变化确定性整理可读小段，起止取首末词真实时间，保留底层词数据 |
| 无可用 words，有合法且非空 segments | 保留服务的段级粒度和可选 speaker，不把覆盖整块的一个 segment 当作一句，不补造词级时间 |
| words 无效但 segments 合法 | 使用合法段级结果并保留词数据异常诊断，不混入未经校验的词 |
| 有文字，没有合法时间戳 | 明确不满足时间定位要求；不按字数均摊、不将整个请求范围补成伪造的服务时间戳 |
| 空文字，时间数组为空或未提供 | 如实表达没有取得文字，时间戳能力未证实；不能证明静音、无讲话或纯音乐，也不能作为已知语音连接测试通过的依据 |
| 无合法替代粒度且结构/时间非法 | 报协议或响应错误，不将部分坏条目丢掉后冒充完整成功 |

不维护供应商或模型到返回形状的映射，不要求先收集大多数返回样本；只支持明确的协议结构，并在本地覆盖各结构与非法数据的验证。字段合法不证明识别准确率、时间对齐精度或转写无遗漏。不为分句另调 LLM，不因测试通过就跳过真实响应校验，不在文字或时间不合格时额外发收费请求试探其他输出格式。

模型请求某个时间附近的文字时，按 from/to 筛选底层时间条目，可从多个缓存块组合，不必把整块转写交给模型自行查找。展示分组不删除词级索引；跨块时间统一加回实际音频在原媒体中的起点。分组与时间校验不证明专名正确或转写无遗漏，不静默“校正”服务原文。

有词级时间戳时按实际时间选择内容。只有句级时间戳时，保留与请求范围相交的完整句子及真实起止，另给 `visible_range` 说明请求交集；不能把整句时间裁成 150–180 却暗示全文都在这 30 秒内，也不按字符比例截句。相邻逻辑块对边界句采用确定的时间归属与重叠去重，规则随适配器冻结，跨缓存读取保持一致。

去重同时依据重叠音频、时间位置和内容，只去除同一次发言因边界上下文产生的副本。不同时间真实重复的发言保留；两次独立识别在边界给出不同原文时，不简单拼字或让 LLM润色成“正确台词”。保留选定原文及必要来源/边界限制，无法可靠衔接时明确说明。后续缓存合并不能改写已经交付的有效范围原文以掩盖分歧。

一块成功处理而没有识别到讲话，可记录该块已处理且原文为空；这不证明物理上绝无语音。认证失败、服务异常、无法校验时间戳、响应不完整或取消均不记作已完成。过滤可疑重复/低可信内容要保留可诊断原因，不能将失败或被过滤内容都当成静音。

### 7.3 无音轨、静音与空转写

文件级有无音轨由容器/流探测确定。视频的默认 overview 已用一行基础元信息显示该事实；read_transcript 自行探测，并按第 4.2 节保留“无音轨但有可用文字字幕”的读取能力。没有音轨不等于字幕为空；有音轨也不证明某个请求范围实际有声音。

范围级静音检测复用已选 PyAV/FFmpeg 音频处理路径，在本次确需提取的音频中检测音量，不调用额外模型、不下载权重、不新开全片扫描或音频分类任务。优先使用依赖已有的静音检测能力，冻结首个媒体适配实现前核实随包库的实际 API。检测覆盖有效请求范围，边界上下文不冒充该范围有声音；按声道检查，不能因混为单声道后的相位抵消误判静音。

| 已确认事实 | 模型可见表达与行为 |
| --- | --- |
| 没有音轨，且没有可用文字字幕 | NO_AUDIO_TRACK；说明无需再次调用 read_transcript，不发 ASR、不返回重试 next |
| 本次检测范围全段低于已验证的静音阈值 | “此范围近乎静音”；保留范围，不能保证绝对无声或不存在极轻讲话 |
| 本次检测到非静音声音，ASR 成功返回空原文 | “此范围存在声音，未获得可转写文字”；不能推断纯音乐、噪声、无人讲话或识别准确 |
| 没有声音检测事实，文字结果为空 | 只说明未获得文字，声音状态未知；不从空结果猜静音 |
| ASR 缺配置、失败、响应无效或取消 | 按真实错误/执行状态返回，不冒充静音、空转写成功或已完成覆盖 |

近乎静音是阈值观察，不作为跳过 ASR、裁掉音频范围或将范围标为已完成的依据；原文非空时照常保留，不因音量低过滤。阈值与持续时间由低音量人声、数字静音、底噪、短音效及多声道样例实测后在媒体适配器内部明确，不新增工具参数，不把整个范围的平均音量低误判为全段静音。

已有字幕或完整转写缓存命中时不为补充声音状态重新解码音频。可复用缓存 payload 中已有、覆盖当前查询范围的声音观察；缺失或仅覆盖部分时保持未知，不把块级存在声音自动套到任意子范围。新检测若保留静音/非静音区间，则使用原媒体的真实时间边界，仍放同一成功块 payload，不另建声音表。检测失败不丢弃有效转写或伪造静音，必要诊断留原 owner。声音观察不能独立充当成功 ASR 覆盖，仍按第 9 节以实际成功处理的块为准。

## 8. 资源、取消、并发与长视频

物理解码内存准入（`media/resources.py`、`media/worker.py`；行为验证见 `tests/test_media_source.py`）：所有媒体 worker owner 共用进程级标准 `threading.BoundedSemaphore`，容量复用 `foreground_io_hard_concurrency=8`，不同会话、Core 设置操作和事件循环不各自增加 8 个名额。等待者每 20ms 以非阻塞方式重试同一个物理名额，可取消；这是物理准入等待，不建立任务实体或生命周期上限。取得名额后冻结 `B=floor(A/8)`；A 为 psutil 报告的实际可用内存，Linux 再与当前 cgroup 及所有可读取祖先的 `(memory.max−memory.current)`（或 v1 对应值）取较小值。B 是本次新 worker 给宿主增加的物理内存分配，覆盖该进程整体 RSS，不是源文件大小、分辨率、总帧数或输出图片像素限制。

Linux worker 在启动后以当前 VMS 为基准，将新增地址空间 allowance 设为 `max(0,B−当前RSS)` 并保留已有更严格 OS hard limit；由 RLIMIT_AS 在本次解码分配时约束。两端宿主同时每 20ms 通过 psutil 观察所属子进程 RSS；超过 B 时终止并回收该子进程，返回 RESOURCE_BOUNDARY。macOS 不把无效的 RLIMIT_RSS 当作硬保证，采用此 RSS 检测与解码前几何准入；轮询可能漏掉两次观察之间的瞬时峰值，不能宣称精确约束所有原生分配峰值。源视频解码前按 coded width/height、最多四个 16bit 分量的每像素 8 字节，计一个参考帧与两个解码/转换缓冲，再加按 SAR 扩展后的两份 RGB 展示缓冲，与当前剩余 B 比较；这只是可取得几何下的保守工作集预检，实际 codec 参考存储和后续累计仍由 RSS/OS 边界结算。通过 PyAV 的支持配置将解码器 thread_count 设为 1，避免自动帧线程复制绕开该分配。不能安全解码时明确资源边界，不静默缩小或改写源媒体。

探测按用途读取元数据：批注、字幕与缓存路径不为补充声音状态或展示旋转解码音视频；只有读图需要显示变换时才解码必要首帧，时间起点优先复用容器/流事实，元数据缺失时只读取必要 packet PTS，不为获取默认时长扫描全片。测试覆盖两个独立 owner 争用同一物理名额、取消/关闭释放、真实 worker 超限回收、cgroup 祖先 headroom、SAR 几何边界及元数据路径不调用 decode。Linux 原生发行仍须在 Ubuntu/WSL2 上实测 OS 限制；macOS 的 RSS 观察限制如上，不能用模拟测试宣称另一平台验收完成。

- 不新增视频总时长、文件总大小、会话累计帧数、工具调用次数或任务寿命上限。大文件按容器与流读取，不整体载入内存。
- 单次操作受既有 tool watchdog、内存/进程 admission、图片 canonical/logical/wire/token allowance、输出容量及云服务协议限制约束。物理容量不足时排队、分批或给出明确资源边界，不增加全片处理上限；云端 ASR 不执行本地语音模型推理。
- 解码与音频转换在可取消的隔离物理 worker 内执行；云端请求采用可取消的 SDK/HTTP 异步路径。不能在主事件循环运行阻塞解码，也不能把不可停止的 C 扩展或仍在发送音频的请求假装取消成功。复用既有物理执行/结算 owner，不增加 durable job、租约、重放或崩溃续跑机制。
- 原始高分辨率视频可用于生成低分辨率结果；不得把现有输出图片像素限制错误地套成源视频分辨率总上限。无法安全解码时返回明确资源边界。
- 按既有物理执行和服务配额 admission 排队，取消等待项及时撤销；运行项关闭自己的流/worker 并结算，停止提交后续音频。不将排队误判成云服务失败。进程内复用同一识别工作时，一个调用取消只撤销自己的等待；仍有其他合法调用使用的工作不能被误杀。远端已接受任务不保证能够撤销或免计费，诊断保留实际请求结果，不伪造撤销成功。
- 一次取消、超时或崩溃不会将未完成范围标成已完成。已有可交付进展可返回 partial 与 next；没有进展明确失败，不制造后台完成承诺。
- 内部元数据探测、read_transcript 和 annotate_media 不因当前模型不能收图片而不可用；只有 read_video_frames 的图像路径受该能力检查影响，不静默变成只返回元数据的成功调用。
- 不做跨调用、跨请求范围的预测性 ASR 预取。播放、拖动、打开侧栏、read_video_frames、annotate_media、模型思考或云端完成某块均不会自行发起下一段识别。一次读取内未处理完的逻辑工作通过 next 继续，不变成后台全片任务。

## 9. 缓存、证据与持久化

解码元数据、扫描结果、代表帧、字幕解码和排版缓存可丢弃；ASR 已确认成功的转写块使用第 9.3 节的一张可清理数据库缓存表，跨进程重启复用，减少重复识别、等待和收费。原媒体的内嵌字幕仍留在源文件中，不为它另建全片字幕库。缓存不负责权限、执行恢复或证明模型已经看过；视频回看仍按本次模式、清晰度和 crop 生成结果，不把低清概览缓存当作高质量原帧。

图像缓存继续使用现有文件读取 owner 的实际 stat 事实、流选择、crop、算法版本、实际分析尺度/探测间隔/阈值。视频和纯音频共用同一张 ASR 缓存表；持久媒体版本键固定为规范路径、`st_mtime_ns` 与 `st_size`，仅在现有访问域内复用。ASR 请求地址、模型/版本以及内部识别、音频处理或时间对齐参数均不参与命中、ID 派生或唯一约束；切换配置继续读同一媒体的已有成功原文。来源使用实际 typed 值记录，不存秘密值或其散列，不新增源文件全量 SHA、DTO fingerprint 或 fingerprint 注册表。

本缓存保存原媒体的已完成语音转写，不是某个模型配置的输出集合。配置变化只影响尚未处理的缺口，不自动刷新、覆盖或重做缓存；不增加刷新 action 或按模型选择缓存的参数。被第 9.4 节的一键清理实际删除后，相关范围才重新成为可识别缺口；最近使用的媒体继续复用缓存。选定音轨沿用第 3 节的源决定规则，ASR 不做翻译，不因切换模型重新选轨或改写旧文字。

from/to 与 continuation 是本次源读取的范围/位置，不参与 ASR 缓存身份，不阻止子范围或跨块复用。表中每行的有效 from/to 记录该块确实完成的范围，不要求查询范围恰好等于某行。每次调用只从缺口中按时间选择累计最多 180 秒；命中缓存的时长不占该额度。ASR 缓存源键与播放器/批注的归属分开：后者继续按规范路径与文件修改时间，不因新增缓存表而增加文件大小、inode 或独立媒体 ID。

### 9.1 完成范围并集与缺口补齐

本节仅用于第 4.2 节的转写兜底路径；有可用文字字幕时不因字幕空白计算 ASR 缺口。对同一媒体版本和访问域，保留每块成功处理的有效范围及带时间码原文；完成范围独立于文字项，不按 ASR 模型或配置拆分。令请求为 R、已完成范围的并集为 U，仅识别差集 `M = R − U`。U 可以由多块共同覆盖，不能只检查“有一条缓存完整包含请求”，也不能用最早/最晚句子包围范围代替 U。缺口可以有多个，分别切分与并发，不重跑已完成的中间范围，也不以宽松时间容差吞掉未处理缺口。

读取时先按媒体版本和访问域筛选，再查满足 `block.from < request.to && block.to > request.from` 的相交成功块，按 from/to 稳定排序。对相关范围单次遍历，只将相邻或重叠区间求并集，再求请求中的差集；不用扫描所有媒体的缓存，也不要求有一行包含完整请求。必要索引围绕访问域、媒体版本与区间读取设置，在实际查询计划和长媒体基准中验证，不另建分页会话。

写入保留独立转写块，不在每次成功后把正文或 words 拼成长行，不重写旧块。完成范围并集只是读取时的可重建派生值，不额外持久化合并区间表、全片完成标记或完成账本。进程内若保留派生索引，也允许随时丢弃并从成功块重建。

| 已完成范围 | 新请求 | 逻辑上新增识别 |
| --- | --- | --- |
| `[180,240)`、`[240,300)`、`[300,360)` | `[190,220)` | 无 |
| 同上 | `[220,280)` | 无，跨两块组合原文 |
| 同上 | `[150,210)` | `[150,180)`，复用 `[180,210)` |
| 同上 | `[330,390)` | `[360,390)` |
| 同上 | `[150,390)` | 并集为 `[180,360)`，只补 `[150,180)` 与 `[360,390)` |
| `[180,240)`、`[300,360)` | `[180,360)` | `[240,300)` |
| `[180,360)` | `[150,600)` | 本次最多 `[150,180)` 与 `[360,510)`，合计 180 秒；中间缓存不占额度，`[510,600)` 通过后续 next 处理 |

同一媒体的 `[180,360)` 由模型 A 完成后切换到模型 B：读取 `[200,300)` 零新增 ASR 请求；读取 `[330,390)` 只由 B 处理 `[360,390)`。不同来源块按原时间轴组合，分别保留原文和来源记录，不为了整齐统一模型、重写台词或重新计费。

必要边界上下文按第 7.2 节处理，逻辑缺口不因此变成整段重识别。组合结果按绝对时间选择原文，不修改旧块时间来适配新请求，不强制把缓存对齐到固定整分钟网格。新增块写入后，下一次读取自然会得到新的并集；不合并正文行也能复用连续覆盖。

同进程并发读取相同媒体版本与访问域的相同缺口时，在通过各自访问检查后可复用正在运行的识别及已完成块，防止重复提交，不因后来的调用更换模型就重复识别。已经受理的实际请求沿用其冻结配置；之后新缺口才使用新配置。在途识别仍由现有执行/取消 owner 和最小 process-local 协调持有，不存入缓存表，不建租约、跨重启作业或新调度框架。正在运行不算已完成，等待失败后不能命中空结果；成功块仅在响应、时间映射和源事实校验通过后按第 9.3 节提交。部分响应未能确认完整覆盖时，只保存明确完成的范围，其余仍是缺口。

### 9.2 缓存生命周期与证据

连续窗口图像特征不能跨未扫描区间拼接成完整扫描；概览抽样缓存不能冒充 motion 密集观察。缓存命中每次都重新通过文件/权限与源版本检查。切换识别设置仍复用旧原文，并保留该块实际来源，不将缓存原文标为新模型重新识别的结果。

ASR 数据库成功块在重启后仍可命中；未完成的识别、派生索引、当前工作阅读范围和其他进程内观察允许丢失。缓存按第 9.4 节人工一键清理超过 24 小时未使用的媒体，删除后相关范围重新成为缺口，不要求重建缓存才能使用媒体。24 小时是用户点击清理时的保留条件，不是自动过期、后台清理周期或媒体任务寿命上限。磁盘音频和帧临时文件沿用临时/缓存清理 owner，不将音视频二进制存入 ASR 表，不新增任意总时长/行数上限、自动保活或执行恢复任务。

已经交付的字幕/转写原文仍归普通工具结果，图片进入现有 canonical image/blob owner；会话历史、正文补读与 IMAGE_REF 回读不依赖 ASR 缓存存活。精确补读和保存原结果继续使用 read_file / write_file(source=SESSION_ENTRY)。缓存中的完整成功块用于后续范围复用，已提交的工具结果记录本次交付事实；清缓存不删除或改写它们，不通过重放历史调用恢复在途识别。

已提交批注以 annotate_media 调用/结果为真，不存入 ASR 表；丢弃侧栏 Map 后可按需重建批注视图，不承诺自动恢复整个分析现场。模型范围仅由仍存活的当前工作 owner 提供，不从历史读取结果恢复，见第 11.5 节。重复读取仍是一次新观察，缓存不证明模型消费或理解；关闭播放器、用户 seek 和会话切换不改写已完成工具结果。

只新增第 9.3 节的一张 ASR 成功块缓存表；不建媒体主表、逐词表、会话/媒体/批注外键、独立产品关系、事件种类、guard、持久 job、识别状态机、媒体/批注注册表或分页会话。工具调用、结果正文及图片证据使用现有 canonical 路径。批注视图复用来源结果的身份，不另分配批注 ID。

### 9.3 ASR 成功块缓存表

持久化的独立目的仅是跨重启复用已付费的成功转写，节省后续读取的费用与等待。由 Core 所有、用户级生命周期的媒体/ASR runtime 管理，同一表覆盖视频、纯音频和不同会话，命中仍经过本次源读取与访问检查，不从当前侧栏或活动会话取得权限。

一行只保存一块确认成功的转写，不保存 pending/running/failed 状态：

| 字段 | 含义 |
| --- | --- |
| `id` | 在成功块创建边界通过共享 derive_id，以访问域、媒体版本及有效范围稳定派生；增加明确的 `asr-cache` kind，不包含 ASR 配置，不自行拼路径 ID 或编写散列生成器 |
| `memory_domain_id` | 复用既有访问域，不跨域复用；不关联 session，ASR 连接变化不产生新的访问域 |
| `source_path`、`source_modified_ns`、`source_size` | 已通过读取入口校验的规范路径、实际 st_mtime_ns 与 st_size；三者组成轻量媒体版本键，不区分音频表和视频表 |
| `provenance` | 实际 ASR endpoint、请求模型/返回模型版本（可取得时）、检测语言、选定源音轨与必要处理/时间对齐事实；仅作来源记录，不参与命中、ID、唯一约束或配置匹配，不包含密钥、秘密散列或单独配置 ID |
| `from`、`to` | 在原媒体时间轴上确实成功处理的有效半开区间，独立于有无讲话、首末词时刻及额外上下文 |
| `payload` | 原文、实际词/段时间戳、必要的音频请求范围/时间映射事实及已有范围级声音观察；保留原始粒度供后续精确筛选，不每词或每声音区间建一行 |
| `last_used_at` | 服务端记录的最近使用时间；成功块创建时设为当前时间，按第 9.4 节的实际使用动作刷新，仅用于人工清理，不参与缓存命中、ID 派生或唯一约束 |

媒体版本键只用于可清理缓存的等值匹配，不作为内容完整性证明；不保存 inode/device 或全文件哈希，不为源另外分配媒体 ID。路径、修改时间或大小变化即不沿用该缓存版本；移动/改名不自动跟踪。读取时核对当前事实，命中行 ID 不替代源校验或授权。

一次成功块在服务响应、时间戳/有效范围和源事实校验通过后，用独立短事务原子插入整行；文本与完成范围不能分开发布。访问域、媒体版本及相同有效范围的重复提交保留已有块、来源与 ID，即使重复提交使用不同模型也不覆盖原文；有效范围不同的块仍可独立保存并按第 9.1 节组合。必要唯一约束与范围查询索引直接放在这张表中，不包含识别配置，不另建身份映射或覆盖索引表。

缓存事务与会话 ToolResult 提交没有外键或事务绑定。成功空块可以入表；响应不完整、时间非法、源变化及尚未确认完成的范围不能入表。某块确认成功后可独立保存，不要求整次读取全部成功。缓存写入失败只记录现有诊断，不重发收费识别；已取得的有效结果继续走普通工具交付与必要 canonical 结算，不能因缓存失败伪造交付成功。缓存读取故障按既有数据库错误处理，不能冒充“查无缓存”；明确被清理或不存在的行才作为未命中。

缓存行被清理不影响已保存的会话工具结果，未完成远端工作也不因重启自动恢复或重试。这张表进入实施时的 clean-v0 基线和表类别验收；新增仅此一表，事件/subject/guard/relation/job 类别保持不变，不增加线上迁移兼容或双写路径。

### 9.4 一键清理与最近使用

用户级设置的 ASR 区域只提供一个“清理旧转写缓存”按钮。按钮旁沿用设置页说明样式，显示“清理超过 24 小时未使用的转写缓存。”不增加单文件清理、全部强制清空、时间选择器、模型清理工具或刷新参数，也不创建定时清理任务。按钮可在没有活动会话时使用，由 Core 所有的用户级缓存 owner 在当前用户可管理的访问域内执行，不依赖当前会话授权或侧栏选择。

“最近使用”按明确动作记录，不持久化“正在看”状态：

- 用户实际打开或重新激活该音视频的侧栏预览，经源读取与权限校验后刷新该媒体版本的使用时间。
- ROOT 实际开始 read_video_frames 或 read_transcript，经源校验后刷新；生成参数、排队、失败的访问请求不计使用。
- 新转写块成功写入时，以完成写入时的当前时间记录 last_used_at。

只刷新已有缓存行；尚无缓存时不创建占位媒体行或新表。读取/预览可刷新对应媒体版本的缓存行，清理时按 `(memory_domain_id, source_path, source_modified_ns, source_size)` 分组，以 `MAX(last_used_at)` 作为该版本的最后使用时间；即使只读了一个片段，也整份保留，不按各旧块的生成时间逐条删除。播放、暂停、拖动、逐帧更新、仅驻留标签、历史正文回读、批注重建与后台库存扫描不反复刷新时间。

点击按钮时取一次服务端当前时间，cutoff 为该时刻减 24 小时；仅删除整组最后使用时间严格早于 cutoff 的缓存。时间使用统一服务端时间口径保存/比较，等于 cutoff 时保留，不使用缓存创建时间或文件修改时间代替 last_used_at。该规则保护最近 24 小时内打开、读取或新生成缓存的媒体，不承诺仅因标签长期驻留而永久保留。清理不扫描磁盘、不重新探测媒体、不解码或发起 ASR，不新增清理实体、持久清理任务或另一张最近使用表。

最近使用刷新、成功块写入与清理删除通过现有缓存 owner 按实际顺序结算；删除时核对整组最后使用时间，不能先枚举过期候选、再无条件删除已经刷新或新写入的媒体。清理不取消在途识别，也不禁止正常回填：开始读取时刷新已有缓存，任务完成后新写入的块自然具有当前使用时间。无需清理 generation、墓碑或禁止回填状态。

清理成功时给出简短结果；没有合格旧缓存时说明“暂无可清理的旧转写缓存”。数据库失败报告真实失败，不假装清理成功。删除仅涉及 ASR 缓存及可丢弃派生索引，不改写原媒体、canonical 工具正文、图片或已提交批注。若旧 continuation 所需的缓存已被清理，沿第 4.2 节明确位置失效；原页面仍可通过 read_file 回读，后续显式读取只识别实际缺口。

## 10. 依赖与云端 ASR 设置

### 10.1 随包资源

三端媒体解码、探测、字幕解码和音频转换使用 PyAV 所带 FFmpeg 库，拼图使用已有 Pillow。用户不需要安装系统 ffmpeg、Python 或本地识别服务。

| 资源 | 交付方式 | 使用条件 |
| --- | --- | --- |
| 媒体处理与拼图依赖 | 随对应平台的 Pulsara 资源包提供 | 本地直接使用 |
| 云端 ASR 客户端适配 | 随应用提供 OpenAI 官方 Python SDK 与单一转写协议适配 | 用户配置后，仅在字幕不可用的转写兜底路径中补齐未缓存音频 |

Python 依赖通过 uv 锁定；发行检查完整传递依赖、原生库、许可与三端实际安装体积。播放器使用应用内原生 video/audio 播放内核与现有文件预览读取 owner，控制条和时间轴由 Pulsara 呈现，不引入额外播放器运行时。随包资源不含语音模型，运行时不下载识别权重。

### 10.2 OpenAI 转写协议、上传与客户端边界

首版只提供一个 OpenAI Transcriptions 协议适配，接受用户填写的完整请求地址，以 multipart/form-data 上传本次缺口所需音频。模型由用户配置，不硬编码首个供应商或默认模型，不建立供应商选择、协议切换、模型目录、路由或自动切供应商框架。配置地址可指向 OpenAI 或满足同一协议的服务，但协议名称不能代替时间戳、认证、限流和取消行为的实际验证。

复用 OpenAI 官方 Python SDK 的上传/编码与现有 HTTP/TLS/代理、凭据绑定客户端和响应资源边界。请求地址保留用户填写的完整路径，不重复拼接 /audio/transcriptions；需要完整地址时使用 SDK 的公开 POST 入口与 files 参数，SDK 仍负责 multipart 编码。固定请求 model、音频 file、response_format=verbose_json 及词/段时间戳；这些不是设置页或模型工具参数。音频使用运行时统一选定并验证的受支持格式，文件名扩展和 MIME 与实际字节一致；不上传视频画面、无关范围或公开音频 URL，不走 JSON/Base64 的第二条协议路径。

ASR 客户端通过公开 HTTP 请求 hook 做受控预读取：先核对已冻结音频输入、SDK 生成的编码长度与既有单次上传/内存准入，再调用 request.aread() 展开 SDK 生成的 multipart，校验实际长度后进入原 ProcessCredentialBoundary 检查与传输。输入音频只来自已有可取消物理执行路径准备的有界数据，不在主事件循环从任意长文件同步读入，也不对未知长度、未准入或任意流无界预读取。SDK 负责编码和字节重放，Pulsara 不复制 multipart 编码器或关闭流式凭据保护；文件内容、文件名、URL 及非凭据 header 中的秘密值仍须拒绝。失败、取消、超时、重定向和关闭均沿原 gate/客户端生命周期结算并释放资源。

响应按第 7.2 节识别实际 words/segments。服务须能返回可校验时间戳；只有普通 text 的模型不满足本功能，不通过 LLM、插值或隐藏的多次探测补救。音频/响应大小、并发/速率和计费粒度按实际接口验证后接入已有 admission；配额未知沿第 7.1 节串行排队。内部块长与格式可基准校准，不能改变每次累计最多新增 180 秒的产品边界，也不承诺宣传时延。

所有音频请求均受本次工具生命周期约束；不另起云端任务管理、跨重启查询或后台恢复路径。重试按第 10.4 节的受理事实决定；SDK 自动重试统一关闭，安全重试由同一适配入口按实际合同执行，避免叠加或未知受理状态下重复提交收费请求。不能承诺取消已接受的远端工作一定生效。

### 10.3 用户级 0–1 配置与连接测试

用户级「设置 → 模型」在「输入框建议」与「记忆检索」之间显示「ASR 配置」。标题沿用输入框建议样式，单条连接沿用模型配置行，编辑弹窗沿用 Embedding 的布局。设置由 LocalSettingsStore 读写，ASR 独立保存为一个可空配置值：未配置为 null，配置后只有一套 endpoint/model_id/api_key。它不挂到 memory_retrieval 或聊天模型列表，不复用记忆向量重建确认、模型路由或后台维护任务，不增加独立配置 ID 或额外启用开关。

设置页只要求三个输入字段：

| 字段 | 含义 |
| --- | --- |
| 请求地址 | 完整 OpenAI 兼容转写 URL，例如 https://api.openai.com/v1/audio/transcriptions；复用现有完整 endpoint 校验，保留实际路径 |
| 模型 ID | 用户填写的转写模型标识，不自动从聊天模型或模型目录推断 |
| API key | Bearer 密钥，复用现有秘密值保存和 keep/replace/clear 语义；同一端点编辑时留空保留，修改端点不自动携带旧凭据 |

提供配置/修改、删除配置和测试连接；删除模型配置与第 9.4 节的清理旧缓存是两个明确动作。没有配置时仍可读图、已有字幕和完整缓存，需要识别新缺口时才返回 ASR_NOT_CONFIGURED。保存只做本地字段与秘密值校验，不强制测试、不联网、不提交音频或重建缓存；保存完整配置后按需使用。修改/删除影响后续调用，已受理调用仍按冻结配置和原取消边界结算；缓存继续复用，不出现向量重建式的批准面板。语言由服务自动识别，不增加供应商、区域、协议、输出格式、并发或块长表单。

测试连接是用户显式触发的一次短语音上传，使用随包的固定已知语音和正式上传、凭据、响应校验路径。检查认证、非空原文与可校验词级或段级时间戳，简短反馈实际粒度和耗时；只成功返回文字或返回空文字不能显示为满足时间定位要求。测试不创建用户媒体缓存、批注或会话阅读状态，不自动再发其他格式请求，不持久化模型兼容性名单；失败保留具体原因，只清理实际秘密值。保存和普通配置读取不触发测试。

配置及清理按钮在没有活动会话时仍可用，由用户级设置/缓存 owner 提供读写与授权。复用现有 endpoint/凭据绑定、HTTP owner、ProcessCredentialBoundary 及精确秘密值清理；新 ASR 密钥加入现有 credential_scrub_set，公有配置仅呈现凭据是否已配置，不回传密钥。请求地址来自此配置，不直接借用 LLM/MCP 密钥，不通过环境变量、模型工具参数或任意请求头传递秘密。

设置卡片在标题下方说明“转写和连接测试会上传音频并可能计费。”，沿用「输入框建议」的说明样式。弹窗中的同一提示沿用 Embedding 弹窗的费用提示样式。已配置后的正常读取不逐段弹确认，凭据不进入工具结果、图片、临时文件名、缓存键、日志或 provider 历史。一次调用冻结配置，修改不改写缓存原文、已交付结果或 provider prefix。空闲时不发识别、连接测试或预取；Host 关闭时关闭客户端、取消本地请求/队列并结算。

### 10.4 超时、重试与远端受理状态

重试依据实际可确认的受理事实，不能仅凭一个异常名或 HTTP 状态码推断“没有收费”。选定服务接入时核实官方 SDK 的默认重试、请求阶段可观测能力、拒绝语义、Retry-After 及可选的请求查询/幂等支持；利用其配置和现有传输 owner 落地同一策略，不新增通用重试框架。

| 本次已确认情况 | 行为 |
| --- | --- |
| 连接建立失败，能够确认请求尚未发送 | 可在同次工具的现有处理期限内重试，沿用原取消与物理执行边界 |
| 服务明确拒绝且按已验证接口合同未受理，例如有该保证的限流 | 遵守服务等待指示、共享配额和现有处理期限后重试；不能只凭 429/5xx 通用地假定未受理 |
| 音频已开始发送、已发送完或无法确认发送阶段，随后超时/断连 | 默认不自动重新提交；报告“远端处理结果未知，可能已经计费”，保留失败范围，不将其记为已完成 |
| 服务支持且实际提供原请求查询能力或经过验证的幂等重试 | 在同次工具生命周期内复用原请求标识与服务能力，不另建收费任务；没有这项能力时按未知受理状态处理 |
| 缺配置、认证失败、非法参数或无效时间戳等不能靠相同请求解决的错误 | 返回明确原因，不自动重复提交相同识别 |

OpenRouter 官方转写端点明确返回 HTTP 429 和结构化限流错误时，工具在原期限内复用当前音频，按退避及服务的 Retry-After 等待后重试。上传次数逐次记录。其他端点仅凭 429 不能确认相同的拒绝及计费语义。[转写计费说明](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/) · [限流与 Retry-After](https://openrouter.ai/docs/api_reference/errors-and-debugging)

由同一 ASR 适配入口统一物理请求与重试策略；SDK 固定 max_retries=0，安全重试按已验证的受理事实在同次适配入口执行，不能与 SDK 各自重发。安全重试仍遵守第 4.2 节单次有效缺口累计 180 秒的范围和原 watchdog，不重置额度、添加新范围或在工具结束后后台继续；实际发送、等待、服务返回和可能费用如实保留诊断。取消/Host 关闭后不再提交重试，不为这项策略增加持久请求状态、跨重启查询或恢复作业。

部分块成功时照常缓存，未知或失败块仍为缺口；返回连续成功前缀并明确列出卡住的范围和原因，后部成功块可复用。错误不能被包装成普通分页完成或无提示的“复制 next 即可继续”：若提供续读位置，必须与失败事实同时交付；没有进展则明确失败，不用原地 next 诱导循环。模型后续显式重新读取是新一次工具操作，只补真实缺口；未知受理范围再次提交仍可能重复收费，不宣称服务端先前任务已取消或免费。

## 11. 工具面、图片交付与会话侧栏

### 11.1 权限、结果与 provider 历史

read_video_frames、read_transcript、annotate_media 仅对 ROOT 的直接工具调用开放。SUBAGENT 的 provider tools、可发现工具目录及 Code Mode 的目录与工具绑定均不包含它们；即使 Code Mode 由 ROOT 发起也不可调用。执行准入同时检查调用角色与入口，拒绝子代理、Code Mode 或其他间接工具调度入口对这三个工具的请求；不能只靠隐藏 schema 或提示词限制。筛选与校验复用现有 builtin 定义、工具面、Code Mode 目录筛选及执行准入 owner，不建立另一套视频执行路径。

两个读取工具沿用 filesystem/read-only 的文件目标权限；annotate_media 复用源读取校验与既有会话工具准入，将批注作为会话结果提交，不获得媒体或其他文件的写权限。read_transcript 的云端处理是第 10 节已配置服务的明确产品行为，仅可发送该次读取所需音频及必要边界上下文；不把文件读取扩成模型可指定任意 URL、请求头或脚本的联网能力。工具不改写源媒体，不安装依赖，不新增网络工具或逐段批准面板；内部媒体临时文件仍由现有执行 owner 管理。

read_video_frames 的 admission 对本页实际图片、完整索引与 next 联合 quote，同时执行共享完整外层文字预算，使用现有图片校验与绑定机制，按完整图文页接受或在提交前缩页/明确降档。不得先提交文字再丢弃超额图片。扩展已有 IMAGE_ATTACHMENT 的 FULL 交付规则，不新造成功凭证或同义事件。持久结果沿用 FrozenPromptContent/LLMImagePart → canonical image refs/blob → provider lowering；重读沿用 IMAGE_REF，不给 provider 添加视频协议。

选择策略为 `frames-v3`，旧策略 continuation 明确失效，不转换位置或兼容执行。新工具说明与 bundled Skill 只在下述已批准安装边界生效，不因实现更新重写既有前缀。模型历史的 SYSTEM、provider tools 和已有 messages 在同一 epoch 中保持不变。三个工具及 read_video_frames 的六参数 schema 只在 ROOT 的新 cold epoch 或明确采用的 compaction successor 安装到直接工具面，不安装到 SUBAGENT 或 Code Mode；设置变化、媒体发现、云端完成或播放器事件均不能触发额外 rebase，也不向历史插入后台进度。bundled 使用 Skill 教授阅读策略，物理并行、时间校验及缓存正确性必须由 runtime 保证，不依赖模型记住说明。

### 11.2 内置播放器与文件读取

在会话页现有侧栏中提供原媒体播放器、自定义时间轴与按数据展开的模型范围、批注视图，复用 InspectorPanel、DesktopWorkspace 和 FilePreviewPanel。顶部沿用脚本预览的工具栏，只放“从目录中打开”按钮，文件名由已有标签页呈现，不重复标题。选择文件复用现有文件选择/预览入口，不新增上传协议。播放控件顺序为后退五秒、播放/暂停、前进五秒；前后使用回转箭头，保持现有深色播放按钮和整体风格。

视频和纯音频共用同一播放器控制、预览时间轴、标签 Map、播放位置/音量/静音/倍速状态与批注布局；组件在现有 FileVideoContent 上适配为媒体共用实现，不另建平行音频播放器。视频保留画面区和全屏；纯音频用原生 audio 解码，呈现紧凑控制条、时间轴及按数据出现的批注，不保留黑色画面占位、视频比例约束、封面取帧或全屏按钮。音频首版不增加波形生成或大面积装饰封面，无批注时保持紧凑，有批注时将剩余空间用于完整正文。

模型 Markdown 中的本地链接、用户输入框与回复批注中的文件引用、文件浏览、媒体工具的呈现及 `pulsara-viz` 音视频的扩大入口，共用 FilePreviewProvider 的 prepare/adopt/release 与标签 Map。预览服务完成路径、读取作用域和源事实校验后，在当前会话中复用同一规范路径及 reading_root 的可用标签；批注按规范路径与文件修改时间关联。不按文件名、未经解析的 URL 字符串或临时 read_token 判断批注归属。普通打开已有标签时直接激活并保留播放位置，不重建播放器；围栏的显式扩大可按第 11.6 节携带当前位置。overview 等结果可原位补充模型范围与批注，后续工具状态更新不反复抢焦点、切文件或 seek。Map 仅作可丢弃的界面索引，不新增媒体注册表。

首次读取自动展示：在当前会话页生命周期内，主模型首次直接调用 read_video_frames（任意 mode）或 read_transcript 实际读取某个规范路径与文件修改时间对应的媒体时，经源与读取权限校验后，自动展开侧栏并激活对应媒体标签；允许这一次从用户正在查看的其他侧栏内容切换过来，已有标签仍复用。自动展示不触发播放或 seek：已有标签保留播放位置，新标签沿用普通预览的初始位置。

同一媒体的后续读取只覆盖模型范围并更新已提交批注；用户切换文件、收起侧栏或关闭标签后，不因后续读取再次自动打开或抢回焦点。首次展示状态仅属于当前会话页的可丢弃视图，不写数据库；页面重建不从历史调用或重连状态补发自动打开，只有新的实际读取可以触发首次展示。参数生成、排队、annotate_media、历史记录加载与普通媒体发布均不触发该行为。

显示由规范路径与文件修改时间对应的实际数据决定，不取决于从哪个入口打开：

- 只有普通文件预览时，显示媒体、播放控件与可拖动的预览轴，隐藏空的模型轨道、批注轨道、批注列表及其布局占位。
- read_video_frames 的 overview/detail/motion 或 read_transcript 实际开始读取时，才可写入模型范围；后续展示沿用当前工作 owner 的保留值；overview 是常见入口，不是展示分析的强制前置步骤。
- 只在存在已提交批注时显示批注轨道与列表；annotate_media 本身不制造模型阅读范围。读取工具结束后保留模型范围，当前 ROOT 工作回到 idle 或关闭时清空；已提交批注保留。
- 同一媒体已有可用批注时，从普通链接重新打开也保留这些记录；模型轨道只读取当前工作 owner 的范围，不以历史调用填充。当前工作尚未结束时，即使没有读取工具在执行也可显示其保留范围。不持久化“分析已启用”或“已 overview”开关。

批注以规范路径与文件修改时间为归属：两者相同即可关联已有批注，不按会话划分；修改时间变化或路径改变时不自动沿用旧批注。跨会话读取仍经过既有记录访问权限，会话用于原记录的访问边界，不为此新增全局标注库。切换会话不得把上一会话的模型活动标成当前事实；用户级 ASR 设置不依赖活动会话或预览选择。

播放器复用 descriptor-bound 文件预览 owner、权限/源变化检查、媒体类型与字节范围响应；现有 video 类型之外补齐 audio 文件识别、MIME、prepare/adopt/release 与渲染分支，文件链接和文件引用走同一入口。分别由原生 video/audio 元素负责解码、播放和 currentTime；通过 HTMLMediaElement 共用控制和清理能力，视频尺寸/封面/全屏保持视频专属。隐藏浏览器自带 controls，由 Pulsara 自定义控制条/时间轴操作标准播放 API，不复制媒体引擎。只给经过预览读取边界校验的源建立短期读取地址，不将 PATH 直接拼成任意 file:// 或绕过检查的本地 URL；每次 Range 读取仍校验源。只在可信侧栏与围栏的原生播放器位置允许所需媒体源，HTML 本地媒体访问遵守第 11.7 节的读取引用边界，脚本与宿主隔离保持不变。

音视频均在播放器容器隐藏、切换标签或页面隐藏时显式暂停，返回不自动继续播放；可见性观察挂在实际可见容器上，不能观察隐藏的 audio 元素。卸载时保存允许保留的临时播放状态，撤销可见性监听，暂停、清除 src/子 source、调用 load() 并释放所属读取引用。处理迟到的加载/seek/play、StrictMode 和源变化，不因共用实现重复释放另一处仍使用的引用；隐藏或关闭播放器不取消模型工具、不发 steer 或 ASR。

播放、暂停、拖动、倍速、音量和字幕显示由用户预览控制。源媒体时间与工具索引使用同一时间轴；长媒体支持按需 Range seek，不整片载入 renderer 内存。原生播放器不支持的容器/codec 明确显示预览不支持，不把它误报成媒体工具不能解码，不自动全片转码或另建媒体流服务。三端发行验收冻结实际支持矩阵；首版必须有共同可用的常见样例。关闭预览撤销其读取资源与临时界面引用，关闭侧栏或丢弃 Map 均不取消模型任务。

用户可从工具时间索引定位原媒体，查看已交付的分镜、detail 大图和 motion 有序帧。播放器播放原媒体不意味着模型接收了原媒体或原音频，预览源失效也不破坏历史 canonical 图片/原文。不给用户展示 Base64、内部缓存说明或灰色小字教程。

### 11.3 预览、模型阅读与 steer

| 动作 | 用户预览 | 模型阅读与 ASR |
| --- | --- | --- |
| 播放、暂停、seek、倍速或点击时间索引 | 只改变本地播放状态/位置 | 不发送 steer，不改工具参数，不发识别或预取 |
| 打开、关闭或切换预览文件 | 打开/撤销对应预览资源 | 不启动、停止或切换模型任务 |
| 模型实际开始读取某个范围 | 主模型首次读取该媒体时按第 11.2 节自动打开并允许切换侧栏；覆盖对应媒体的 0–1 个模型阅读范围，不移动用户播放头，后续读取不抢焦点 | 仅按 ROOT 的实际工具请求执行；read_transcript 才可触发 ASR 补缺口 |
| 模型追加批注 | 在对应源的时间轴/列表显示已提交记录 | 不启动识别、移动播放头或改变阅读范围 |
| 用户通过既有输入框发送 steer | 可继续独立预览 | 由既有 steer/安全点/取消语义交给模型，再由模型选择新范围 |

不得用 media.currentTime、暂停、拖动频率、播放结束或可见标签页推断用户指令，也不要求用户播放位置与模型范围同步。预览头与模型轨道分别呈现，用户手动预览时不被模型下一次调用强行拖回；点击模型范围仅定位用户预览。steer 后是否 overview、回看或直接读字由新要求决定，overview 本身不启动 ASR；新的 read_transcript 请求同步补齐新位置缺口。

同一规范媒体路径与文件修改时间的模型轨道只有 `activeSpan | null`，表示当前 ROOT 工作的最近阅读落点，不等于“工具正在执行”。两个读取工具经源与权限校验、实际开始读取并确定本次处理窗口时，覆盖该媒体的范围；参数生成、排队、校验失败、历史加载、annotate_media 和普通播放均不更新。read_transcript 的总请求可为一小时，显示仍使用本次实际窗口，不把未执行的整小时请求画成阅读范围；处理范围与已交付文字位置按第 5 节分别表达。overview 和 detail 在验证窗口后、准备稳定观察计划前发布范围。motion 在确定首帧可见区间时发布首个前缀，最终按本次实际可交付的前缀更新。overview 的全范围仍是稀疏观察，不表示逐帧看完全片。界面保持“模型”轨道，不增加“正在读取”状态文案、百分比或连续模型播放头。

工具成功返回后范围保留，模型理解结果、回复、调用其他工具或等待用户批准/回答时均保留；单次读取失败或取消本身也不回滚已展示的阅读落点，不据此声称已成功取证。下一次实际读取覆盖。若有并行读取，按现有执行开始顺序使用最近开始的一次，关联现有调用身份；较早调用的迟到更新、成功、失败或取消不得覆盖或清除较新的范围，较新调用结束后也不回退到较早范围。不串行化工具，不按内部 ASR 子块完成顺序改变范围。

清理边界与 TODO 相同：当前 ROOT 工作完成、用户停止或终止失败并回到 idle 时，统一清空该工作的全部媒体范围；工作关闭或 owner 丢失时丢弃。同一工作的内部 turn 延续、等待用户决定和上下文压缩不清空，不以单次工具结束、final 文本块到达或 DOM 卸载判断工作结束。源失效时删除该源对应项；切换会话只展示所选会话 owner 的当前值，不泄露上一会话的范围。关闭媒体标签或收起侧栏不清空运行时范围、不取消工具，重新打开时可读取仍存活工作的当前值，不因此自动抢回焦点。

复用 TODO 链路的具体边界：

- 将现有 TODO owner 的 ROOT 工作生命周期部分整理为共同的进程内状态承载，TODO 清单和媒体范围分别存放；媒体范围为按规范路径与文件修改时间索引的 Map。共用已有工作/调用身份和开始顺序，不新建媒体 ID、工作 ID、注册表或第二套生命周期状态机。
- Host 的现有工作激活、continuation 绑定、idle 结算与关闭入口同时管理两种内容，包括正常结束、停止、失败和关闭。播放器只消费投影，不自行监听 final 或推断 turn 结束；旧工作迟到的回调不得写入或清空新工作。
- 扩展现有 `SessionLiveControlSnapshot`，在同一当前工作快照中分别返回 TODO 与媒体范围；共用 gateway、runtime-adapter 的读取、刷新、断连和重连链路，最终把对应范围传给播放器已有 activeSpan 属性。将原 TODO 专用快照失效通知扩展为当前工作快照失效通知，替换原通知及消费者；一次通知刷新当前快照，不新增平行事件类别、不借 TODO 条目或 payload 伪装媒体更新、不建立第二条轮询/推送通道。现有 TODO 提交后的通知也走这条单一路径。
- TODO 的准备替换、工具结果提交和清单安装结算仍只服务 TODO；媒体范围是实际读取触发的可丢弃观察，不复制这些结算 token、回执或持久提交机制，也不把媒体范围注入模型上下文或 compaction 提示词。
- 断连时前端清空无法核实的范围；连接恢复或页面刷新后只向同一个仍存活 owner 读取当前快照，允许恢复其中保留的阅读落点，不要求读取工具仍在执行。owner 已丢失、工作已 idle 或源已失效时不恢复，不从会话历史、ASR 缓存或已完成工具结果重建。快照与通知缺口处理复用现有同步边界，迟到通知不得使已清空范围复活。

上述状态只属于当前工作进程内 owner，不存数据库、不新增 durable event、live event 类别或恢复作业。历史读取范围与画面继续作为原工具结果中的证据；保留的模型范围不证明观察覆盖、工具成功或模型理解程度。

洞察由主模型明确提供：需留在时间轴的内容用 annotate_media 提交，普通会话回复不自动猜测或抽取成已提交批注。读取工具只提供证据，批注工具只校验并提交正文，都不在内部另调 LLM 总结。章节尚未结束时模型可以继续读而保持沉默，侧栏保留当前工作的最近阅读落点；不设置发言配额或定时唤醒。detail 对照标签保持中性，motion 显示实际 dt、采样与切点限制；这些证据同时进入模型结果，不能只存在于界面。

### 11.4 自定义时间轴与追加式批注

同一时间轴使用原媒体秒数，分别呈现可拖动的用户播放头、0–1 个当前工作的模型阅读范围与已提交批注区间；对应轨道按第 11.2 节有数据才显示。使用分层轨道/不同形状与“预览／模型／批注”标签，不把三者画成同一条已读进度，批注也不是观察覆盖证明。横坐标由时间与当前显示尺度推导，窗口缩放后重新计算，不保存像素坐标或把拖拽误差写回已提交批注时间。

时间轴仅保留轨道与刻度，不设额外标题或模型状态横条。批注轨道的编号与条带边框对齐，各批注行的垂直净间距与模型范围至首行批注的间距一致，原型为 8px。点击时间轴中非预览轴、非模型范围、非批注按钮的空白，或按 Escape，取消批注选中；不 seek、不发 steer。

播放头拖拽和键盘调整只更新用户预览，反映 media 元素实际 seek/loading 状态，不能声称尚未加载的位置已经播到。时间轴保留可聚焦控件、键盘操作、可访问名称和明确时间值，优先复用成熟 slider 基础能力，不手写一套拖拽/键盘协议。时长未知时显示已知事实，不伪造全片比例或可拖动终点。

已提交批注在时间轴上用区间/编号标记，完整正文位于旁边或下方独立滚动列表；点击条目高亮其区间并定位用户预览。播放或 seek 使原生媒体的实际播放位置变化时，按 [from, to) 跟随当前位置选中批注，同步高亮时间轴与列表并将选中项滚入可见区域。当前位置仍在选中批注范围内时保留选中，离开其范围且进入另一条批注时才切换；空档保留上一条选中。需要新选一条时，优先包含当前位置且开始时间更靠后的批注，开始时间相同则沿用列表顺序。暂停原地不反复恢复用户已取消的选中；自动选中不 seek、不改变播放状态。选中仅用现有高亮呈现，不显示对号。显示规范路径与文件修改时间匹配、且当前用户可访问的全部批注，列表不设范围筛选、额外标题或计数栏。条目保持紧凑，仅呈现编号、时间与完整正文，不重复来源字样，不通过缩字、灰色小字或截断正文压低高度。重叠、极短或大量批注采用可选择的聚合标记与可分页/虚拟化列表，最小命中区域不改变真实 from/to；不设置批注总数上限，不以截断最近几条代替历史读取。

视频有批注时，容器宽度达到 953px 即采用左视频、右批注的双栏布局：640px 播放器保留 608px 画面宽度及完整控件/时间轴，300px 批注列保留正文阅读空间，中间分隔条为 13px。切换只取决于容器宽度，不受视频比例、批注数量、内容高度或分隔条位置影响；画面可以随可用宽度适当缩小。批注列默认占容器宽度的 30%、至少 300px；拖动时播放器不窄于 640px，批注列沿用 264px 最小宽度。窄于 953px 时采用上下布局，视频随侧栏变宽按原比例增高，只保留一条紧凑批注的最小阅读空间，不预扣固定多卡片高度锁住画面。两种布局都保持视频原比例，时间轴仍在视频下方，视频高度受播放器实际可用空间约束。保留可拖动分隔线，上下布局调高度、左右布局调宽度，支持键盘和双击恢复默认。切换布局复用同一个 video 和列表，不重载媒体、不重置播放位置或选中状态；不持久化排版比例。无批注的视频沿用单播放器布局；纯音频采用紧凑控制/时间轴加下方批注列表，不计算视频画面高度或显示空的画面分隔区，批注的选中、定位、间距和正文规则相同。

每条批注的展示数据仅来自结果及同次冻结参数：规范路径、文件修改时间、from、to、text；列表投影仅返回原结果身份、from、to 与 text。同一 canonical 结果重复加载不重复展示，新调用是新追加，不能用相同正文或时间散列静默去重。查看历史批注通过既有会话内容读取/分页机制筛选对应结果，不仅扫描当前 DOM 或客户端已加载的消息；投影可重建，不成为新持久权威。

批注跨多个读取窗口时仍是一条记录；文件修改时间变化后，旧批注保留在原工具记录中，不自动挂到当前媒体；不校正或重算旧记录。修改时间未变时仍沿用批注；原范围超出当前时长时保留正文，不改写时间或执行越界 seek。草稿可编辑/移除，已提交批注不提供独立改删或自动版本链。用户调整草稿范围或点击已提交批注都不构成 steer；只有明确通过现有输入框发送要求，才交给模型决定后续动作。不添加批注 CRUD API/模型工具或独立笔记数据库。

### 11.5 存储归属与可丢弃视图

读取与批注的参数/结果仍由现有会话存储 owner 写入数据库；媒体侧栏不是独立的持久化产品对象，不再保存一份。侧栏展示数据只分为原有会话事实与可丢弃视图；第 9.3 节的 ASR 成功块缓存独立用于范围复用，不成为侧栏或批注的真值：

| 内容 | 归属与生命周期 |
| --- | --- |
| 读取工具参数、成功/失败结果、实际处理范围及图片/文字证据 | 继续走现有会话工具记录、原结果正文与 canonical 图片内容的提交/保存路径 |
| 媒体时间段批注 | 是一次成功提交的 annotate_media 调用及其结果；正文/from/to 取冻结参数，规范路径与文件修改时间取同次正式结果，会话只记录来源，不保存另一份正文或独立实体 |
| 当前工作的模型阅读范围 activeSpan | 与 TODO 共用 ROOT 工作生命周期的进程内值；实际读取开始时覆盖，工具结束后保留，idle/关闭时清空；重连可读取存活 owner 的当前快照，不持久化、不从历史重建 |
| 标签 Map、批注列表与其编号布局、选中项、用户播放头、分隔比例 | 前端进程内视图，可随关闭、刷新、重启丢弃；Map 只索引已有标签和已核对来源，不承担记录或执行权威 |

关闭页面或清缓存不删除原来的工具调用记录，也不取消仍在运行的工具。重新打开可先播放媒体，再按需通过既有会话内容读取与分页机制重建批注；使用既有结果身份去重，不扫描当前 DOM 冒充完整历史，不仅展示最后几条。重建遇到分页/offload 或读取失败时保留既有读取边界和必要状态；尚未加载不等于没有历史批注，不阻塞普通播放，也不承诺启动时自动恢复整个分析现场。

侧栏和批注不新增数据库表、外键/独立关联、媒体旁 JSON、持久 Map、已读/已 overview 开关、开始/结束回执或恢复作业。重建只读取已提交内容，不重放工具、补做识别或唤醒模型。批注只按规范路径与文件修改时间归属；读取执行、媒体预览与 ASR 缓存沿用各自必要的源变化检查，不把这些检查升级成批注的持久身份体系。

### 11.6 `pulsara-viz` 音视频发布与图集

**发布与内容归属。** 围栏只在完成工具调用后的 final answer 发布，不放入 commentary、进度消息或含工具调用的回复。沿用每行一个本地路径的语法，可与 HTML、图片混排；声明顺序与逐项定位保持一致。音频作为渲染端支持格式接入，不向系统提示词或 bundled Skill 增加专门的音频发布说明、示例或听觉能力宣传，不增加围栏语法或音频模型输入协议。

音视频路径均为文件引用，原声明保留在已有会话消息中；不将二进制写入会话 blob、嵌入 HTML 或另建附件表。HTML、图片沿用冻结发布路径，音视频复用既有轻量路径引用、occurrence/blob 和文件预览 owner，不进入图片校验或 HTML 截图 worker。发布时只冻结已解析的规范路径引用，不保存媒体二进制或打开时的修改时间。路径解析/授权使用所属会话的文件上下文，不以当前激活会话重新解释历史相对路径；上下文不可用时明确失败。消息流式输出期间不提前加载媒体。

打开时读取当前文件，不承诺保存发布时的媒体版本。移动、删除、替换、格式不支持或失去访问权限时沿既有预览结果处理；同路径重新打开读取当前文件，按其修改时间关联批注。一次预览仍绑定已核对源，每次 Range 读取校验源变化，不混入不同版本。单项失败不阻塞图集其他条目。

**围栏与侧栏。** 视频使用原生 `<video controls playsinline>`，音频使用紧凑的原生 `<audio controls>`；均不自动播放。围栏采用原生进度条，不展示模型范围、自定义分析时间轴或批注列表。地址来自现有短期预览服务，不直接读取任意 file:// 或远程 URL；HTML 的本地媒体另按第 11.7 节绑定受限目录引用。

右上角沿用“扩大”图标。点击后暂停围栏，将实际播放位置交给共用文件入口；已有同源标签就激活并定位，否则准备后定位，均保持暂停。没有有效位置时保留已有标签位置或新标签默认值。侧栏按规范路径与文件修改时间显示可访问批注；模型范围只来自当前 ROOT 工作 owner 的保留值，与围栏发布来源或是否显示分析无关。关闭侧栏不恢复围栏播放，两处仅在显式扩大时交接位置，不持续同步。

视频与音频均可在扩大后显示先前成功提交的 annotate_media 批注；当前 ROOT 工作尚未 idle 时可显示其保留的模型范围，工作回到 idle 后不因扩大或 final 内容重建范围。发布/播放不触发 read_video_frames、read_transcript、ASR 或 steer，不把原音频送入 LLM，也不能据此声称模型已经听过。批注仍只按规范路径与文件修改时间关联，沿原访问域校验，不新增媒体 ID、内容指纹或发布与工具调用的专用关系。

**图集缩略图。** 视频默认取第 1 秒实际可解码画面；不足 2 秒取中点，未知时长取首个可解码画面。中央叠加半透明深色圆底与白色播放三角；仅作封面采样，不扫描全片选最佳画面。进入可视区域后沿现有缩略图队列、取消与读取引用异步生成，等待/失败时保留视频占位；单次操作沿现有 30 秒期限，不限制图集总量。封面仅在当前预览生命周期按规范路径、修改时间和尺寸复用，重新加载后重建，可暂时陈旧；失败不阻止主播放器独立尝试。

音频缩略项仅使用静态音频图标和文件名，不抽帧、提取封面、生成波形或为缩略图解码音频。音视频缩略项点击都只切换条目，由主控件开始播放；音频不占视频比例黑框或显示全屏按钮。

**生命周期。** 浏览器负责解码、缓冲和播放；Pulsara 负责读取授权、可见性、取消和释放。共用 HTMLMediaElement 控制/清理能力，不新增播放器框架、全局互斥播放服务或实例总量上限。

| 时机 | 行为 |
| --- | --- |
| 首次进入可视区域 | 按需取得预览引用，preload 为 metadata，不整片载入 renderer |
| 滚出视口、切图集条目、标签隐藏或页面隐藏 | 显式暂停，重新可见后保持暂停；音频观察实际可见容器，不观察隐藏 audio 元素 |
| 淘汰、卸载、切会话、关标签或源变化 | 中止所属读取，暂停、清 src/子 source、调用 load()，释放所属引用与 Blob URL |
| 视频封面提取完成、失败或取消 | 立即释放临时解码元素和读取引用，不保留后台播放器 |

覆盖加载/seek/play 迟到结果、快速切换和 React StrictMode 重复 setup/cleanup；过期结果不复活已关闭视图。围栏、封面和侧栏各自释放自己的引用，不撤销另一处仍使用的资源；卸载允许丢弃播放位置等临时状态。关闭展示不取消模型工具，任何展示操作都不重写 provider 历史。

### 11.7 HTML 布局快照与当前本地媒体

HTML 发布保存布局、内联逻辑及已声明的本地 CSS/JS 快照；外部图片、视频、音频及 poster 保留本地引用，不将媒体二进制打包进 HTML。原生图片条目的冻结规则不变。新 HTML 展示项在既有 blob 中保存规范源路径与 HTML 的轻量 JSON 快照，保留原 source filename、ordinal 与 occurrence 所有权，不增加数据库结构或发布事件。

显示时由现有文件预览 owner 分配一个临时目录读取引用：项目内 HTML 以所属项目目录为资源根，项目外文件以所在目录为根。不要求原 HTML 文件仍存在，不因其后续修改改变已保存布局。html5lib/tinycss2 继续处理 HTML/CSS；声明式媒体 URL 在发布时规范化，在显示时绑定到该读取引用；可信 base URL 让 JavaScript 动态设置的相对 src 按原 HTML 位置解析，无需改写 JavaScript 字符串。

仅允许相应读取引用下的本地媒体请求；继续使用目录描述符、no-follow、类型检查与 Range 读取。允许项目内的 .pulsara 等普通隐藏目录，仍拒绝点/双点路径段和越出资源根的访问。目录被移除、读取引用被撤销或媒体变化时沿现有错误路径处理；音视频同一读取引用内的跨 Range 源一致性仍须核对，不混入不同版本。标注关联仍只用规范路径与修改时间。

HTML 的 img-src、media-src 和 base-uri 只加入该次资源前缀；脚本、网络连接、frame、表单和宿主访问不随之开放。已有已发布的原始 HTML 快照可从原消息围栏取得其来源路径并接入相同目录通道，不改写历史正文或已保存字节；无来源路径的独立 HTML 快照仍可自包含展示。资源目录不可用时保留布局并显示正常正文状态，不使用灰色小字。

目录引用复用 FilePreviews 的分配/撤销与连接生命周期。快照绑定请求复用 canonical blob 的 16 MiB 上限，单次资源准备沿既有缩略图的 30 秒期限，不改变其他请求或图集总量边界。HTML 内的原生媒体隐藏时暂停，返回保持暂停；弹窗移除媒体、frame 卸载或目录引用撤销时释放读取与解码资源。普通文件 HTML 预览使用相同的受限本地媒体规则。桌面全屏只允许当前工作台主 frame 的用户触发请求，其他权限与外部网页隔离保持原边界。

## 12. 错误契约

| 类别 | 必须区分的情况 |
| --- | --- |
| 输入 | INVALID_ARGUMENTS、INVALID_RANGE、INVALID_CROP；continuation 结构/位置无效或定位数据失效分别明确说明，不静默从头开始 |
| 文件 | MEDIA_NOT_FOUND、MEDIA_SOURCE_CHANGED、MEDIA_FORMAT_UNSUPPORTED、MEDIA_DECODE_FAILED |
| 流与时间边界 | NO_VIDEO_TRACK；没有可读文字字幕且无音轨时 NO_AUDIO_TRACK；批注无法确认上界时 MEDIA_DURATION_UNKNOWN |
| ASR 配置与认证 | ASR_NOT_CONFIGURED、ASR_AUTH_FAILED |
| 云服务 | ASR_SERVICE_UNAVAILABLE、ASR_RATE_LIMITED、ASR_RESPONSE_INVALID、ASR_FAILED；超时/断连区分已确认未发送、明确拒绝与远端受理/结果未知，保留失败范围、实际原因及可能计费说明，不将未知结果记作成功覆盖 |
| 图片与资源 | MODEL_IMAGE_INPUT_UNSUPPORTED、现有图片/工具资源边界、处理期限到达 |
| 播放器 | 沿用文件预览的不支持、失效、访问拒绝和源变化错误；与模型解码/识别失败分开 |

成功读取但没有文字是正常结果，不与缺配置、失败或未处理范围混淆。成功处理但没有识别到讲话可以是空原文；部分块失败不能返回“全片没有台词”。有连续成功前缀时可按第 5 节返回 partial、实际范围、缺口及 next；无可交付进展时明确失败。请求尚在排队、被取消和远端限流是不同状态，不能用反复相同 next 诱导模型轮询。原始错误保留可诊断上下文，仅清理实际凭据，不整段抹掉输入、文字或服务返回体。

## 14. 验收

1. schema 严格为 6/4/4 个顶层字段：read_video_frames 为 target/from/to/mode/crop/continuation，read_transcript 为 target/from/to/continuation，annotate_media 为必填 target/from/to/text。read_video_frames 只有 overview/detail/motion，无独立探测工具、元数据 mode 或查询 action；拒绝 read_transcript 的 query/offset，以及 source、并发/块长、预热、批注 CRUD 等额外参数，无旧别名。默认值、有限数字、半开范围、crop 与关闭字段校验一致，三个工具仅供 ROOT 直接调用。SUBAGENT 的 provider tools、可发现目录以及 Code Mode 的目录与工具绑定均不含这三个工具；验证子代理伪造直接请求、ROOT 发起的 Code Mode 调用及其他间接调度请求均在执行准入拒绝，不解码、不发 ASR、不提交批注或触发侧栏。
2. overview/detail/motion 均不附全片基础元信息块；读字只给范围/来源/完成情况，批注模型正文只给添加状态，正式结果分别保留读取源事实或批注的规范路径与文件修改时间。验证默认结果没有完整流列表、容器/编码、原始帧率或客户端配置，必要的图像几何、时间与覆盖限制不丢失。各工具自行探测，无强制前置调用，不因元信息触发全片解码或云端探测；只有 read_transcript 缺口可发 ASR，读图/批注/播放器及字幕或转写缓存命中不联网。无图片能力仍可读字/批注，read_video_frames 提前明确失败；无 metadata-only 成功、跨范围预取或本地识别权重下载。
3. 使用自制、带时间真值的横屏、竖屏、VFR、非零起点、多流、静态长镜头、快剪、短暂状态变化和含文字视频，核对帧时刻、旋转、坐标、字幕与音频时间。seek 预滚不交付范围外画面；边界帧返回真实 t 与 visible_range，不伪造请求起点。
4. DP 用小规模穷举 oracle 验证候选集内最高得分；验证允许尺寸、原顺序、无变形、整数取整、零重叠、回溯面积与页数。包含 [1,1,1,1]、混合档位和分页案例，不只检查满铺度。
5. 时间索引逐项对应实际图片、cell_rect、t、dt、代表区间、crop 及当前页顺序；overview 跨页遍历为固定覆盖优先顺序，不假称全局时间递增。稀疏跳采、未知切点、格子大小不能变成连续/完整覆盖；全范围 overview 保有代表性，静态机位中的局部 UI 变化不因没有切点整体消失。
6. motion 对有真值的短片段提供开始/过程/结束的有序采样；同预算缩小范围可提高密度。测试快速闪现、切点、非均匀采样、长范围 partial 与 next，确认结束状态没有越界冒认。图片与索引真实进入 provider。
7. detail 验证显式范围、恰好两秒、小数边界和超限工具提醒；核对首中尾、strict-before、同源合并、VFR、延迟视频起点/音频尾、有限计划续读和预算缩页。验证原片清晰渲染、crop、不同源时间的页内 exact RGB 共享、源变化和压缩后原图/索引交付。用修订规范第 9 节替换原 detail 格点测试。
8. 验证可用内嵌文字字幕优先，即使存在转写缓存也读取字幕；字幕间空白、请求范围无字幕条目均正常返回，不混入缓存台词、不发 ASR。没有可用文字字幕、仅有位图字幕或字幕解码失败时，先复用转写缓存，只对音频处理缺口触发云端 ASR；分别验证缺服务、无音轨、ASR 成功/失败、空原文和文字分页。工具无 source 输入参数或强制 ASR action，返回来源准确；字幕与讲话故意不一致时仍保留原文与来源，不声称核对了原声，转写命中不成为画面事件结论，未处理范围不能被推断为不存在文字。
9. 区间缓存验证第 9.1 节全部案例：180–360 三块完成后，150–210 只补逻辑缺口 150–180；220–280 跨块零新增请求；330–390 只补 360–390；150–390 同时得到前后两个缺口；存在中间洞时只补该洞。查询多行即可组合命中，不依赖某一行包含请求。验证相邻/重叠并集、不吞未处理空隙、不改写旧正文行、不额外持久化合并范围。成功空块计入覆盖，失败/取消/进行中块不计入，不按首末句跨度或宽松容差伪造完整。
10. 视频与纯音频使用同一缓存表。规范路径、mtime_ns 或文件大小变化不沿用旧版本；访问域不同不互相命中。ASR 请求地址、模型/版本及内部处理/对齐设置改变均继续复用已有块，来源记录保持真实；这些值不参与查找、ID 派生或唯一约束。模型 A 完成 180–360 后换 B，200–300 零新增请求，330–390 仅由 B 处理 360–390；在途工作也不因设置变化重复提交。每次命中仍检查访问与源事实，源音轨选择不受模型变化影响。进程重启可复用成功块；一键清理实际删除的旧媒体范围允许重识别，最近使用媒体保留，历史原文和批注仍可读。改名/移动不自动跟踪，播放器/批注仍只按路径与修改时间归属；跨来源拼接不改写已交付前缀。
11. 内部并行验证服务配额在多个工具调用间共享、未知额度串行排队、重复缺口复用、乱序完成后归位、部分失败缺口和限流。例 180–240/240–300/300–360 的时间戳正确加回原媒体；不能仅用 mock 宣称实际云端并发和提速已通过。
12. 跨句边界、上下文重叠、句/词级时间、切点两侧不同识别、真实重复发言与无讲话样例验证合并。有 words 而仅一个整块 segment 时，可自动整理可读小段且保留底层词级时间，不另调 LLM；只有 segments 时保留真实粒度。验证从多个缓存块按具体 from/to 筛选原文；句级原文保留实际起止和 visible_range，不伪造裁短时间或按字数均摊；已有有效原文不因新缓存覆盖被改写。
13. 长范围同步部分返回、文字分页、长正文共享读取、极小 allowance、源变化、取消和 Host 关闭均验证。排队及时撤销、流/worker 正确结算、无后台下一段；取消一个等待方不误杀其他调用。只发布确认完成的范围，无进展返回明确边界/失败，不循环相同 next。
14. 用户级 ASR 设置在无活动会话时仍能读取/编辑；独立 0–1 配置、固定 OpenAI 协议和 endpoint/model_id/API key 三字段，冻结设置只影响后续调用。缺配置、认证、网络、限流、非法时间戳、超量/不完整响应保留真实诊断，仅清理实际秘密值；endpoint 变化不携带旧凭据，凭据不进模型历史、缓存键或报告。
15. 验证 Markdown 本地链接、输入框/回复批注文件引用、文件浏览和工具呈现共用预览入口；同会话经校验的同路径复用已有标签，保留播放位置。主模型首次直接调用读取工具实际读取该媒体时自动展开侧栏并允许切换已有内容，含任意读图 mode 与直接读字；已有标签不重建、不自动播放或 seek。后续读取不抢焦点、不重新打开用户关闭的标签/侧栏，排队、历史加载与重连不补发自动打开；首次展示状态可丢弃且不持久化。同路径且修改时间相同可跨会话关联可访问的批注，修改时间变化或改名/移动不自动关联。无分析数据时只显示普通播放器，模型轨道与批注区域分别按实际数据出现或隐藏，不要求先 overview。播放、暂停、拖动、键盘、倍速、结束、关闭面板、切文件和点击批注均不发 steer 或 ASR；显式 steer 沿原安全点/取消边界送达。核对实际 seek/loading、可访问名称/时间值、源权限和 Range 读取；用户预览不被后续后台更新抢走，overview 不变成完整已读进度。
16. 同规范媒体路径与文件修改时间的 activeSpan 仅为 0–1。验证源/权限通过且实际读取开始才覆盖，排队、参数生成、校验失败和历史加载不更新；工具成功/失败/取消结束后保留，模型后续思考、其他工具、等待用户批准/回答、内部 continuation 和 compaction 均不清空。并行 A/B 按实际开始顺序覆盖，A 的迟到更新/结束不影响 B，B 结束不回退 A；不串行化工具。与 TODO 共用 Host 激活/延续/idle/关闭入口，正常完成、停止或终止失败回到 idle 时同时清空全部媒体范围，旧工作迟到回调不能影响新工作；源失效只移除对应项，owner 丢失则丢弃。前端断连清空，刷新/重连可从同一存活 owner 快照恢复已保留范围，即使读取工具已返回；idle 后、owner 丢失后及历史回读均不能恢复。验证共用 live-control 快照、失效通知和缺口刷新，TODO 替换/提交仍只沿原结算机制，媒体更新不伪装 TODO、不新增独立通道或事件类别；清单和范围更新互不覆盖，迟到通知不复活已清状态。provider prefix、原 view_image、文件读取、Code Mode、SUBAGENT、原文件预览和工具结果回归通过；仅增加第 9.3 节的一张 ASR 缓存表及其共享 ID kind，事件/subject/guard/relation/job 类别不增加，不新增媒体/批注外键或持久 Map，不通过后台消息改写 provider 历史。
17. macOS、Ubuntu、WSL2 的实际安装包在无用户 Python/ffmpeg、离线新目录下验证抽帧、字幕及原生播放内核＋自定义时间轴共同样例；明确播放内核和媒体 SDK 各自的支持矩阵，预览不支持不冒充模型工具不能解码。本功能不引入本地识别引擎/权重；记录安装体积，macOS 应用及 DMG 副本严格递归签名通过。
18. 固定视频、问题、模型与资源预算，对比均匀选帧、严格 1fps 和本规格固定相邻观测组计划；另用同组帧比较网格与 DP。按讲座、录屏、动作、叙事分组记录事实正确率、定位、误选、无依据结论、全量 token、调用数和端到端延迟。加入只需视觉、字幕/旁白与画面不一致、跨窗口同章节保持沉默与用户 steer 的任务；不凭图少宣布理解提升。云端另测串行/并行、冷/热缓存、重叠补缺口、首段可用时间及总耗时 P50/P95、时间戳偏差、中英文识别质量、实际上传量/计费和失败率；据此冻结服务、块长与并发默认。
19. 选帧基准覆盖全局硬切、渐变、持续运动、小区域短暂变化、完全静止、A→B→A、模糊翻页和噪声。连续输入验证局部、累计及短暂往返候选；稀疏锚点/扫描缺口不能产生虚构积分或精确切点，VFR 使用真实时间。预算变化不改变已定计划；detail 的全部选定源观察、motion 骨架和中间观察可跨页且不得省略。motion 短暂往返按第 14.1 节验收，分别记录采样漏检与采到后被删的情况，不将 DSH 默认值或单次合成实验当作通用准确率。
20. annotate_media 对视频与纯音频均验证四项必填、非空白正文、媒体/源权限、越界/未知时长、跨阅读窗口的单条批注和无隐式媒体/云端操作；无视频轨不妨碍音频批注。仅成功提交的调用/结果产生批注，正文/范围/规范路径/文件修改时间只有原工具记录这一份真值，不增加其他文件身份字段。丢弃侧栏 Map、清媒体缓存、重开会话及结果分页/offload 后，可通过既有内容读取按需重建；未加载不误报无历史，不要求启动全量恢复，不重放工具或补发 ASR。重复加载按原结果身份去重，独立新调用不按正文去重。验证同路径同修改时间跨会话关联、修改时间变化不沿用、旧范围超界不改写/越界 seek、改名不跟随、跨会话访问权限、重叠/极短/大量批注、分页、草稿改删及已提交记录只追加，无批注总量上限或独立笔记库。
21. 视觉验收沿用 gallery 的已定交互：顶部单按钮工具栏与标签文件名，后退五秒/播放暂停/前进五秒及原深色按钮；紧凑时间轴和对齐编号，批注行间距与模型至首行间距一致；全部批注直接展示，无范围筛选/额外标题计数/重复来源字样。验证空白点击和 Escape 仅取消选中，正文完整可读、无灰色小字；窄栏视频按比例增高、宽栏批注右置、分隔线与键盘可用，切换布局保留 video、位置与选中，临时视图丢失不影响原工具记录。
22. 围栏只在工具调用结束后的 final answer 发布；混排 HTML、图片、视频时顺序与定位正确，视频不走图片冻结/HTML 截图，不将二进制写入会话存储，流式阶段不加载。HTML 布局与代码保持快照，引用的本地媒体读取当前文件；验证受限目录绑定、动态图片/视频相对路径、原 HTML 修改或删除、媒体替换、源权限、Range 校验与单项失败。CSP 仅允许第 11.7 节的媒体读取前缀，其他脚本、网络与宿主隔离边界保持既有规则；隐藏暂停、移除清源、卸载撤销目录引用，主工作台视频全屏可用，子 frame 与其他权限不放开。
23. 围栏原生控件不展示分析轨道；扩大暂停围栏、携带实际位置并复用侧栏标签，不自动播放或持续同步。已有同路径同修改时间的可访问批注能显示，跨 turn/会话可重建，修改时间变化或路径不同不自动关联；当前工作未 idle 时扩大可显示其保留范围，idle 后扩大或重新打开 final 均不从历史恢复范围。所有展示操作均无隐式工具调用、ASR 或 steer。
24. 封面验证第 1 秒、短片中点、未知时长、无法解码、源变化与播放标识，点击只选条目。真实浏览器验证可见性懒加载、离屏暂停、返回不自动播放、驻留淘汰、切会话、卸载和 StrictMode；封面与主播放的取消/迟到结果、清源 load()、引用及 Blob URL 释放正确，不残留后台声音或互相撤销仍在使用的资源。
25. 对同一短片段比较三个 mode：静止时允许相同源帧且不复制；A→B→A 区分 overview 代表性、detail 清晰对照和 motion 过程保留。快剪、持续运动、局部频繁变化及模糊样例验证覆盖锚点、清晰度与时间骨架各自保留；motion 长范围部分返回及 next 真实推进，不静默退成 overview。detail 显式范围最多两秒、取首中尾，超限返回提醒；不做邻域锐度替换。overview/motion 保持原范围与分页合同，不新增模式、FPS 或帧数参数。
26. 真实数据库验证成功块整行原子提交、成功空块、部分成功、非法响应拒绝、重复提交沿用原块与 ID、不同访问域隔离及相交范围查询。模拟缓存写失败不得再次发起收费 ASR 或伪造 canonical 成功；缓存读失败不当作空缓存。缓存事务与会话提交无外键/事务绑定，清缓存不影响已交付正文、图片和批注。验证仅新增一张缓存表与共享 `asr-cache` kind，无逐词表、持久运行状态、合并范围表、任务/租约/收据或兼容双写。
27. 视频仅传 target 的默认 overview 交付稀疏画面，不附全片基础元信息块；显式指定 from/to 的 overview 同样遵循此合同。无音轨但有可用字幕时 read_transcript 正常返回字幕；两者都没有时 NO_AUDIO_TRACK 附无需继续调用的说明，无 ASR/配置要求或重复 next。有音轨但不能解码时报解码错误。静音、低音量人声、底噪、音乐、短音效、多声道相位抵消样例验证第 7.3 节：全段近乎静音、存在声音但 ASR 成功空文字、检测未知及 ASR 失败分别表达；不把音乐识别为已支持，不用空原文或平均音量推断静音，不因检测近乎静音跳过识别或伪造完成。字幕/缓存命中不额外解码；块级有声音不套用于任意子范围，实际声音观察只随原成功块保存，不新建表或状态机。
28. 纯音频从 Markdown 链接、输入框/批注文件引用及文件浏览打开时，共用源验证、Range、标签与播放器；read_transcript 可独立工作，read_video_frames 对无实际视频轨的源返回 NO_VIDEO_TRACK，即使文件带封面也不抽取伪视频帧。首次文字读取自动打开并允许切换一次，之后不抢焦点。音频没有黑色画面、全屏按钮、视频比例占位或波形任务，播放控制/时间轴/0–1 模型范围/批注与视频同语义，预览不发 steer 或 ASR。验证常见音频格式和三端支持矩阵，隐藏 audio 元素不误触暂停，可见容器隐藏/切标签/页面隐藏时暂停，返回不续播；卸载、源变化、迟到回调与 StrictMode 均释放所属引用/监听并清源 load()，不残留声音或误撤销其他视图资源。
29. 一小时无字幕、无缓存的源只传 target 时，首调用新增 ASR 的有效范围累计不超过 180 秒。验证多个缺口、并行 worker、内部多批、失败及连续空原文均不重置同次额度，预算/资源边界可提前停止；没有文字也按真实处理时间推进，不自动识别完整小时。已有 [180,360) 时请求 [150,600)，本次最多识别 [150,180) 与 [360,510)，中间缓存不占额度，剩余 [510,600) 由 next 推进。实际上传上下文、重试、费用与有效覆盖分别记录；180 秒不冒充服务等待或费用的绝对上限。
30. 已有全片字幕或转写缓存时按真实完整结果预算分页，一页允许覆盖超过 180 秒，不为填页启动 ASR；测试稀疏字幕、长静音和超长单条原文。已处理 180 秒但文字未交付完时，next 先交付剩余文字，不能重复识别或启动下一批来跳过未交付项。续读可在同时间条目、词/段与行内字符处前进，原文无遗漏，保留粗粒度真实时间；不按字符比例伪造更细时刻。正常页 page_complete=True，外层转义、控制事实及完整 next 纳入 ToolResultPageBudget.fits，不再套头尾摘要或第二层正文省略；最小分片放不下时明确边界，不跳项、不返回原地 next，不先提交可确定无法交付的收费请求。
31. 验证 read_transcript 仅接受 target/from/to/continuation：首次省略 continuation，拒绝 null/空对象/错误位置及旧 query/offset 参数。next 为包含 tool/arguments 的完整调用，保留规范目标、解析后的原请求范围和运行时位置，复制即可续读；同一 next 可重复观察，顺序使用各次新 next 时静态源无重漏。源版本/权限/字幕来源及定位数据失效分别校验，模型切换不使已有缓存或位置失效，不新增分页 ID/表/后台任务。read_file(SESSION_ENTRY) 只回读原页面，write_file(source=SESSION_ENTRY) 只复制原页字节，两者不触发 ASR 或取下一段字幕，也不把单页保存说成全片导出。next:null 的正常完成、失败与无音轨结果分别解释，停止续读不遗留识别工作。
32. 验证请求建立连接失败且确认未发送、按实际服务合同明确未受理的限流可在原调用期限内重试；未知发送阶段、上传中/上传后超时或断连默认不自动重新提交。不能仅凭通用 429/5xx 判断无费用；验证 Retry-After、配额、取消和 Host 关闭，SDK/外层不叠加重试，重试不重置同次 180 秒有效范围。经过验证的服务请求查询/幂等能力复用原请求且限于同次工具，不增加持久请求表或恢复任务。失败/未知范围不计成功缓存；部分成功保留，明确可能计费与失败位置，不以普通 next 隐藏错误或诱导原地重试。

34. 用户实际打开/重新激活预览、ROOT 实际开始两种读取、成功块写入才刷新使用时间；排队、无权限请求、播放/拖动/逐帧、仅驻留标签、历史回读、批注重建和后台扫描不保活，无缓存不创建占位行。并发刷新/写入与清理按原缓存 owner 顺序结算，删除前的新使用不能被旧候选误删；在途任务继续交付并以当前时间正常写缓存，不增加禁止回填、清理 generation、墓碑、定时任务或最近使用表。成功/无旧缓存/数据库失败均如实反馈，原媒体、会话正文和批注不变；旧 continuation 必要时明确失效，清理不会触发 ASR 或取消工具。

### 14.1 短暂往返的验收样例

本节验收 motion 连续过程；detail 另验首中尾采样边界，不要求添加 off-grid 状态。使用带真实 PTS 和状态真值的自制视频。例如 100fps 素材中 `[0,40ms)` 为 A、`[40,80ms)` 为 B、`[80,200ms)` 返回 A；这些数值仅为测试夹具，不作为运行时帧率、持续时间或视频范围限制。

| 样例 | 验收要求 |
| --- | --- |
| 实际扫描命中 A/B/A′且 allowance 足够 | 图片交付与 provider 输入均保留三态、顺序及真实 t/dt，不能只在内部诊断中出现 B |
| 稀疏探测仅在 0ms、100ms 命中 A/A | 不伪造 B 或精确转变时刻，不宣称已排除短暂变化；缩小范围并加密实际读取后，再验证可恢复原片中记录的 B |
| A→B、B→A 相邻等高，间隔短于突变去抖值 | 不能仅因相对尖峰条件或最小间隔不满足而抹掉已观测往返；中间 B 仍进入候选与预算足够的 motion 结果 |
| B 短暂且较模糊；两侧 A 像素完全相同 | B 不因锐度较低被 A 替换，A′不被跨状态去重删除；相同图片字节可共享，独立时间事实仍保留 |
| 图片预算足够与不足的对照 | 已选三态和时序骨架保持稳定；不足时跨页并明确 partial/next，拼接全部页仍包含 B；最小页不适配才返回边界，不返回 A/A 冒充完整往返 |
| 改变 B 持续时间、源帧率、探测间隔及采样相位，加入 VFR、完全静止和噪声对照 | 区分源未记录、探测未采到、特征漏检与采到后被删；记录 B 保留率、误报、实际采样间隔及资源成本，不宣称任意短 ABA 均可识别 |

### 取样与真实模型对照

本规格默认值及两轴场景档位按第 6 节实施，第 14.2 节规定相同预算的均匀、1fps 与新计划对照。hello 的实际 1454×818 比例在整数默认画布和两轴目标下导出 K=9、Q=17。当前生产 prepare/render 路径与严格 1fps 对照分别从 17、24 个候选选择九个代表，均输出一张 1278×720 图片；本地图片为 265,879、263,162 字节，索引为 2,599、1,917 字节。

真实固定图片对照采用同一画布、当前 K、问题与模型，两个回答都识别出图表/表格、文字与最终分栏，但细数字均有误读：新计划回答的首排为 40.3/1.8/3.8，严格 1fps 回答为 49.3/1.8/3.6；独立原帧为 49.3/1.9/3.8，单位为万/万/%。不将这两轮当作概览小字准确率通过或算法理解质量占优，原始错误回答完整保留。

一次独立自然读取先 overview 定位，再由模型选择 crop=[0.27,0.485,0.71,0.595]、from=0、to=0.5 的 detail。prompt 不提供目标数字，模型实际读出 49.3 万、1.9 万、3.8%，与独立解码原帧及原尺寸裁剪一致；模型同时说明其低清 overview 曾误读左卡，放大后才核清。该结果支持按需 detail/crop 路线，不保证任意小字或未采时刻均可恢复。运行时有并行后端工作，单次耗时仅保留在报告，不据此宣布性能优势。
