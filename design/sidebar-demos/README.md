### 生产路径对齐范围

- `runtime-adapter.ts` 的 `projectSubagentRuns()` 将子任务正文、思考、工具结果与补充消息组织为 activities；`attachSubagentRuns()` 按 `parentId` 归集到父轮次消息。它不是批次分组读取。
- `workbench-view.tsx` 的 `AssistantMessage` 先渲染 `execution-rail` / `TraceCard`，再渲染 `SubagentGroup` / `SubagentRunCard`。此前图形提案讨论过移走后者，但 PR03 不采用该主对话调整，两部分继续保留；只替换侧栏任务页，并统一获准的原始结果风格。
- `inspector-panel.tsx` 的分组优先使用 `batchId`，其定位操作原本滚动、展开并高亮主对话中的 `.subagent-run`。PR03 的侧栏任务详情改用精确批次/节点；root 主对话既有内容/定位不采用本 Demo 的替换提案。
- `UserMessage` 中的子任务完成接纳事件是另一类历史记录，不能因移动详情而一并删除。本次 fixtures 没有模拟这类事件，生产组件也未改动。
- 本次直接复用的是**桌面主对话区域**。外层导航、右侧组列表、图布局及节点对话仍是交互原型，不声称整页与生产一比一或生产功能已接入。独立 frame 未导入针对整个应用视口的 `responsive.css`，以免把桌面主对话列宽误当成手机视口。

```sh

```

脚本只写 `design/sidebar-demos/production-assets/`，不读取环境配置、不运行生产构建配置。

子任务工具展开摘要是本地提案，不是已有生产能力。当前 `TraceCard` 未导出且没有展开体的 renderer 注入点，因此预览构建脚本只在内存中替换这一处 JSX 展开入口，并导入 `subagent-tool-summary.tsx`；不复制整套卡片、不写入生产源码、不在运行时改 DOM。构建会检查入口恰好出现一次，生产结构改变时明确失败。普通工具仍走原有展开体。摘要仅识别两个精确 builtin 名称；成功结果按 `batch_id` 或 `task_id` 定位外层现有夹具，失败或无法解析时保留原始结果，不伪造成功摘要。

节点名称可以对接现有 kernel 字段：`create_agent_tasks.tasks[].label` 是可选的可读名称，允许中文，由派发任务的模型填写，保存后由 session controller 返回。单独调用 `spawn_agent` 的可选 `task_name` 只允许小写英文字母开头的英文、数字、下划线和连字符短名，内部会同时赋给 `task_key` 与 `label`。当前生产前端使用 `label || task_key || '子任务'`。本页名称仍是模拟数据，不是从实际任务生成或读取；无须为这些图节点另加命名机制。

## 三个方案

| 方案 | 布局 | 主要取舍 |
| --- | --- | --- |
| A · 常驻节点侧栏 | 主对话与任务依赖图并排；右侧切换子任务和命令 | 任务关系始终可见，但会挤压对话宽度 |
| B · 按需活动抽屉 | 平时只有右侧入口；点击打开任务或命令抽屉 | 对话空间更大，但详情会覆盖部分对话 |
| C · 独立运行工作区 | 对话／运行切换；大图、右侧详情、底部命令 | 更适合复杂协作，但不能同时阅读完整对话 |

顶部按钮切换方案，地址中的 `#a`、`#b`、`#c` 可直接选择初始方案。切换布局保留当前模拟状态；刷新或点击重置恢复初始数据。这只是布局比较，不冻结生产前端的图形、列表或抽屉方案。

## 可以体验什么

- 点击节点或任务卡片，查看目标、依赖、输出和关联命令。
- 模拟取消任务：显示收尾过程和依赖受阻；其他任务与后台命令不被自动取消。演示中的依赖变化由本地夹具模拟，生产实现仍须由 kernel 判定。
- 查看两条后台命令的只读日志、来源、监视状态、输出裁剪提示。
- 体验“进程仍在运行 · 通知已关闭”的持续失败提示；重试创建一次新的模拟操作。
- 模拟终止命令：先显示正在终止，再显示物理收尾完成，不以请求接纳代替终态。
- 切换主助手工作中／空闲／只读观察者，比较反馈目标和控制权限。
- 切换浅色、深色模式。

工作中终止命令时，演示提示反馈待纳入当前轮次，不声称“模型已收到”；空闲时只更新界面，不自动带入下一人工轮次。关闭抽屉不终止任务或进程。初始失败数据是已知仍在运行，不是网络 ACK 未知。

所有命令、日志、耗时、ID、取消结果和状态变化均为虚构。页面不会执行命令、读取实际日志、访问生产配置或修改数据库；也没有真正提交 prompt 的能力。模拟器并非生产控制协议实现，不作为 activation 证据。

## 本地打开

可以直接用浏览器打开 `index.html`，也可以在仓库根目录启动仅监听本机的服务：

```sh
.venv/bin/python -m http.server 8000 --bind 127.0.0.1 --directory design/sidebar-demos
```

随后访问 `http://127.0.0.1:8000/`。停止这个本地服务不影响文件，下次仍可直接打开。

## 选择时主要比较

1. 阅读主对话时，是否需要始终看见依赖关系？
2. 查看任务、日志与返回对话之间的切换是否顺手？
3. “通知已关闭，但进程仍在运行”是否足够容易发现？
4. 信息密度能否接受，还是希望采用 A 的常驻入口与 C 的展开工作区组合？
