## Harness issues and correction

The initial test bundle renamed CFBundleName/DisplayName; Electron failed before JS with `Unable to find helper app` (system crash61487). The CUA timeout was not an authorization prompt. Restored original helper-compatible names and bundle basename, signed/refreshed only this test app, then completed the observations above. No product code was modified to accommodate the harness.

The temporary HOME did **not** isolate Electron's macOS `os.homedir()` CLI destination. The app's original best-effort registration briefly replaced the real user's managed launcher with the test bundle path. This was a test isolation mistake; there was no pre-test exact launcher snapshot, so byte-identical original restoration is not asserted. Root restored the ordinary production launcher generated by the unchanged script contract, pointing to `/Applications/Pulsara.app/Contents/Resources/python/bin/python3`, then used an exact temporary symlink conflict guard during remaining GUI tests. After the final app exit, replaced only that known guard with the executable regular launcher and verified its full contents. No temporary guard or test-bundle CLI target remains. The user was informed; production app/settings/database were not reset or stopped. Future GUI harnesses must explicitly protect the macOS user CLI rather than assume HOME isolation.

These are macOS application-bundle/LaunchServices observations. They do not prove native Ubuntu GUI, DMG distribution/Gatekeeper signing, WSL transport, Windows packaging, or provider activation. Ubuntu qualifications remain pending by explicit user decision; Phase B remains untouched.
